## Summary

FIX-106: `compare_reports` refuses two reports whose records carry different model revisions or prompt identities, so model v1 and v2 (or two providers, whose default prompt identities always differ) can never be compared on the same samples, which is what the benchmark is for. The refusal is deliberate and stays the default. This ticket adds a keyword-only `same_records: bool = True`; `same_records=False` skips only the revision and prompt-identity check. It also writes the final module docstring, which today understates what `compare_reports` refuses.

## Context

**What happens today.** After FIX-105, `compare_reports(a, b)` takes no options, and for two current reports always runs this loop (today's code, `src/nnx/decisions/benchmark.py` L1621–L1625, which FIX-105 moves unchanged into the `else:` branch of its `report_version` check):

```python
    # A report without the key recorded no revision or prompt, which is the same as none.
    for key, what in (("revisions", "model revisions"), ("prompt_identities", "prompt identities")):
        recorded = (list(left.get(key) or []), list(right.get(key) or []))
        if recorded[0] != recorded[1]:
            raise BenchmarkError(f"the reports scored with different {what}: {recorded[0]} and {recorded[1]}")
```

`collect()` defaults `prompt_identity` to a digest of `provider.record()` (L628–L636, used at L712), so reports of two different providers always differ unless both were collected with the same explicit `prompt_identity=`. The module docstring (L33–L37) says only that `compare_reports` "refuses reports of another split or metric identity".

**Why it matters.** The module's first line is "Score decision providers (``nnx.decisions``) on **identical samples**". With the revision check always on, an A/B comparison of two models or two prompts on identical samples is impossible. Source: 3ed0133 (#853).

**History.** #243 (FEAT-021) defined the comparison contract as split and metric identity only: "Comparison import rejects a mismatched split or metric identity." #853 added the revision and prompt-identity refusal on purpose, and it is documented (`docs/decisions.md` L657–L659) and tested (`test_compare_refuses_records_differing_only_in_revision_or_prompt`, `test_report_state_carries_revisions_only_when_records_record_them`). This ticket keeps that refusal as the default and adds the opt-out; it does not change the default.

**Background for the worker.**
- `BenchmarkReport.revisions` / `prompt_identities`: the distinct, sorted `revision` and `prompt_identity` values of the records a report scored (`_recorded_values`, L1307–L1310).
- `sample_set`: a digest of the samples a report scored (ids, questions, inputs, labels, slicing). `same_records=False` keeps the sample-set check, so the two reports must still be of the same samples.
- `report_version` and the 0.5.0 exception come from FIX-105 (this ticket's dependency): a pre-version report against a newer one is compared on split and metric identity only, with a `UserWarning`.
- Conflict 6 of the plan: this ticket writes the final module docstring; FIX-105 left it alone.

**Proposal.**
1. In `src/nnx/decisions/benchmark.py`, change the `compare_reports` signature to:

   ```python
   def compare_reports(
       a: Union[BenchmarkReport, Mapping[str, Any]],
       b: Union[BenchmarkReport, Mapping[str, Any]],
       *,
       same_records: bool = True,
   ) -> dict[str, dict[str, Optional[float]]]:
   ```

2. As the first statement of the body (before `left, right = _report_state(a), _report_state(b)`), add:

   ```python
       if not isinstance(same_records, bool):
           raise BenchmarkError(f"same_records must be a bool, got {same_records!r}")
   ```

3. In the `else:` branch FIX-105 added, wrap the revision / prompt-identity loop (keep the sample-set check outside it):

   ```python
       else:
           sets = (left.get("sample_set"), right.get("sample_set"))
           if None not in sets and sets[0] != sets[1]:
               raise BenchmarkError(
                   f"the reports scored different samples of split {left['split']!r}: {sets[0]} and {sets[1]}"
               )
           if same_records:
               # A report without the key recorded no revision or prompt, which is the same as none.
               for key, what in (("revisions", "model revisions"), ("prompt_identities", "prompt identities")):
                   recorded = (list(left.get(key) or []), list(right.get(key) or []))
                   if recorded[0] != recorded[1]:
                       raise BenchmarkError(
                           f"the reports scored with different {what}: {recorded[0]} and {recorded[1]}"
                       )
   ```

   No error message changes.
4. Replace the whole `compare_reports` docstring (as FIX-105 left it) with:

   ```python
       """``b - a`` per slice and metric, for two reports of the same split and
       metric identity and — when both record it — the same sample set (a
       :class:`BenchmarkReport` or a saved report's state). With
       ``same_records=True`` (the default) the scored records must also carry
       the same model revisions and prompt identities; ``same_records=False``
       skips that check, to compare two models or two prompts on the same
       samples. Anything else raises :class:`BenchmarkError`. A metric
       unavailable on either side has no delta.

       A report saved before ``report_version`` 2 (NNx 0.5.0 or earlier) did not
       digest sample inputs or record revisions and prompt identities: compared
       with a newer report, only the split and metric identity are checked,
       with a ``UserWarning``. Two such reports are checked as NNx 0.5.0
       checked them."""
   ```

5. Replace the module docstring's `BenchmarkReport` item (L33–L37):

   Old:
   ```
   - :class:`BenchmarkReport` — JSON, CSV and text exports that agree on
     units, eligible and failure counts and unavailable states;
     :func:`compare_reports` refuses reports of another split or metric
     identity. :class:`Resources` declares how cost was measured — or leaves
     it ``None``.
   ```
   New:
   ```
   - :class:`BenchmarkReport` — JSON, CSV and text exports that agree on
     units, eligible and failure counts and unavailable states;
     :func:`compare_reports` refuses reports of another split or metric
     identity, of another sample set (when both record one) and, unless
     ``same_records=False``, of other model revisions or prompt identities.
     A report saved before ``report_version`` 2 (NNx 0.5.0 or earlier) is
     compared on its split and metric identity only, with a ``UserWarning``.
     :class:`Resources` declares how cost was measured — or leaves it
     ``None``.
   ```

6. In `docs/decisions.md` §8, replace L657–L659 (the third item of the "Comparison" list):

   Old:
   ```
       - the same model revisions and prompt identities (the distinct values
         the scored records carry; a report that records none matches only one
         that records none);
   ```
   New:
   ```
       - the same model revisions and prompt identities (the distinct values
         the scored records carry; a report that records none matches only one
         that records none), unless you pass `same_records=False` to compare
         two models or two prompts on the same samples;
   ```

7. Regenerate the API reference: `uv run python -m scripts.docs.build_api_reference` (the signature and docstring are in `docs/api.md`).
8. CHANGELOG: in `## [Unreleased]` → `### Added`, add after the existing `dpo_train_step_factory(..., prompt_packing=True)` bullet (L39 at `9ad461e`; find it by its text, since #859 added a line above it):

   ```
   - **`compare_reports(..., same_records=False)` compares reports whose records carry different model revisions or prompt identities.** The split, metric identity and sample set must still match, so two models or two prompts can be compared on the same samples. The default (`same_records=True`) keeps refusing them.
   ```

9. Tests in `tests/test_decision_benchmark.py` (reuse `fixture()`, `replace`, `Sample`, `evaluate`, `compare_reports`, `BenchmarkError`). Add after `test_compare_refuses_records_differing_only_in_revision_or_prompt` (L1324–L1336):

   ```python
   def test_compare_allows_other_revisions_when_asked():
       samples, records = fixture()
       first = evaluate(samples, [replace(r, revision="r@1", prompt_identity="sha256:feed") for r in records], split="x")
       second = evaluate(samples, [replace(r, revision="r@2", prompt_identity="sha256:beef") for r in records], split="x")
       deltas = compare_reports(first, second, same_records=False)
       assert deltas["in_family"]["accuracy"] == 0.0
       with pytest.raises(BenchmarkError, match="different model revisions"):
           compare_reports(first, second)
       reworded = [Sample(s.id, s.question, f"{s.input} (reworded)", s.label) for s in samples]
       with pytest.raises(BenchmarkError, match="different samples"):
           compare_reports(first, evaluate(reworded, records, split="x"), same_records=False)
       with pytest.raises(BenchmarkError, match="different splits"):
           compare_reports(first, evaluate(samples, records, split="y"), same_records=False)
       with pytest.raises(BenchmarkError, match="same_records must be a bool, got 1"):
           compare_reports(first, second, same_records=1)  # type: ignore[arg-type]
   ```

   The two existing refusal tests stay as they are and must pass.

## Scope

**In:** the `same_records` keyword, the `compare_reports` and module docstrings, `docs/decisions.md` "Comparison", the CHANGELOG bullet, one test.

**Out:**
- Returning both reports' revisions and prompt identities with the deltas, so a caller sees what differed (a return-type change).
- Changing the default to `same_records=False` (#243's original contract); that would be an owner decision.
