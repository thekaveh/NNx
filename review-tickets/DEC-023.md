## Summary

DEC-023: The test, lint and docs toolchains are published as the PyPI extras `thekaveh-nnx[dev]` and `thekaveh-nnx[docs]`, with exact pins such as `pip-audit==2.10.1` and `cairosvg==2.9.1`. The repository already keeps its release and docs-publish tools in PEP 735 dependency groups, which are not published. The owner must decide whether `dev` and `docs` move to dependency groups (A) or stay extras (B).

## Context

**What happens today.** `pyproject.toml` `[project.optional-dependencies]` holds both toolchains (L119–L136 and L203–L210):

```toml
dev = [
    "pytest>=7.4",
    "pytest-cov>=4.1",
    # Runs the suite on every core (FIX-031): CI uses `-n logical`.
    "pytest-xdist>=3.6",
```

```toml
docs = [
    "cairosvg==2.9.1",
    "mkdocs>=1.5,<2",
    "mkdocs-material>=9.5",
```

while `[dependency-groups]` (L6–L16) already holds `release` and `docs-publish`. Every CI job and the contributor setup install the toolchains through `uv sync --frozen --all-extras` (for example `.github/workflows/ci.yml` L62), and one job through `--extra dev` (L218).

**Why it matters.** Published extras are part of the package's public metadata: `pip install thekaveh-nnx[dev]` imposes exact tool pins on a user's environment, and the extras list on PyPI mixes features with contributor tooling.

**History.**
- #220 (FEAT-010) and #225 (FIX-015) set the convention that `uv sync --frozen --all-extras` is "the CI-equivalent environment" (#225: "Run them from the repository root after `uv sync --frozen --all-extras` (the CI-equivalent environment)"). Option A must keep one command that gives that environment, so it adds `--all-groups` wherever `--all-extras` is documented or run.
- FIX-140 (DOC-29, DOC-34) first rewrites `CONTRIBUTING.md` L17 to "CairoSVG itself is pinned (`cairosvg==2.9.1`) in the `docs` extra and the `docs-publish` dependency group." and the `.pre-commit-config.yaml` ruff comment to name `uv.lock` instead of "pyproject.toml's [dev] extras". Option A edits L17 after it.

**Background for the worker.**
- Extra (`[project.optional-dependencies]`): a published, user-installable feature set (`pip install pkg[extra]`).
- Dependency group (`[dependency-groups]`, PEP 735): a development-only set that is not published; `uv sync --group NAME`, `--all-groups`, `--only-group NAME`.
- uv installs the group named `dev` by default on `uv sync` and `uv run`, unless `--no-dev` is passed. So after option A, a job that must not have the dev tools (or the `onnx` / `onnxruntime` they pull in) needs `--no-dev`.
- `uv lock` rewrites `uv.lock` after `pyproject.toml` changes; `uv lock --check` fails when the two disagree.
- `PYPI_README.md` is generated from `README.md`: `uv run python -m scripts.docs.build_pypi_readme`.

## Options

| Option | What changes | Trade-off |
|---|---|---|
| A | Move `dev` and `docs` to `[dependency-groups]`, add `--all-groups` to every `uv sync --all-extras` in CI and the docs, and `--no-dev` where a job must not have the tools. | The published metadata lists only features, and users never get tool pins. Contributors using plain `pip install -e ".[dev]"` lose that route (pip reads dependency groups only from 25.1, with `--group`). About fifteen files change. |
| B (recommended) | Keep both extras. | No churn, and every install route keeps working. PyPI keeps listing two tooling extras with exact pins. |

B is recommended because the extras are opt-in (nobody gets the pins without asking for them), the convention of #220 and #225 is built on `--all-extras`, and A's benefit is cosmetic against a change that touches every CI job.
