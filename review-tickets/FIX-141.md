## Summary

FIX-141: CHANGELOG 0.4.4 lists six changes twice and 0.4.3 one, because each landed once on `develop` and once on `main` and release-please listed both commits. `finalize_changelog.finalize` keeps release-please's raw list when no curated notes exist, so it will happen again, and the duplicate test only checks `- **title**` bullets, not release-please's `* ` bullets. This ticket deletes the seven duplicate lines, makes `finalize` drop repeats on that branch, and extends the test.

## Context

**What happens today.** The branch that keeps the generated list (`scripts/release/finalize_changelog.py` L143–L146):

```python
    if curated:
        body = [lines[release], "", *curated, ""]
    else:  # nothing curated: keep release-please's list
        body = lines[release:unreleased]
```

`CHANGELOG.md` L51/L52 (`31a4258` / `5c4bc22`), L53/L54, L55/L56, L60/L61, L62/L63, L64/L65 (0.4.4) and L90/L91 (0.4.3), line numbers at `9ad461e` (one higher at `1402b49`, where #859 added a line above them), are pairs whose text is identical once the trailing commit link (and, for L56, an issue link) is stripped. release-please generated them (ee10a92, PR #803); 15630ec (#833) restored them verbatim from the v0.4.4 tag. `tests/test_release_finalize.py::test_no_changelog_section_lists_one_entry_twice` (L236) matches only `^- \*\*(.+?)\*\*` titles.

**Why it matters.** The published release notes read as if every fix landed twice.

**History.** #418 (FIX-029) found the cause ("Under gitflow, the generated changelog lists each feature twice: the feature commit and the `develop`→`main` merge") and accepted either fix: "The curated `[Unreleased]` notes land under the release heading automatically and leave `[Unreleased]` empty. Alternatively, the generated list is deduplicated and the curated notes are kept." It implemented the first; this ticket adds the dedupe for the branch with no curated notes, which #418 left out. #535 (FIX-068) made the post-release steps retryable and reads the notes from the tag; it does not change this branch.

**Background for the worker.**
- release-please: the GitHub action that opens release PRs; it writes a `## [x.y.z]` section of `* ` bullets, one per commit, each ending in `([abc1234](commit-url))`, sometimes with `([#123](issue-url))` before it.
- Curated notes: the `- **Bold.** text` bullets maintainers write under `## [Unreleased]`; `finalize` moves them under the release heading. When there are none, the generated list stays.
- Generated subsection: a `### Bug Fixes` / `### Documentation` block of `* ` bullets.

**Proposal.**
1. In `CHANGELOG.md`, delete these seven lines. Find each by its commit hash with `grep -n <hash> CHANGELOG.md`; the line numbers are at `9ad461e` and shift as entries are added above them:
   - L52 (`5c4bc22`), L54 (`918cb4a`), L61 (`9490244`), L63 (`ade8acc`), L65 (`bdf2489`) in 0.4.4 — the second line of each pair;
   - L55 (`3c23214`) in 0.4.4 — the first line of its pair, because the second (L56, `0c7e650`) also carries the issue link `#766`;
   - L91 (`1a8dc31`) in 0.4.3.
2. In `scripts/release/finalize_changelog.py`, add `import re` after `import argparse` (L35), and add after `_headings` (after L59):

   ```python
   # A release-please bullet's commit link "([abc1234](url))" or issue link "([#123](url))".
   _GENERATED_LINK = re.compile(r"\s*\(\[(?:[0-9a-f]{7}|#\d+)\]\([^)]*\)\)")


   def _dedupe_generated(lines: list[str]) -> list[str]:
       """release-please's generated list without a ``* `` bullet whose text
       repeats an earlier one in the same ``###`` subsection once its commit and
       issue links (and a trailing ``, closes …``) are stripped: under gitflow a
       change lands on develop and on main, and release-please lists both
       commits (#418)."""
       kept: list[str] = []
       seen: set[str] = set()
       for line in lines:
           if line.startswith("#"):
               seen = set()
           elif line.startswith("* "):
               text = _GENERATED_LINK.sub("", re.sub(r",\s*closes\s.*$", "", line)).strip()
               if text in seen:
                   continue
               seen.add(text)
           kept.append(line)
       return kept
   ```
3. In `finalize`, replace L146:

   Old: `        body = lines[release:unreleased]`

   New: `        body = _dedupe_generated(lines[release:unreleased])`

   and in the module docstring replace `notes the generated list stays.` (L7) with `notes the generated list stays, without the bullets a change listed twice (once per develop and main commit).`
4. In `tests/test_release_finalize.py`, replace the whole function `test_no_changelog_section_lists_one_entry_twice` (L236–L246) with:

   ```python
   def test_no_changelog_section_lists_one_entry_twice():
       """merge=union keeps both sides of an edited line: two entries with one
       bold title in a section are a union-merge duplicate, not two changes. A
       release-please ``* `` bullet whose subject repeats is one change listed
       once per develop and main commit (#418)."""
       import collections

       text = (ROOT / "CHANGELOG.md").read_text(encoding="utf-8")
       for section in re.split(r"\n## ", text):
           titles = re.findall(r"^- \*\*(.+?)\*\*", section, flags=re.M)
           # A title ending in ":" is a category label ("Critical:"), repeated by design.
           repeated = [t for t, count in collections.Counter(titles).items() if count > 1 and not t.endswith(":")]
           assert not repeated, (section.splitlines()[0], repeated)
           subjects = re.findall(r"^\* (.+?) \(\[", section, flags=re.M)
           repeated = [s for s, count in collections.Counter(subjects).items() if count > 1]
           assert not repeated, (section.splitlines()[0], repeated)
   ```
5. In the same file, add after `test_without_curated_notes_the_generated_list_stays` (L78–L86):

   def test_finalize_dedupes_a_generated_list_without_curated_notes():
