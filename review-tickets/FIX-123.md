## Summary

FIX-123: `TopPFilter` checks only `0.0 < top_p <= 1.0`, so `TopPFilter(True)` and `generate(top_p=True)` silently mean "no filtering", and `top_p="0.9"` raises a bare `TypeError` from the comparison. The other three logits processors validate with `require_finite_real`. This ticket validates `top_p` the same way and keeps the established range message.

## Context

**What happens today.** `TopPFilter.__init__` (`src/nnx/generation/logits_processors.py` L121–L124):

```python
    def __init__(self, top_p: float):
        if not (0.0 < top_p <= 1.0):
            raise ValueError(f"top_p must be in (0, 1], got {top_p}")
        self.top_p = top_p
```

`True` passes (`0.0 < True <= 1.0`), is stored as-is, and `__call__` returns the logits unfiltered because `True >= 1.0`. A string fails inside the comparison with `TypeError: '<' not supported between instances of 'float' and 'str'`. `GenerativeNNModel.generate(top_p=...)` builds this processor (`generative_nn_model.py` L241–L242), so it has the same gap. `TemperatureScaling` and `RepetitionPenalty` in the same file use `require_finite_real` with a `domain_message`.

**Why it matters.** A typo'd or bool `top_p` changes decoding without an error.

**History.** #544 moved hand-written validators onto the shared helpers ("Hand-written validators that bypass the shared `require_count` / `require_finite_real` helpers refuse NumPy numbers…"); `TopPFilter` was missed, so this is its leftover. #254 added `LogitsStage`, whose `_real` helper (`generation/pipeline.py` L75–L84) already refuses a bool or non-number `top_p` stage; this ticket brings the processor in line.

**Background for the worker.**
- `require_finite_real(value, field, *, owner, minimum, maximum, exclusive_min, exclusive_max, domain_message)` (`src/nnx/_validation.py` L50–L92): returns `float(value)` for a finite real in the domain. A bool, a string, `None` or another non-real raises `ValueError("<owner> requires <field> to be a finite real number <domain>, got <repr> of type <type>")`. An out-of-domain value raises `domain_message` when given. NumPy numbers are accepted.
- `shown(value, real=True)`: `repr(value)` for a message, safe for huge integers.
- With `minimum=0, maximum=1, exclusive_min=True` the domain text is `> 0 and <= 1`.

**Proposal.**
1. In `src/nnx/generation/logits_processors.py`, replace the body of `TopPFilter.__init__` (L122–L124) with:

   ```python
           # A bool, a string, NaN or ±inf is refused by name, as TemperatureScaling
           # does; generate(top_p=) builds this processor.
           self.top_p = require_finite_real(
               top_p,
               "top_p",
               owner="TopPFilter",
               minimum=0,
               maximum=1,
               exclusive_min=True,
               domain_message=f"top_p must be in (0, 1], got {shown(top_p, real=True)}",
           )
   ```

   `require_finite_real` and `shown` are already imported (L18).
2. In the `TopPFilter` class docstring, insert one blank line and this paragraph between L118 (the end of the "Edge case" paragraph) and the closing `"""` (L119):

   ```
   ``top_p`` must be a finite real number in ``(0, 1]``; a bool, a string,
   NaN or ±inf raises ``ValueError``, as an out-of-range value does.
   ```
3. Regenerate the API reference: `uv run python -m scripts.docs.build_api_reference` (`TopPFilter` is catalogued at `scripts/docs/api_reference_catalog.txt` L1140).
4. Add to `CHANGELOG.md` under `## [Unreleased]` → `### Fixed`:

   ```
   - **`TopPFilter` and `generate(top_p=...)` refuse a value that is not a real number.** `True` was read as 1 (no filtering) and `"0.9"` raised a bare `TypeError`; both now raise `ValueError` naming `top_p`, as the other logits processors do. NumPy numbers are accepted and an out-of-range value keeps its message.
   ```
5. In `tests/test_generation_sampling.py`, add `import pytest` after `import math`, and add at the end of the file:

   ```python
   @pytest.mark.parametrize("bad", [True, "0.9", None])
   def test_top_p_filter_refuses_a_value_that_is_not_a_real_number(bad):
       from nnx.generation import TopPFilter

       with pytest.raises(ValueError, match=r"^TopPFilter requires top_p to be a finite real number > 0 and <= 1, got "):
           TopPFilter(bad)


   @pytest.mark.parametrize("bad", [0, 0.0, -0.1, 1.5])
   def test_top_p_filter_keeps_its_range_message(bad):
       from nnx.generation import TopPFilter

       with pytest.raises(ValueError, match=r"^top_p must be in \(0, 1\], got "):
           TopPFilter(bad)


   def test_top_p_filter_accepts_a_numpy_number():
       import numpy as np

       from nnx.generation import TopPFilter

       assert TopPFilter(np.float32(0.5)).top_p == 0.5
   ```
6. In `tests/test_generative_nn_model.py`, add after `test_generate_deterministic_greedy_is_reproducible`:

   ```python
   def test_generate_refuses_a_bool_top_p(tmp_path):
       model = _make_model(_make_tokenizer(tmp_path))
       with pytest.raises(ValueError, match="TopPFilter requires top_p"):
           model.generate(prompt="the", max_new_tokens=4, top_p=True)
   ```
