## Summary

DEC-017: `nnx.decisions` (4,899 lines: typed questions, providers, a decision-job orchestrator and a benchmark harness for LLM-style providers) ships inside NNx, and nothing in training imports it. FEAT-059 stops `import nnx` from loading it and FEAT-060 breaks its import cycle. The owner must decide whether it then stays in NNx (A) or moves to a separate distribution with a shim left behind (B).

## Context

**What happens today.** `src/nnx/__init__.py` imports it eagerly (L34–L69):

```python
from . import (
    abstention,
    benchmarking,
    bundles,
    calibration,
    comparison,
    compilation,
    components,
    data_splits,
    decisions,
```

The package docstring (`src/nnx/decisions/__init__.py` L1–L4) presents it as its own product:

```python
"""Provider-neutral typed decisions.

Ask a typed question, get labelled probabilities back — from any provider
that declares it can answer:
```

Its size: `benchmark.py` 1,643 lines, `jobs.py` 1,149, `jev.py` 544, `providers.py` 496, `schema.py` 490, `nli.py` 449, `__init__.py` 128, plus seven `tests/test_decision_*.py` modules. Core code reaches into it at `src/nnx/result.py` (`validate_decision_request_result`, L209; `decide_result`, L248, which imports private `jobs._check_results` and `jobs._rows`) and `src/nnx/abstention.py` `decide` (L1451–L1495), which FEAT-060 moves into `nnx.decisions`. Only `FixedHeadProvider` (`providers.py` L244–L496) wraps an NNx model.

**Why it matters.** Every `import nnx` pays for about 5k lines it may never use (fixed by FEAT-059), and the package forces the import cycle decisions ↔ abstention ↔ result (fixed by FEAT-060). What remains after those two is the long-term question of where the code lives.

**History.** The placement is deliberate and was built ticket by ticket:
- #219 (FEAT-009): "Add immutable Choice, Boolean and Score schemas, a `DecisionProvider` protocol and a fixed-head adapter."
- #220 (FEAT-010): "add an optional adapter over the TypeSafe software development kit (SDK), `typesafe-sdk`" (the `jev` extra).
- #234 (FEAT-011): the local NLI baseline provider. #243 (FEAT-021): the benchmark. #245 (FEAT-024): `DecisionJob`. #263 (FEAT-025): the `Result` boundaries in `nnx.result`.
- #262 (FEAT-023), the decision-model research pilot, was closed as not planned; its recipe shipped (`docs/decision-model-pilot.md`, `examples/decision_model_pilot.py`).

So this ticket does not question the feature, only its distribution. The review's "bolted on" wording and High severity are not carried over.

**Background for the worker.**
- Distribution: what `pip install` installs (`thekaveh-nnx` today); one distribution can hold several import packages.
- Lazy load (FEAT-059): `nnx.decisions` is imported on first attribute access through `nnx.__getattr__`, not by `import nnx`; `tests/test_imports.py` L530 still asserts `nnx.decisions is decisions`.
- Shim: a module left at the old import path that raises `ImportError` naming the new distribution, so old code fails with an actionable message.
- `docs/manifest.yaml` numbers every page by its position (`numbering: navigation`); each page's H1 carries that number. Removing a page renumbers every later page, so option B keeps two short stub pages instead.
- Generated files: `docs/api.md` (`uv run python -m scripts.docs.build_api_reference`), `PYPI_README.md` (`uv run python -m scripts.docs.build_pypi_readme`), `docs/feature-composition.md` (`uv run python scripts/check_feature_composition.py --render`).

## Options

| Option | What changes | Trade-off |
|---|---|---|
| A (recommended) | Nothing beyond FEAT-059 (lazy load) and FEAT-060 (no cycle). `nnx.decisions` stays a subpackage of `thekaveh-nnx`. | One repository, one release train, and `FixedHeadProvider` stays next to `NNModel`. NNx keeps maintaining an LLM-provider toolkit and the `jev` extra. |
| B | Move `nnx.decisions`, the decision boundaries of `nnx.result`, `abstention.decide` (after FEAT-060), their docs, examples, tests, the `jev` extra and the live smoke script into a new distribution `thekaveh-nnx-decisions` (import package `nnx_decisions`, depending on `thekaveh-nnx`). NNx keeps a shim that raises `ImportError` naming it. | NNx shrinks by about 7% of `src/nnx` and two guides. Every user of `nnx.decisions` or `nnx.result.decide_result` must change imports; two repositories and two releases to keep in step. A breaking change for a 0.x minor release. |

A is recommended because the board built the package deliberately (#219 to #263), FEAT-059 removes its import cost and FEAT-060 its cycle, and B's cost (a second repository and a breaking import change) buys only a smaller wheel.
