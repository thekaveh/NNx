## Summary

FIX-137: Since 3ed0133 (#853), `export_bundle` verifies the resume point before it loads it and raises `ResumePointError` for a torn, mixed or corrupted point; it also refuses the run id `"best"` with `BundleError`. Neither refusal is in the `export_bundle` docstring or `docs/concepts.md` §22 ("Refused at export"). This ticket adds both to both places.

## Context

**What happens today.** `export_bundle` (`src/nnx/bundles.py` L1210–L1216):

```python
    if _addresses_best_pointer(run_id, root):  # a moving alias: a bundle records the run it came from
        raise BundleError('export a run by its own id, not the "best" pointer (NNRun.best_id() names it)')
    label = str(_resume_checkpoint_type(checkpoint))
    # The resume path verifies a resume point before it restores from it (#394, #537); an export
    # publishes the same point, so it is checked the same way: a torn, mixed or corrupted point is
    # refused here, before anything is written.
    manifest = NNCheckpoint.verify(run=run_id, type=label, root=root)  # type: ignore[arg-type]
```

`NNCheckpoint.verify` raises `ResumePointError` (`nn_checkpoint.py` L328, exported as `nnx.ResumePointError`). CHANGELOG `[Unreleased]` L23 says "`export_bundle` verifies the resume point first". The docstring (L1171–L1203) lists other refusals only, and concepts §22 (L3072–L3080) lists five refusals, neither of these.

**Why it matters.** A user whose export fails on a torn checkpoint, or who passes `"best"`, finds no mention of either in the reference.

**History.** #537 made every resume path refuse a resume point republished between verification and load; its Scope listed `export_bundle` as Out. 3ed0133 then applied the same verification to `export_bundle`, so this ticket documents that reversal.

**Background for the worker.**
- Resume point: a checkpoint plus its training-state sidecar and manifest, written by `NNCheckpoint.save`; `NNCheckpoint.verify` checks that every file matches its manifest digest.
- `runs/best`: a pointer to the best run; `NNRun.best_id()` returns the id it points to. A bundle records the run it came from, so a moving alias is refused.
- `docs/api.md` is generated from docstrings: regenerate it, never edit it by hand.

**Proposal.**
1. In `src/nnx/bundles.py`, `export_bundle` docstring, insert after L1195 (`    unit; store a duration as a plain number in a fixed unit instead.`):

   ```
       A checkpoint whose resume point fails verification (torn, mixed or a
       digest mismatch) raises ``ResumePointError`` before anything is
       written, and the run id ``"best"`` is refused with ``BundleError``
       (export the id ``NNRun.best_id()`` names).
   ```
2. In `docs/concepts.md` §22, **Refused at export** list, insert after L3080 (`      conversion; the error names its index and id.`):

   ```
       - a checkpoint whose resume point fails verification (torn, mixed or a
         digest mismatch): `ResumePointError`, before anything is written;
       - the run id `"best"` (`BundleError`): export the id `NNRun.best_id()`
         names.
   ```

   and change the end of the item before it (L3080) from `index and id.` to `index and id;` so the list punctuation stays consistent.
3. Regenerate the API reference: `uv run python -m scripts.docs.build_api_reference` (`export_bundle` is catalogued at `scripts/docs/api_reference_catalog.txt` L537).

**Worker setup.** No torch needed (docs/config only).
