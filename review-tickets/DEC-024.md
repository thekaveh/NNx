## Summary

DEC-024: `generate()` takes three overlapping decoding configurations: inline keyword arguments, `logits_chain=` (`LogitsChain`, whose builder sorts processors into NNx's canonical order) and `logits_pipeline=` (`OrderedLogitsPipeline`, immutable stages in declared order, serializable). #254 added the pipeline *alongside* the chain on purpose. The owner must decide whether both stay, with docstrings that point at each other (A), or `LogitsChain` is deprecated (B).

## Context

**What happens today.** `LogitsChain` (`src/nnx/generation/logits_chain.py` L51–L66) does not mention the pipeline:

```python
@dataclass(frozen=True, kw_only=True, slots=True)
class LogitsChain:
    """A typed, ordered sequence of LogitsProcessors.

    Build via `LogitsChain.builder()` for the safe / discoverable
    path; or construct directly from a list for advanced cases. The
    `.apply()` method runs the processors against a logits tensor in
    order, returning the adjusted tensor.
    """

    processors: list[LogitsProcessor] = field(default_factory=list)
```

Only `LogitsChainBuilder.custom` and its `build()` refusal (L110–L139) name `OrderedLogitsPipeline`. The pipeline's module docstring contrasts the two (`pipeline.py` L1–L7), but its class docstring (L263–L267) does not. `docs/lm.md` §5–§5.1 (L243–L298) already compares them in a table.

**Why it matters.** SMELL-46: three ways to configure the same decoding path, two of them classes, is a choice users must understand. `OrderedLogitsPipeline` covers the same four built-in stages, custom stages and greedy handling, and also serializes.

**History.**
- #254 (FEAT-037) created the pipeline as a companion, not a replacement: "The ticket requests an immutable `OrderedLogitsPipeline` (proposed name) with append, prepend, generation integration and a versioned round trip. `LogitsChain` stays unchanged." Its criterion: "`LogitsChain`, the builder overwrite behaviour and inline keyword arguments stay unchanged." Its Scope Out: "a migration of the mutable list in `LogitsChain`." Option B reverses that design.
- #578 (FEAT-056) pinned that "Default `generate()` matches `generate(logits_chain=LogitsChain(processors=[]))`" and that "`LogitsChainBuilder.temperature(1.0)` and the `OrderedLogitsPipeline` temperature stage behave the same way". Both options keep those tests.

**Background for the worker.**
- Logits processor: a callable `(logits, token_history) -> logits` applied at each decoding step (`nnx.generation.logits_processors`: `RepetitionPenalty`, `TopKFilter`, `TopPFilter`, `TemperatureScaling`).
- Canonical order: `RepetitionPenalty → TopKFilter → TopPFilter → TemperatureScaling`, which `LogitsChainBuilder.build()` imposes whatever the call order; temperature 0 is greedy and must be last.
- `OrderedLogitsPipeline(stages)`: accepts `LogitsStage` / `CustomStage` values, built-in processors (copied into `LogitsStage` specs by `_as_stage`, `pipeline.py` L222–L240) and other callables; a zero-temperature stage that is not last raises `ValueError`.
- `_warn_at_user_frame(message, category)` (`src/nnx/nn/callbacks.py` L111): NNx's warning helper, attributing the warning to the caller's line; import it inside the function (`nnx.nn` imports `nnx.generation`).
- `docs/api.md` is generated from docstrings: `uv run python -m scripts.docs.build_api_reference`.

## Options

| Option | What changes | Trade-off |
|---|---|---|
| A (recommended) | Keep both. `LogitsChain`, its module docstring and `OrderedLogitsPipeline`'s class docstring say when to use which. | No break, as #254 decided. Users still meet two classes for decoding. |
| B | `LogitsChain` and `LogitsChainBuilder` emit a `DeprecationWarning` pointing at `OrderedLogitsPipeline`; add `OrderedLogitsPipeline.from_chain(chain)`; update the example and docs; remove both in the next minor release (a later ticket). | One decoding class. Every `LogitsChain` user gets a warning now and a break later, for a design #254 kept on purpose. |

A is recommended because #254 decided the two coexist ("`LogitsChain` stays unchanged"), the canonical-order builder is still the simplest correct path for most users, and the docs already contrast them; only the class docstrings lack the pointer.

**If option A, the worker does:**

1. In `src/nnx/generation/logits_chain.py`, append to the module docstring, after `the "post-default" slot for user extensions.` (L20):

   ```
   For an order of your own (temperature before the nucleus cut, a stage
   applied twice, a custom stage between built-ins) or a configuration to
   save, use :class:`~nnx.generation.OrderedLogitsPipeline`, which runs its
   stages exactly as declared (``docs/lm.md`` §5.1).
   ```

2. In the `LogitsChain` class docstring, add after `returning the adjusted tensor.` (L58): `For stages in declared order, immutable and serializable, use :class:`~nnx.generation.OrderedLogitsPipeline`.`
3. In `src/nnx/generation/pipeline.py`, replace the `OrderedLogitsPipeline` class docstring (L265–L267) with:

   ```python
       """Decoding stages run exactly in declared order. See the module
       docstring for immutability, validation, the terminal greedy rule,
       custom stages and serialization. For NNx's canonical order
       (penalty → top-k → top-p → temperature, whatever the call order), use
       ``LogitsChain.builder()``."""
   ```

4. `uv run python -m scripts.docs.build_api_reference`. No CHANGELOG entry (docstrings only).

**If option B, the worker does:**

1. In `logits_chain.py`, add after `_CANONICAL_ORDER` (L48):

   ```python

       "{name} is deprecated and will be removed in the next minor release; use "

   )
   ```

   Add to `LogitsChain`:

   ```python
       def __post_init__(self) -> None:
           from ..nn.callbacks import _warn_at_user_frame  # lazy: nnx.nn imports nnx.generation

           _warn_at_user_frame(_DEPRECATED.format(name="LogitsChain"), DeprecationWarning)
   ```

   In `LogitsChainBuilder.__init__`, first line: the same import and `_warn_at_user_frame(_DEPRECATED.format(name="LogitsChainBuilder"), DeprecationWarning)`. In `build()`, replace `return LogitsChain(processors=ordered)` with:

   ```python
           with warnings.catch_warnings():  # the builder already warned once
               warnings.simplefilter("ignore", DeprecationWarning)
               return LogitsChain(processors=ordered)
   ```

   and add `import warnings` to the module's imports. Add one sentence to both class docstrings: `Deprecated: use :class:`~nnx.generation.OrderedLogitsPipeline`.`
2. In `pipeline.py`, add `from .logits_chain import LogitsChain` to the imports and this method after `of` (L278–L281):

   ```python
       @classmethod
       def from_chain(cls, chain: LogitsChain) -> OrderedLogitsPipeline:
           """The pipeline that runs ``chain``'s processors in the chain's order:
           built-in processors become :class:`LogitsStage` specs, any other
           callable a :class:`CustomStage`. A processor after a zero
           temperature raises ``ValueError``, as in any pipeline."""
           return cls(tuple(chain.processors))
   ```

3. In `pyproject.toml` `[tool.pytest.ini_options]` `filterwarnings`, add `"ignore:LogitsChain(Builder)? is deprecated:DeprecationWarning",` with the comment `# NNx's own deprecated decoding path, still exercised by its tests until removal (DEC-024)`. In its module docstring replace L3–L4 `` ``nnx.generation.OrderedLogitsPipeline`` is the order-preserving companion to `` / `` ``LogitsChain`` (whose builder sorts processors into NNx's canonical order): `` with `` ``nnx.generation.OrderedLogitsPipeline`` runs decoding stages in declared order: ``.
5. Docs: at the start of `docs/lm.md` §5 (after the heading L243 and its blank line) insert this paragraph, followed by a blank line:

   ```
   **Deprecated.** `LogitsChain` and `LogitsChainBuilder` emit a `DeprecationWarning` and will be removed in the next minor release; use `OrderedLogitsPipeline` (§5.1). `OrderedLogitsPipeline.from_chain(chain)` converts a chain, keeping its order.
   ```

   Append `` Deprecated: use `OrderedLogitsPipeline`. `` (with a leading space, inside the last cell) to the two table rows `nnx.LogitsChain` and `nnx.LogitsChainBuilder` (`docs/lm.md` L27–L28), and to the end of the `LogitsChain.builder()` bullet of `docs/concepts.md` (L152).
6. Tests:

7. `uv run python -m scripts.docs.build_api_reference`.
8. `CHANGELOG.md`, `[Unreleased]` → `### Changed`:

The new `OrderedLogitsPipeline.from_chain(chain)` converts an existing chain, keeping its order. Both classes will be removed in the next minor release.
