**Category:** Interoperability · **Priority:** P1 · **Size:** M · **Evidence:** read at `9ad461e` (develop); not run: torch was unavailable in the review environment

## Summary

FIX-107: `to_onnx`'s "dropped state" check compares the network's state with the exported graph's initializers by name and value. The legacy exporter folds an eval-mode BatchNorm into the preceding convolution, so every Conv+BatchNorm export warns about tensors that are correctly carried, and under a warnings-as-errors filter the warning, raised inside the export's `try`, discards a correct file. The same check copies same-shape weights to NumPy once per key (quadratic) and, on the dynamo path, skips almost every comparison. This ticket replaces it with a check of what the warning means (attached tensors one eval forward pass never reads), named `_unread_state_keys(net, example_input)`, and raises the warning after the file is in place.

## Context

**What happens today.** `_unexported_state_keys` (`src/nnx/nn/nn_model.py` L2653–L2683) loads the exported file and matches each state tensor against the initializers:

```python
    for key, tensor in net.state_dict().items():
        if not torch.is_tensor(tensor) or key in named or key.endswith("num_batches_tracked"):
            continue
        shape = tuple(tensor.shape)
        candidates = [init for init in initializers if tuple(init.dims) in (shape, shape[::-1])]
        if not candidates:
            dropped.append(key)
            continue
        if any(init.data_location == TensorProto.EXTERNAL for init in candidates):
            continue  # its data is not in the file, so absence cannot be shown
```

`to_onnx` (L4221) calls it and warns inside the `try` that discards the partial file on any exception (L4394–L4407):

```python
            dropped = _unexported_state_keys(self.net, partial)
            if dropped:
                shown = ", ".join(dropped[:5]) + (", ..." if len(dropped) > 5 else "")
                warnings.warn(
                    f"to_onnx(): the exported graph holds no initializer for {len(dropped)} tensor(s) of the network's "
                    f"state ({shown}); the exporter dropped them, so the ONNX model does not carry them",
                    UserWarning,
                    stacklevel=2,
                )
            _commit_partial(partial, path)
        except BaseException:
            _discard_partial(partial)
            raise
```

Three problems, one root cause:
1. **False warning (BUG-04).** `to_onnx` puts the net in eval mode. The legacy (TorchScript) exporter's eval peephole pass (`_jit_pass_onnx_eval_peephole`, `fuseConvBatchNorm`) then fuses each BatchNorm into the Conv before it, regardless of `do_constant_folding`. The fused Conv gets new initializers (`onnx::Conv_NNN`) with new values (W·γ/√(σ²+ε) and a new bias); the BatchNorm weight, bias, `running_mean` and `running_var` disappear. The check finds neither the names nor the values and names the conv weight and all four BatchNorm tensors. A ResNet gets dozens. Under `-W error` or pytest `filterwarnings = error`, the warning becomes an exception inside the `try`, `_discard_partial` runs, and a correct export is thrown away.
2. **Quadratic cost (BUG-05).** Each unmatched key converts every same- or transposed-shape initializer to NumPy (`numpy_helper.to_array` copies) and holds the copies at once (L2680–L2682). The legacy exporter renames every transposed MatMul weight of a `TransformerNN`, so a 12-layer d=768 model does about 1.5k full-matrix copies per export.
3. **No check on dynamo (BUG-06).** With default external data, every candidate of 256 bytes or more is `EXTERNAL` and skipped (L2675–L2676). Only keys with no same-shape initializer at all are ever reported.

These come from torch, onnxscript and onnx_ir source, not from a run here: write the tests first and confirm they fail on `develop`.

**Why it matters.** A correct export of any CNN with BatchNorm warns, and a user who runs with warnings as errors loses the file. Source: ed93d51 (#855, "dropped-state warning"); the CHANGELOG `[Unreleased]` → `### Fixed` bullet (L27 at `9ad461e`) ("ONNX export warns about attached tensors the exported graph does not hold").

**History.** No board issue covers this check; it is new in #855.

**Background for the worker.**
- Legacy exporter: `torch.onnx.export(..., dynamo=False)`, the TorchScript tracer; NNx's default.
- Dynamo exporter: `torch.onnx.export(..., dynamo=True)`, built on `torch.export` and onnxscript; it writes tensors of 256 bytes or more as external data by default (torch 2.6 and later).
- Initializer: a constant tensor stored in an ONNX graph (a weight).
- `TorchFunctionMode` (`torch.overrides`): a context manager whose `__torch_function__(self, func, types, args=(), kwargs=None)` is called for every torch function and tensor method invoked while it is active (`F.linear`, `F.batch_norm`, `Tensor.t`, `Tensor.__getitem__`, `_VF.lstm`, ...). Inside the method the mode is disabled, so `func(*args, **kwargs)` runs normally. Available on the `torch>=2.4` floor.
- `state_dict(keep_vars=True)`: the state with the module's own `Parameter` and buffer objects instead of detached copies, so `id()` identifies the object the forward pass receives.
- `num_batches_tracked`: a BatchNorm buffer an eval-mode forward never reads; it is left out today and stays left out.
- `_capture_training_modes` / `_restore_training_modes` (`nnx.utils`): snapshot and give back every submodule's `training` flag; `to_onnx` restores them in the inner `finally` (L4392–L4393).
- `_reserve_partial` / `_commit_partial` / `_discard_partial` (`nn_run.py` L290–L322): the hidden partial file `to_onnx` writes and renames onto `path`. FIX-108 later replaces them with a staging directory; it calls `_unread_state_keys` exactly as this ticket leaves it.

**Proposal.**
1. In `src/nnx/nn/nn_model.py`, delete `_unexported_state_keys` (L2653–L2683) and put this function in its place. Do not keep an alias: nothing else, in `src/` or `tests/`, references `_unexported_state_keys` (`grep -rn _unexported_state_keys src tests` shows only L2653 and L4395).

   ```python
   def _unread_state_keys(net: torch.nn.Module, example_input: tuple[torch.Tensor, ...]) -> list[str]:
       """The keys of ``net``'s state whose tensors one forward pass on
       ``example_input`` never reads, so an exported graph of that forward does
       not carry them. Every tensor a torch function or tensor method receives
       during the pass counts as read (``state_dict(keep_vars=True)`` gives the
       module's own parameter and buffer objects, matched by identity), so a
       tensor an exporter folds into new initializers (an eval-mode BatchNorm
       into its convolution) or renames is never reported, and the check is the
       same for every exporter. ``num_batches_tracked`` is left out: an
       eval-mode forward never reads it. The caller puts ``net`` in eval mode;
       the pass runs without gradients."""
       from torch.overrides import TorchFunctionMode

       seen: set[int] = set()

       def visit(value: Any) -> None:
           if isinstance(value, torch.Tensor):
               seen.add(id(value))
           elif isinstance(value, (list, tuple)):
               for item in value:
                   visit(item)
           elif isinstance(value, Mapping):
               for item in value.values():
                   visit(item)

       class _Reads(TorchFunctionMode):
           def __torch_function__(self, func, types, args=(), kwargs=None):
               kwargs = kwargs or {}
               visit(args)
               visit(kwargs)
               return func(*args, **kwargs)

       state = net.state_dict(keep_vars=True)
       with torch.no_grad(), _Reads():
           net(*example_input)
       return [
           key
           for key, tensor in state.items()
           if torch.is_tensor(tensor) and id(tensor) not in seen and not key.endswith("num_batches_tracked")
       ]
   ```

   `Any` and `Mapping` are already imported at the top of the module (L18, L22). The state tensors stay alive in `state` for the whole pass, so no temporary can reuse their `id()`.

   ```python
   def test_a_conv_batchnorm_export_names_no_tensor(tmp_path):
       """The legacy exporter folds an eval-mode BatchNorm into the convolution before it (new initializers,
       new values), so a check of the graph's initializers named the conv weight and every BatchNorm tensor,
       and -W error discarded the file. The forward pass reads all of them: nothing is named."""
       import onnx
       from torch import nn

       net = nn.Sequential(nn.Conv2d(3, 4, 3, bias=False), nn.BatchNorm2d(4), nn.ReLU(), nn.Flatten(), nn.Linear(144, 2))
       with torch.no_grad():
           net[1].running_mean.uniform_(-1.0, 1.0)
           net[1].running_var.uniform_(0.5, 2.0)
           net[1].weight.uniform_(0.5, 2.0)
           net[1].bias.uniform_(-1.0, 1.0)
       model = NNModel(module=net, params=NNModelParams(device=Devices.CPU, loss=Losses.CROSS_ENTROPY))
       path = tmp_path / "conv.onnx"
       with warnings.catch_warnings():
           warnings.filterwarnings("error", message=r"to_onnx\(\)", category=UserWarning)
           model.to_onnx(str(path), torch.randn(2, 3, 8, 8), dynamic_batch=False)
       assert path.exists()
       names = {init.name for init in onnx.load(str(path)).graph.initializer}
       assert "1.running_mean" not in names  # the exporter folded the BatchNorm, the case the old check got wrong


   def test_under_warnings_as_errors_the_export_is_kept(tmp_path):
       model = _feed_forward()
       model.net.register_buffer("class_prior", torch.tensor([0.25, 0.75]))
       model.net.train()
       path = tmp_path / "model.onnx"
       with warnings.catch_warnings():
           warnings.filterwarnings("error", message=r"to_onnx\(\)", category=UserWarning)
           with pytest.raises(UserWarning, match="class_prior"):
               model.to_onnx(str(path), torch.randn(2, 4), dynamic_batch=False)
       assert path.exists() and sorted(os.listdir(tmp_path)) == ["model.onnx"]
       assert model.net.training  # the modes were given back before the warning


   def test_a_dynamo_export_names_an_unread_buffer_shaped_like_a_weight(tmp_path, skip_on_dynamo_dispatch_error):
       """The old check skipped every external-data candidate, so on the dynamo path a 64x64 buffer the
       forward never reads, shaped like the first weight, was never named."""
       pytest.importorskip("onnxscript")
       model = NNModel(
           net_params=NNParams(input_dim=64, output_dim=2, hidden_dims=[64], dropout_prob=0.0, activation=Activations.RELU),
           params=NNModelParams(net=Nets.FEED_FWD, device=Devices.CPU, loss=Losses.CROSS_ENTROPY),
       )
       model.net.register_buffer("unused_matrix", torch.randn(64, 64))
       with pytest.warns(UserWarning, match=r"1 tensor\(s\) the forward pass never reads \(unused_matrix\)"):
           try:
               model.to_onnx(str(tmp_path / "model.onnx"), torch.randn(2, 64), dynamic_batch=False, dynamo=True)
           except Exception as error:
               skip_on_dynamo_dispatch_error(error)
               raise
   ```
