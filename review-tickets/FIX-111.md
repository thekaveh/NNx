## Summary

FIX-111: The CHANGELOG promises that a failed `save_pretrained` leaves the previous artifact intact. That holds for a save refused or failed before any file moves; a failure after the first `os.replace` leaves new weights beside the old config and manifest, which `from_pretrained` refuses by design, as `docs/hub.md` §2.2 has said since #859. This ticket states the same guarantee, and the move order FIX-110 leaves, in the CHANGELOG and the `save_pretrained` docstring, and updates §2.2's tokenizer sentence to FIX-110's order; no code changes.

## Context

**What happens today.** The CHANGELOG `[Unreleased]` → `### Changed` bullet (L12) says:

```
- **Hub saves are staged, and loads are verified.** A refused or failed `save_pretrained` leaves the previous artifact intact. Each save writes `nnx_hub_manifest.json` (the SHA-256 and size of each file), which `from_pretrained` verifies before building anything. A directory saved before manifests existed loads with a `UserWarning`.
```

`docs/hub.md` §2.2 (L161) said the same at `9ad461e`. #859 (1402b49) kept that sentence and added the interrupted move after it: "If the process stops during the move, the directory can hold new files beside the previous manifest. Load refuses that mix, because the manifest's digests no longer match, so it is detected rather than read silently. Run `save_pretrained` again to repair the directory." Its tokenizer sentence still describes the removal before FIX-110: "A `tokenizer.json` that this save does not produce is removed only if an earlier NNx save wrote it (the previous manifest lists it)." The code moves staged files in one by one (`src/nnx/nn/nn_model.py` L4628–L4633):

```python
            # config.json, then the manifest, move last: an interrupted move leaves the previous manifest beside files
            # it no longer matches, which a load refuses rather than reading a mix of two saves.
            for name in sorted(produced, key=lambda produced_name: _HUB_MOVE_ORDER.get(produced_name, 0)):
                if name == "README.md" and (target / name).exists():
                    continue  # huggingface_hub does not overwrite an existing model card
                os.replace(os.path.join(staging, name), target / name)
```

A failure after the first `os.replace` leaves files of two saves under the previous manifest. The load refuses that mix (the comment above says so on purpose), but the previous artifact is no longer intact. The `save_pretrained` docstring (L4593–L4607) says nothing about staging or failures.

**Why it matters.** A user relying on the CHANGELOG would expect the old model to load after any failed save. Source: 3ed0133 (#853, staging) and ed93d51 (#855, manifest).

**History.**
- #260 (FIX-025) recorded the project's stance for NNx's writers: §4.2 "describe owned-temp cleanup. They do not claim a multi-file transaction or a crash-proof unlink." `docs/concepts.md` §4.2 keeps it: "This is per-file cleanup for ordinary exceptions, not a multi-file transaction." This ticket documents the Hub save to that stance (BUG-09 option a); making the move reversible (option b) is out of scope.
- #859 documented the interrupted move in `docs/hub.md` §2.2. This ticket does not rewrite those sentences; its CHANGELOG and docstring texts say the same thing.
- #509 (FIX-042) defined the refusals the docstring lists ("Refuse unreplayable Hub saves"); they all run before anything is written and stay as described.

**Background for the worker.**
- Staging directory: `save_pretrained` writes the whole save into a hidden `.nnx-hub-*` directory beside the target, then moves each file into the target with `os.replace`.
- Move order at 9ad461e: files with no `_HUB_MOVE_ORDER` entry (`model.safetensors`, a new `README.md`, `tokenizer.json` when produced) in no set order, then `config.json`, then `nnx_hub_manifest.json` (`_HUB_MOVE_ORDER = {config.json: 1, manifest: 2}`, L193).
- FIX-110 (this ticket's dependency) moves the removal of a stale `tokenizer.json` to after the loop, and removes it only when it still has the digest the previous manifest lists. The texts below describe that order.
- Hub manifest: `nnx_hub_manifest.json`, the SHA-256 and size of each NNx-written file; `from_pretrained` refuses a listed file that is missing or changed.

**Proposal.**
1. CHANGELOG: in `## [Unreleased]` → `### Changed`, replace L12:

   Old:
   ```
   - **Hub saves are staged, and loads are verified.** A refused or failed `save_pretrained` leaves the previous artifact intact. Each save writes `nnx_hub_manifest.json` (the SHA-256 and size of each file), which `from_pretrained` verifies before building anything. A directory saved before manifests existed loads with a `UserWarning`.
   ```
   New:
   ```
   - **Hub saves are staged, and loads are verified.** A refused `save_pretrained`, or one that fails before files move, leaves the previous artifact intact; one interrupted while moving files is refused on load, and saving again repairs it. Each save writes `nnx_hub_manifest.json` (the SHA-256 and size of each file), which `from_pretrained` verifies before building anything. A directory saved before manifests existed loads with a `UserWarning`.
   ```

2. In `src/nnx/nn/nn_model.py`, `NNModel.save_pretrained`: the docstring ends at L4607 with `them out through ``exclude_submodules``."""`. Change that line to end without the closing quotes and append a blank line and this paragraph, closing the docstring after it:

   ```
           them out through ``exclude_submodules``.

           The save is staged in a hidden ``.nnx-hub-*`` directory beside
           ``save_directory`` and its files move in only once it has succeeded:
           the weights (with ``tokenizer.json`` and a new ``README.md``) first,
           then ``config.json``, then ``nnx_hub_manifest.json``; a
           ``tokenizer.json`` an earlier NNx save wrote and this save does not
           produce is removed last, and only if it is unchanged. A refused save,
           or one that fails before files move, leaves the previous artifact
           intact. One interrupted while moving leaves files of both saves
           beside the previous manifest, which ``from_pretrained`` refuses to
           load; save again to repair the directory. The moves are not one
           atomic step."""
   ```

3. In `docs/hub.md` §2.2, L161 (the paragraph that starts `A save is staged in a temporary directory beside the target`), replace only the tokenizer sentence. Leave the rest of the paragraph, including #859's sentences on the move order and an interrupted move, as it is.

   Old:
   ```
   A `tokenizer.json` that this save does not produce is removed only if an earlier NNx save wrote it (the previous manifest lists it).
   ```
   New:
   ```
   A `tokenizer.json` that this save does not produce is removed last, after the new manifest is in place, and only if an earlier NNx save wrote it: the previous manifest lists it with the digest the file still has.
   ```

4. Regenerate the API reference: `uv run python -m scripts.docs.build_api_reference` (the `save_pretrained` docstring is in `docs/api.md`, L322).

**Worker setup.** Branch from `develop`. `uv sync --frozen --all-extras` installs torch and every extra the tests need (the API-reference build imports `nnx`, and the Hub tests need the `hub` extra).
