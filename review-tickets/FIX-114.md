## Summary

FIX-114: `_fsync_file`, which flushes every atomic export before its rename, opens the file read-only. On Windows `os.fsync` (`FlushFileBuffers`) fails on a handle without write access with `EBADF`, which `_full_fsync` tolerates as "unsupported", so `to_onnx`, `export_state_dict`, `write_gguf` and the Hub weights are renamed into place unflushed. This ticket opens the file read-write, as `history._fsync_path` already does for the same reason.

## Context

**What happens today.** `_fsync_file` (`src/nnx/nn/params/nn_run.py` L300–L306):

```python
def _fsync_file(path: str) -> None:
    """Flush the file at ``path`` to stable storage (through a read-only descriptor)."""
    fd = os.open(path, os.O_RDONLY)
    try:
        _full_fsync(fd)
    finally:
        os.close(fd)
```

`EBADF` is in `_UNSUPPORTED_FLUSH` (`src/nnx/nn/params/nn_checkpoint.py` L206–L210), so `_full_fsync` (L213–L232) swallows it. Its callers:
- `_commit_partial` (`nn_run.py` L309–L316), used by `NNModel.to_onnx` (`nn_model.py` L4404), `NNModel.export_state_dict` (L5022) and `write_gguf` (`interop/gguf/writer.py` L323);
- the Hub weights in `NNModel._save_pretrained` (`nn_model.py` L4757).

The project already knows the rule: `history._fsync_path` (`src/nnx/history.py` L299–L317) opens a file `O_RDWR` with the comment "A file is opened for writing: Windows' fsync needs a writable handle", and `tests/test_history_journal.py::test_the_new_history_directory_and_files_are_flushed_writably` (L1141–L1155) pins it.

**Why it matters.** On Windows every atomic export can lose its data on a power loss while its name says it is complete. That breaks the documented guarantee in `docs/concepts.md` §14.3 (L2249–L2251): "On Windows the files are flushed with `os.fsync`, but the renames are not, because a directory cannot be flushed there." Source: 3ed0133 (#853), which made these exports atomic.

**History.**
- #443 (FIX-030) introduced `F_FULLFSYNC` for resume points and scoped out "Windows-specific durability"; this ticket closes that gap for exports only.
- #552 (FIX-084) made a real flush error fail the write and documented the flush policy in §14.3; the tolerance of an unsupported flush stays. Its acceptance criterion "Tests intercept the primitive (`os.fsync` or `_full_fsync`), not the wrapper" is why the new tests spy on `os.open`.

**Background for the worker.**
- `_full_fsync(fd)`: flushes a descriptor with `fcntl(F_FULLFSYNC)` on macOS, else `os.fsync`; it tolerates `_UNSUPPORTED_FLUSH` (`ENOTSUP`, `EOPNOTSUPP`, `EINVAL`, `ENOTTY`, `EBADF`) and raises any other `OSError`.
- Partial file: a file NNx creates beside the target (mode 0600 from `mkstemp`, or created by `safetensors` for the Hub weights), fills, flushes and renames onto the target. NNx owns it, so opening it read-write cannot fail with `EACCES` in practice; any other `OSError` propagates and the caller discards the partial.
- `os.O_BINARY`: exists only on Windows; `getattr(os, "O_BINARY", 0)` is the portable form.
- `nn_checkpoint._fsync_directory` (L235–L245) opens a directory `O_RDONLY`; that is correct for directories and stays.

**Proposal.**
1. In `src/nnx/nn/params/nn_run.py`, replace `_fsync_file` (L300–L306) with:

   ```python
   def _fsync_file(path: str) -> None:
       """Flush the file at ``path`` to stable storage (through a writable
       descriptor: Windows' fsync needs one, and fails a read-only handle with
       ``EBADF``, which the flush would tolerate as unsupported). The file is
       one NNx just wrote; an error opening it propagates."""
       fd = os.open(path, os.O_RDWR | getattr(os, "O_BINARY", 0))
       try:
           _full_fsync(fd)
       finally:
           os.close(fd)
   ```

2. Do not change `nn_checkpoint._fsync_directory`, `_full_fsync`, `_UNSUPPORTED_FLUSH` or `history._fsync_path`.
3. CHANGELOG: in `## [Unreleased]` → `### Fixed`, add at the end of the list:

   ```
   - **Atomic exports reach the disk on Windows before they are renamed into place.** `to_onnx`, `export_state_dict`, `write_gguf` and the Hub weights reopened the finished file read-only to flush it; Windows' `fsync` refuses such a handle (`EBADF`), which the flush tolerated, so the file was renamed in unflushed. It is now flushed through a writable handle.
   ```

4. Tests in `tests/test_hub_export_atomic.py`. It imports `os`, `stat`, `pytest` and `_tiny_model` from `tests.test_hub_mixin` (L5–L10; the import skips the module without `safetensors`). Add at the end of the module:

   ```python
   def _record_opens(monkeypatch) -> list[tuple[str, int]]:
       """Every os.open of the test as (path, flags), as nnx.nn.params.nn_run sees it."""
       import nnx.nn.params.nn_run as nn_run

       opened: list[tuple[str, int]] = []
       real_open = nn_run.os.open

       def spy(path, flags, *args, **kwargs):
           opened.append((os.fspath(path), flags))
           return real_open(path, flags, *args, **kwargs)

       monkeypatch.setattr(nn_run.os, "open", spy)
       return opened


   def _flush_opens_of_partials(opened: list[tuple[str, int]]) -> list[int]:
       """The flags of every reopening of a ``.partial`` file: not its creation (O_CREAT), which mkstemp does
       read-write anyway, but the open the flush makes."""
       return [flags for path, flags in opened if path.endswith(".partial") and not flags & os.O_CREAT]


   def test_a_committed_export_is_flushed_through_a_writable_descriptor(tmp_path, monkeypatch):
       """Windows' fsync fails a read-only handle with EBADF, which the flush tolerated: the export was renamed
       into place unflushed."""
       opened = _record_opens(monkeypatch)
       _tiny_model().export_state_dict(str(tmp_path / "weights.pt"))
       flushes = _flush_opens_of_partials(opened)
       assert flushes and all(flags & os.O_RDWR for flags in flushes)


   def test_hub_weights_are_flushed_through_a_writable_descriptor(tmp_path, monkeypatch):
       opened = _record_opens(monkeypatch)
       _tiny_model().save_pretrained(str(tmp_path / "hub"))
       flushes = _flush_opens_of_partials(opened)
       assert flushes and all(flags & os.O_RDWR for flags in flushes)
   ```

   `os.O_RDWR` is 2 and `os.O_RDONLY` is 0 on Linux, macOS and Windows, so `flags & os.O_RDWR` is false for today's read-only open. `torch.save` and `safetensors` write the partial through their own file handles, not `os.open`, so the only non-creating `os.open` of a `.partial` path is the flush. `tests/test_hub_mixin.py::test_hub_weights_are_flushed_before_they_are_renamed_into_place` (L836–L856) patches `_full_fsync` and cannot see the open mode; it stays unchanged and must pass.

**Worker setup.** Needs Windows to observe the lost flush; on Linux the tests above prove the fix by spying on `os.open` and asserting the flush's descriptor is writable. Branch from `develop`. `uv sync --frozen --all-extras` installs torch, `safetensors` and every extra the tests need.
