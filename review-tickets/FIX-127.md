## Summary

FIX-127: `nnx._optional.require` already tells a *missing* optional package (name the extra) from a *broken* one (propagate its own error), but its registry `DOMAIN_EXTRAS` knows only `torch_geometric`, `torchvision` and `plotly`. Eleven other optional packages are guarded by hand-rolled `try/except ImportError` blocks that call every failure "missing". This ticket (part 1 of 3) registers those packages with their extras and adds `require_onnxscript`. No caller changes here; FIX-128 and FIX-129 move the call sites.

## Context

**What happens today.** The registry (`src/nnx/_optional.py` L19–L24):

```python
# top-level import name -> (extra, distribution name)
DOMAIN_EXTRAS: dict[str, tuple[str, str]] = {
    "torch_geometric": ("graph", "torch_geometric"),
    "torchvision": ("vision", "torchvision"),
    "plotly": ("plots", "plotly"),
}
```

`require(module, feature)` (L33–L51) re-raises any import failure unless the package is registered, the missing module is the package itself, and the package is not installed; only then does it raise `ImportError(f"{feature} needs {package}: {install_hint(package)}")`. `install_hint` (L27–L30) builds `pip install "thekaveh-nnx[<extra>]" (or pip install <second element>)`.

**Why it matters.** When, for example, torchao is installed but one of its own imports fails, the hand-rolled guards tell the user to install what they already have. Routing them through `require` fixes that, but only for registered packages.

**History.** #249 (FEAT-031) introduced `require` for the three domain stacks and pinned "An `ImportError` raised inside an installed dependency keeps its original cause." This is the leftover: the other extras never joined it. #234 set the wording a new optional backend must match: the error "leads with `pip install "thekaveh-nnx[embeddings]"`". #220 requires the Jev error to name `thekaveh-nnx[jev]`.

**Background for the worker.**
- Extra: an entry of `[project.optional-dependencies]` in `pyproject.toml` (`quantize`, `gguf-write`, `jev`, `embeddings`, `viz`, `viz-interactive`, `optuna`, `hub`, `onnx-dynamo`, …), installed with `pip install "thekaveh-nnx[<extra>]"`.
- Second element of a `DOMAIN_EXTRAS` value: today a distribution name. From this ticket on it is "the requirement `pip install` takes directly", quoted when it carries a version bound, exactly as the hand-rolled hints print it today (`pip install 'torchao>=0.17'`, `pip install 'captum>=0.7.0'`). `tests/test_viz_attribute.py` L96 asserts `pip install 'captum`, so the quoted form is what keeps that test passing in FIX-129. The three existing entries do not change.
- `SDK_RANGE` (`nnx.decisions.jev`, L99): `">=0.7,<0.8"`, the `typesafe-sdk` range the Jev adapter is tested against; the `jev` hint carries it.

**Proposal.**
1. In `src/nnx/_optional.py`, replace L19–L24 with:

   ```python
   # top-level import name -> (extra, the requirement `pip install` takes directly)
   DOMAIN_EXTRAS: dict[str, tuple[str, str]] = {
       "torch_geometric": ("graph", "torch_geometric"),
       "torchvision": ("vision", "torchvision"),
       "plotly": ("plots", "plotly"),
       "torchao": ("quantize", "'torchao>=0.17'"),
       "gguf": ("gguf-write", "'gguf>=0.19.0'"),
       "typesafe_sdk": ("jev", "'typesafe-sdk>=0.7,<0.8'"),  # nnx.decisions.jev.SDK_RANGE
       "faiss": ("embeddings", "faiss-cpu"),
       "captum": ("viz", "'captum>=0.7.0'"),
       "torchinfo": ("viz", "'torchinfo>=1.8.0'"),
       "netron": ("viz-interactive", "netron"),
       "optuna": ("optuna", "optuna"),
       "safetensors": ("hub", "safetensors"),
       "huggingface_hub": ("hub", "huggingface_hub"),
       "onnxscript": ("onnx-dynamo", "onnxscript"),
   }
   ```

2. Replace the `install_hint` docstring (L28) with `"""The install command for an optional package, leading with the NNx extra."""` and rename its local `distribution` to `requirement` (L29–L30):

   ```python
       extra, requirement = DOMAIN_EXTRAS[package]
       return f'pip install "thekaveh-nnx[{extra}]" (or pip install {requirement})'
   ```

3. Replace the `Raises:` block of `require`'s docstring (L36–L40, from `    Raises:` to `            Any other import failure propagates unchanged.`) with:

   ```
       Raises:
           ImportError: the package ``module`` belongs to is registered in
               :data:`DOMAIN_EXTRAS` and is not installed; the message names
               the extra (``pip install "thekaveh-nnx[<extra>]"``) and the
               original error is the cause. Any other import failure,
               including one raised inside an installed package, propagates
               unchanged.
   ```

4. Add after `require_onnx` (after L68):

   ```python
   def require_onnxscript(feature: str) -> None:
       """Import ``onnxscript`` before a dynamo (``torch.export``) ONNX export.

       Without it torch's dynamo exporter fails with an error that names no
       install command.

       Raises:
           ImportError: ``onnxscript`` is not installed; the message names
               ``thekaveh-nnx[onnx-dynamo]``. An installed ``onnxscript`` that
               fails to import raises its own error.
       """
       require("onnxscript", feature)
   ```

5. Replace the module docstring (L1–L11) with:

   ```python
   """Optional dependencies (FEAT-031).

   Every optional package NNx imports on use is registered in
   :data:`DOMAIN_EXTRAS` with the extra that installs it: the graph
   (``torch_geometric``), vision (``torchvision``) and plotting (``plotly``)
   stacks, and the packages behind the ``quantize``, ``gguf-write``, ``jev``,
   ``embeddings``, ``viz``, ``viz-interactive``, ``optuna``, ``hub`` and
   ``onnx-dynamo`` extras. Apart from ``huggingface_hub`` (``NNModel``
   subclasses its mixin when it is installed), ``import nnx`` loads none of
   them. A feature that needs one imports it on use through :func:`require`,
   which names the extra to install when the package itself is missing. An
   ``ImportError`` raised from *inside* an installed package (one of its own
   dependencies missing or broken) propagates unchanged, with its cause.
   :func:`require_onnx` does the same for the ``onnx`` extra before a legacy
   ONNX export, and :func:`require_onnxscript` for the ``onnx-dynamo`` extra
   before a dynamo export.
   """
   ```

6. Create `tests/test_optional_extras.py`:

   ```python
   """FIX-127: every optional package NNx imports on use is registered in
   nnx._optional with an extra that pyproject.toml declares and that installs it."""

   from __future__ import annotations

   import re
   import sys
   import tomllib
   from pathlib import Path

   import pytest

   from nnx import _optional
   from nnx.decisions.jev import SDK_RANGE

   ROOT = Path(__file__).resolve().parents[1]
   EXTRAS = tomllib.loads((ROOT / "pyproject.toml").read_text(encoding="utf-8"))["project"]["optional-dependencies"]


   def _name(requirement: str) -> str:
       return re.split(r"[<>=!~\[; ]", requirement.strip("'"), maxsplit=1)[0]


   def test_the_registry_covers_every_optional_package_nnx_imports_on_use():
       assert set(_optional.DOMAIN_EXTRAS) == {
           "torch_geometric", "torchvision", "plotly", "torchao", "gguf", "typesafe_sdk", "faiss",
           "captum", "torchinfo", "netron", "optuna", "safetensors", "huggingface_hub", "onnxscript",
       }


   @pytest.mark.parametrize("package", sorted(_optional.DOMAIN_EXTRAS))
   def test_every_registered_package_names_an_extra_that_installs_it(package):
       extra, requirement = _optional.DOMAIN_EXTRAS[package]
       assert extra in EXTRAS, extra
       assert _name(requirement) in {_name(req) for req in EXTRAS[extra]}, (package, requirement)


   def test_the_jev_hint_carries_the_tested_sdk_range():
       assert _optional.DOMAIN_EXTRAS["typesafe_sdk"] == ("jev", f"'typesafe-sdk{SDK_RANGE}'")


   @pytest.mark.parametrize(
       ("package", "hint"),
       [
           ("torchao", "pip install \"thekaveh-nnx[quantize]\" (or pip install 'torchao>=0.17')"),
           ("captum", "pip install \"thekaveh-nnx[viz]\" (or pip install 'captum>=0.7.0')"),
           ("faiss", 'pip install "thekaveh-nnx[embeddings]" (or pip install faiss-cpu)'),
           ("plotly", 'pip install "thekaveh-nnx[plots]" (or pip install plotly)'),
       ],
   )
   def test_install_hint_leads_with_the_extra(package, hint):
       assert _optional.install_hint(package) == hint


   def test_require_names_the_extra_of_a_missing_package(monkeypatch):
       monkeypatch.setitem(sys.modules, "torchao", None)
       monkeypatch.setitem(sys.modules, "torchao.quantization", None)
       with pytest.raises(ImportError, match=r'^quantize_int8 needs torchao: pip install "thekaveh-nnx\[quantize\]"'):
           _optional.require("torchao.quantization", "quantize_int8")


   def test_require_onnxscript_names_the_onnx_dynamo_extra(monkeypatch):
       monkeypatch.setitem(sys.modules, "onnxscript", None)
       expected = r'^to_onnx\(dynamo=True\) needs onnxscript: pip install "thekaveh-nnx\[onnx-dynamo\]" \(or pip install onnxscript\)$'
       with pytest.raises(ImportError, match=expected):
           _optional.require_onnxscript("to_onnx(dynamo=True)")
   ```

   Run `uv run ruff format tests/test_optional_extras.py` after creating it (it splits the set literal one item per line).

   `sys.modules[name] = None` makes `import name` raise `ModuleNotFoundError` with `name` set and makes `importlib.util.find_spec(name)` return `None`, so `require` sees a missing package. `import nnx.decisions.jev` needs no SDK (#220).

7. No CHANGELOG entry: nothing a user sees changes until FIX-128 and FIX-129 move the call sites (each adds its own entry).
