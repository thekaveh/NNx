## Summary

FIX-124: `nnx.embeddings.train_contrastive` checks only `n_epochs <= 0` and `batch_size < 2`. `n_epochs=True` trains one epoch, and `n_epochs=2.5` passes the check, moves the backbone and builds the optimizer, then fails at `range(2.5)`. This ticket validates both with `require_count`, keeping the current out-of-range messages.

## Context

**What happens today.** `train_contrastive` (`src/nnx/embeddings/contrastive_trainer.py` L402–L408):

```python
    if n_epochs <= 0:
        raise ValueError(f"n_epochs must be positive, got {n_epochs}")
    if batch_size < 2:
        # NT-Xent needs at least one negative per batch (nt_xent_loss
        # itself raises on B < 2 as the backstop; rejecting here gives
        # the error before any training work happens).
        raise ValueError(f"batch_size must be >= 2 for NT-Xent (got {batch_size}) — each batch needs a negative.")
```

A bool passes both checks and trains as `1` / `True`; a float passes them and fails later in `range()` or the `DataLoader`. The same file's `embed_texts` already validates its `batch_size` with `require_count` (L220–L226).

**Why it matters.** A bad count is refused after side effects (`backbone.to(device)`, the optimizer build) or runs a different number of epochs than asked.

**History.** #231 set the rule for counts: "Accept `numbers.Integral` values, including NumPy integers, and normalize them to Python `int`. Reject booleans, all floats (including `2.0`), strings and nonfinite values." #542 refused bool hyperparameters in paradigm steps and #544 moved hand-written validators onto the shared helpers; this function's two counts are their leftover.

**Background for the worker.**
- `require_count(value, field, *, owner, minimum, maximum, exclusive_min, exclusive_max, domain_message)` (`src/nnx/_validation.py` L140–L176): returns `int(value)` for a non-bool integral in the domain. A bool, any float, a string or `None` raises `ValueError("<owner> requires <field> to be an integer <domain>, got <repr> of type <type>")`; an out-of-domain integer raises `domain_message` when given.
- NT-Xent: the contrastive loss (`nnx.nt_xent_loss`); it needs at least two pairs per batch, so `batch_size` must be at least 2.

**Proposal.**
1. In `src/nnx/embeddings/contrastive_trainer.py`, `train_contrastive`, replace L402–L408 with:

   ```python
       # Integer counts (#231): a bool trained as 1 and a float failed late, in range().
       n_epochs = require_count(
           n_epochs,
           "n_epochs",
           owner="train_contrastive",
           minimum=1,
           domain_message=f"n_epochs must be positive, got {shown(n_epochs)}",
       )
       # NT-Xent needs at least one negative per batch (nt_xent_loss itself
       # raises on B < 2 as the backstop; rejecting here gives the error
       # before any training work happens).
       batch_size = require_count(
           batch_size,
           "batch_size",
           owner="train_contrastive",
           minimum=2,
           domain_message=f"batch_size must be >= 2 for NT-Xent (got {shown(batch_size)}) — each batch needs a negative.",
       )
   ```

   `require_count` and `shown` are already imported (L44).
2. In the same function's docstring, replace the `ValueError` item of `Raises:` (L393–L398):

   Old:
   ```
           ValueError: on a dataset of fewer than 2 pairs, batch_size < 2,
               non-positive epochs, a ``temperature``, ``lr`` or
               ``grad_clip_norm`` that is not a finite positive real (a
               ``bool`` included) — NT-Xent needs at least one
               negative, so both the dataset and every batch must carry
               >= 2 pairs.
   ```
   New:
   ```
           ValueError: on a dataset of fewer than 2 pairs, an ``n_epochs``
               that is not an integer >= 1 or a ``batch_size`` that is not
               an integer >= 2 (a ``bool`` or a float included), or a
               ``temperature``, ``lr`` or ``grad_clip_norm`` that is not a
               finite positive real (a ``bool`` included) — NT-Xent needs
               at least one negative, so both the dataset and every batch
               must carry >= 2 pairs. Every check runs before the backbone
               is moved or an optimizer is built.
   ```
3. Regenerate the API reference: `uv run python -m scripts.docs.build_api_reference` (catalogued at `scripts/docs/api_reference_catalog.txt` L1047).
4. Add to `CHANGELOG.md` under `## [Unreleased]` → `### Fixed`:

   ```
   - **`train_contrastive` validates `n_epochs` and `batch_size` as integer counts.** `n_epochs=True` ran one epoch, and `n_epochs=2.5` failed in `range()` after the backbone had moved and the optimizer was built. A bool or a float for either now raises `ValueError` before any work; NumPy integers are accepted.
   ```
5. In `tests/test_embeddings_contrastive.py`, add after `test_train_contrastive_rejects_batch_size_one`:

   ```python
   @pytest.mark.parametrize(
       ("kwargs", "match"),
       [
           ({"n_epochs": True}, r"train_contrastive requires n_epochs to be an integer >= 1, got True of type bool"),
           ({"n_epochs": 2.5}, r"train_contrastive requires n_epochs to be an integer >= 1, got 2\.5 of type float"),
           ({"batch_size": 1.0}, r"train_contrastive requires batch_size to be an integer >= 2, got 1\.0 of type float"),
           ({"batch_size": True}, r"train_contrastive requires batch_size to be an integer >= 2, got True of type bool"),
       ],
   )
   def test_train_contrastive_refuses_a_non_integer_count_before_any_change(kwargs, match):
       backbone = _HashEmbedder(vocab_size=64, dim=8)
       before = {k: v.detach().clone() for k, v in backbone.state_dict().items()}
       pairs = [("a b", "a c"), ("d e", "d f"), ("g h", "g i")]
       with pytest.raises(ValueError, match=match):
           train_contrastive(backbone, pairs, **{"n_epochs": 1, "batch_size": 2, **kwargs})
       after = backbone.state_dict()
       assert all(torch.equal(before[k], after[k]) for k in before)


   def test_train_contrastive_accepts_numpy_counts():
       import numpy as np

       backbone = _HashEmbedder(vocab_size=64, dim=8)
       pairs = [("a b", "a c"), ("d e", "d f"), ("g h", "g i")]
       assert train_contrastive(backbone, pairs, n_epochs=np.int64(1), batch_size=np.int32(2)) is backbone
   ```

6. Existing tests keep passing unchanged: `test_train_contrastive_rejects_bad_inputs` (L132) matches only `"n_epochs"` / `"batch_size"`, and `test_train_contrastive_rejects_batch_size_one` (L363) matches `"batch_size"`; both appear in the kept out-of-range messages.
