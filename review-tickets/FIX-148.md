## Summary

FIX-148: NNx's GGUF writer and Ollama-bundle exporter write the custom `nnx_transformer` architecture, which stock llama.cpp, Ollama and LM Studio cannot load. `docs/gguf.md`, the `nnx.interop` docstrings and the external-contracts ledger say so; the README, which is also the PyPI page and carries the `"ollama"` keyword, lists "experimental GGUF export" in its feature list without saying it. This ticket adds that sentence to the README feature list (the "keep it and document it" option of the finding).

## Context

**Pre-check (DROP or not).** `grep -n -i "gguf\|ollama\|llama.cpp\|lm studio\|stock" README.md` at `9ad461e` returns three lines:
- L56: `- **Networks and export** — … ONNX, Hub, safetensors and experimental GGUF export.`
- L107: `pip install "thekaveh-nnx[gguf-write]"          # experimental NNx GGUF writer`
- L333: `- [Experimental GGUF export](docs/gguf.md) — write and inspect an NNx-tagged GGUF file, and the current stock-runtime limits.`

None says that stock runtimes cannot load the output, and Ollama is not mentioned at all; L333 only points to "limits". So the ticket is not dropped.

**What happens today.** The limit is stated elsewhere: `docs/gguf.md` L9–L12 ("NNx writes `general.architecture = "nnx_transformer"`, which stock llama.cpp, Ollama, and LM Studio do not implement"), `src/nnx/interop/ollama.py` L5–L6 ("stock Ollama cannot load NNx's ``nnx_transformer`` GGUF architecture") and `docs/external-contracts.md` (GGUF row: "Stock llama.cpp, Ollama, and LM Studio execution remains explicitly unsupported"). `pyproject.toml` L45 lists `"ollama"` among the PyPI keywords.

**Why it matters.** A user who finds NNx through the `ollama` keyword or the feature list expects a file Ollama runs.

**History.** #255 scoped export conformance to structural evidence for GGUF and listed "A GGUF engine" as Out; documenting that a custom runtime is required matches that decision. #525 and #517 maintained the GGUF path recently, so deprecating it (the finding's other option) is not taken.

**Background for the worker.**
- GGUF: the llama.cpp model file format. `general.architecture` names the model architecture a runtime must implement to execute the file.
- `PYPI_README.md` is generated from `README.md`: regenerate it, never edit it by hand.

**Proposal.**
1. `README.md` L56:

   Old: `- **Networks and export** — feed-forward, convolutional, graph, transformer and ViT networks; a small language-model path; ONNX, Hub, safetensors and experimental GGUF export.`

   New: ``- **Networks and export** — feed-forward, convolutional, graph, transformer and ViT networks; a small language-model path; ONNX, Hub, safetensors and experimental GGUF / Ollama-bundle export. The GGUF file uses NNx's own `nnx_transformer` architecture, which stock llama.cpp, Ollama and LM Studio cannot load: running it needs a runtime patched for NNx.``
2. Regenerate the PyPI README: `uv run python -m scripts.docs.build_pypi_readme`.

**Worker setup.** No torch needed (docs/config only).
