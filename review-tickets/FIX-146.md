## Summary

FIX-146: Nine numbered examples are only imported by the tests, never run, and `examples/README.md` says import-only examples are "references" without saying which ones. One of them, example 13, combines torch and FAISS without the macOS OpenMP guard `docs/embeddings.md` requires, which no test can catch. This ticket names the nine in the README and adds the guard to example 13. Running them in CI stays out of scope (#572's policy).

## Context

**What happens today.**
- `examples/README.md` L37–L39: "`tests/test_examples_smoke.py` imports every example, runs many of them end to end and executes their bounded helpers. Examples that are only imported are references, not evidence that they work." It never lists them. At `9ad461e` these numbered examples appear in no run list of `tests/test_examples_smoke.py` (neither the end-to-end list at L113–L143 nor `BOUNDED_EXAMPLE_HELPERS` at L169–L234): `06_finetune_with_layer_freezing.py`, `13_train_domain_embedder.py`, `14_moe_classifier.py`, `17_export_transformer_to_gguf.py`, `18_export_ollama_bundle.py`, `19_prune_synthetic_classifier.py`, `21_viz_attribute_xai.py`, `23_born_again_distillation.py`, `24_feature_kd.py`.
- `examples/13_train_domain_embedder.py` imports torch at L38, then calls `faiss.read_index` (L161) and `idx.search` (L164) with no `KMP_DUPLICATE_LIB_OK` / `OMP_NUM_THREADS` setup. `docs/embeddings.md` L25 says such a process can abort ("OMP: Error #15") and to set both first; `examples/ranking_offline.py` L44–L54 does.

**Why it matters.** A reader cannot tell which examples are verified, and example 13 can abort on macOS for a user who copies it.

**History.** #572 decided the policy: "Running import-only examples: examples/README.md calls them 'references, not evidence that they work'; that policy is unchanged." This ticket keeps that policy and only makes it visible. #570 fixed seeding and private names in examples.

**Background for the worker.**
- Import-only example: a script that `test_example_imports_without_running_main` imports (so its imports work) but no test executes.
- OpenMP guard: on macOS the `faiss-cpu` and `torch` wheels each bundle an OpenMP runtime; setting `KMP_DUPLICATE_LIB_OK=TRUE` and `OMP_NUM_THREADS=1` before either loads avoids the abort. `os.environ.setdefault` leaves a user's own setting alone.
- ruff's `E402` allows imports after `os.environ` changes, as `examples/ranking_offline.py` shows.

**Proposal.**
1. `examples/README.md`, replace L39:

   Old: `Examples that are only imported are references, not evidence that they work.`

   New (two lines):
   ```
   Examples that are only imported are references, not evidence that they work.
   Import-only today (no test executes them): 06, 13, 14, 17, 18, 19, 21, 23 and 24.
   ```
2. `examples/13_train_domain_embedder.py`: add `import sys` after `import os` (L34), and insert between `import zlib` (L36) and `import torch` (L38), separated from each by one blank line:

   ```python
   # macOS: the faiss-cpu and torch wheels each bundle an OpenMP runtime, and
   # a process that loads both aborts ("OMP: Error #15") or crashes in the
   # FAISS search. Set before either library loads. Linux needs neither.
   if sys.platform == "darwin":
       os.environ.setdefault("KMP_DUPLICATE_LIB_OK", "TRUE")
       os.environ.setdefault("OMP_NUM_THREADS", "1")
   ```

**Worker setup.** No torch needed for the edits; `uv sync --frozen --all-extras` is needed for the checks. The abort itself needs macOS to observe; the check below proves only that the guard is in place and the example still imports.
