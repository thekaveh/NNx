## Summary

FIX-119: `save_lora_weights` on a net that holds `DoRALinear` layers writes only `lora_A` / `lora_B` and drops each learned `magnitude` without a runtime warning. A user who reloads that file gets a different function. This ticket adds a `UserWarning` that names the DoRA layers; what is saved does not change.

## Context

**What happens today.** `save_lora_weights` selects the keys owned by `LoRALinear` wrappers. `DoRALinear` subclasses `LoRALinear`, so its `lora_A` / `lora_B` are saved and its `magnitude` is not:

```python
_LORA_OWNED = ("lora_A", "lora_B")
```

```python
    sd = _lora_keys_only(module, module.state_dict())
    atomic_torch_save(sd, str(path))
    return str(path)
```

(`atomic_torch_save` since #859, at `1402b49`.) `load_lora_weights` then leaves each DoRA layer's `magnitude` at its construction value, `||W_0||` per row. The docs already say so (`docs/concepts.md` L1677: "Persist a DoRA adapter with the complete `state_dict()`, since the LoRA-only helpers omit `magnitude`"; the `DoRALinear` docstring says the same), but nothing tells a user at the call.

**Why it matters.** A user who follows the LoRA recipe for a DoRA net loses the trained magnitudes silently. The warning is the cheap guard.

**History.** This finding is narrowed by #201. #201 scoped out the DoRA save API: "**Out:** A separate DoRA-magnitude artifact API; the learned DoRA magnitude still needs a full-state round trip." #201 also required "Verify that the existing DoRA LoRA-only round-trip test passes unchanged." So this ticket does NOT add `save_dora_weights` (that is DEC-020), does NOT change which keys are saved, and leaves `test_save_lora_weights_captures_dora_lora_matrices` unchanged. #225 recorded that `magnitude` "needs full module state persistence". The prompt-loader shape-check nit from the same finding (BUG-19 step 3) is not ticketed: one prompt tensor cannot half-load.

**Background for the worker.**
- `LoRALinear`: wraps an `nn.Linear` with a frozen `base` plus trainable `lora_A` / `lora_B` (`src/nnx/peft/lora.py`).
- `DoRALinear`: subclass of `LoRALinear` (`src/nnx/peft/dora.py`) that adds a trainable per-output-row `magnitude` parameter.
- `_lora_keys_only`: restricts a `state_dict` to the `lora_A` / `lora_B` keys of the `LoRALinear` wrappers registered in the module (ownership, not key substrings; #201).
- `_warn_at_user_frame(message, category)`: NNx's warning helper in `src/nnx/nn/callbacks.py`. It attributes the warning to the first stack frame outside the `nnx` package, so the user sees their own line. Callers import it inside the function (`from ..nn.callbacks import _warn_at_user_frame`), as `_update_engine.py` and `trainer/trainer.py` do.
- `atomic_torch_save(obj, path)` (`src/nnx/_artifacts.py`, #859; `lora.py` imports it at module level): `torch.save` through a temporary file renamed onto `path`, so a failed save leaves the previous file. The new code keeps it.
- Import cycle: `dora.py` imports `LoRALinear` from `lora.py` at module level, so `lora.py` must import `DoRALinear` inside the function.

**Proposal.**
1. In `src/nnx/peft/lora.py`, replace the body of `save_lora_weights` (L302–L304 at `1402b49`, after its docstring) with:

   ```python
       from ..nn.callbacks import _warn_at_user_frame  # attributed to the caller, not NNx
       from .dora import DoRALinear  # dora imports lora at module level: a top-level import would cycle

       dora_paths = [path or "<root>" for path, sub in module.named_modules() if isinstance(sub, DoRALinear)]
       if dora_paths:
           _warn_at_user_frame(
               f"save_lora_weights saves only lora_A / lora_B: the learned magnitude of {len(dora_paths)} "
               f"DoRALinear layer(s) ({', '.join(dora_paths)}) is not saved. Persist a DoRA adapter with the "
               "full module state_dict().",
               UserWarning,
           )
       sd = _lora_keys_only(module, module.state_dict())
       atomic_torch_save(sd, str(path))
       return str(path)
   ```

2. In the same function's docstring, insert this paragraph, followed by one blank line, directly before `Args:` (L293 at `1402b49`):

   ```
   A ``DoRALinear`` layer's learned ``magnitude`` is not LoRA state and is
   not saved; the call warns (``UserWarning``) and names those layers.
   Persist a DoRA adapter with the full ``state_dict()``.
   ```

3. Regenerate the API reference: `uv run python -m scripts.docs.build_api_reference` (`save_lora_weights` is catalogued at `scripts/docs/api_reference_catalog.txt` L857).
4. Add to `CHANGELOG.md` under `## [Unreleased]` → `### Changed`:

   ```
   - **`save_lora_weights` warns on DoRA layers.** It saves only `lora_A` / `lora_B`, so a `DoRALinear`'s learned `magnitude` is not in the file; the call now raises a `UserWarning` naming those layers. Persist a DoRA adapter with the full `state_dict()`.
   ```

5. In `tests/test_peft_dora.py`, add `import warnings` after `from __future__ import annotations`, and add these two tests after `test_save_lora_weights_captures_dora_lora_matrices`:

   ```python
   def test_save_lora_weights_warns_that_dora_magnitude_is_not_saved(tmp_path):
       torch.manual_seed(0)
       net = _TinyNet()
       apply_dora_to(net, "layers.*", r=2, alpha=4.0)
       expected = r"magnitude of 3 DoRALinear layer\(s\) \(layers\.0, layers\.1, layers\.2\) is not saved"
       with pytest.warns(UserWarning, match=expected) as record:
           save_lora_weights(net, tmp_path / "dora_lora.pt")
       assert any(w.filename == __file__ for w in record)  # attributed to the caller's line
       saved = torch.load(tmp_path / "dora_lora.pt", weights_only=True)
       assert not any(k.endswith("magnitude") for k in saved)  # what is saved is unchanged


   def test_save_lora_weights_does_not_warn_without_dora(tmp_path):
       torch.manual_seed(0)
       net = _TinyNet()
       apply_lora_to(net, "layers.*", r=2, alpha=4.0)
       with warnings.catch_warnings():
           warnings.simplefilter("error")
           save_lora_weights(net, tmp_path / "lora.pt")
   ```

   `apply_lora_to`, `apply_dora_to` and `save_lora_weights` are already imported at the top of the file.

6. Do not edit `test_save_lora_weights_captures_dora_lora_matrices` (L194) or `tests/test_peft_lora.py::test_loading_adapter_state_keeps_modes_and_adds_no_mode_key` (L747, parametrized with `"dora"`). Both still pass; the new `UserWarning` appears in pytest's warnings summary, which is expected (pytest is not run with `-W error`).
