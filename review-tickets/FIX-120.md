## Summary

FIX-120: Six paradigm train steps return `f1=0.0, recall=0.0, accuracy=0.0, precision=0.0` although they compute none of these, and Mixup / CutMix return `0.0` for `f1`, `recall` and `precision` beside a real accuracy. A user sees a fabricated 0.0 where the value is unavailable. This ticket drops those keyword arguments so the fields stay `None`, and fixes the two docs that say they "stay zero".

## Context

**What happens today.** `NNEvaluationDataPoint` defaults the four classification fields to `None`, and its docstring says a record "leaves the classification fields and `error` as ``None`` rather than fabricating them". The DPO step (`src/nnx/paradigms/dpo.py` L213–L225) fabricates them:

```python
        return NNEvaluationDataPoint(
            f1=0.0,
            recall=0.0,
            accuracy=0.0,
            precision=0.0,
            loss=loss_val,
            error=-gap,
            extra={
                "reward_chosen": float(reward_chosen.mean()),
                "reward_rejected": float(reward_rejected.mean()),
                "reward_accuracy": reward_accuracy,
            },
        )
```

The same four lines appear in the JEPA, SimCLR, text-contrastive and diffusion steps. Mixup and CutMix pass `accuracy=acc` and `0.0` for the other three. The diffusion step's docstring says the metrics "stay zero", and `docs/jepa.md` §4.4 says "The other classification fields stay zero."

**Why it matters.** A record that says `accuracy=0.0` is indistinguishable from a model that is always wrong. `NNEvaluationDataPoint.mean_of` and every renderer already skip `None` fields, because regression task records (#212) and causal-LM records (#251) leave them `None`; the paradigm steps are the leftover.

**Checks already done (BUG-20 step 4).**
- Epoch aggregation: `NNEvaluationDataPoint.mean_of` averages each field over the records that carry it (`_mean`, L203) and returns `None` when none does. `nn_run._epoch_values` reads only `loss` and `error`.
- BEST tracking, the plateau scheduler and the progress bar read `error`, then `loss` (`_resolve_metric_with_provenance`); none reads `accuracy`.
- `run.id` is the MD5 of the model, net and train params (`NNRun.__post_init__`, `nn_run.py` L912); records are not part of it, so no run id changes.
- `idps.csv` writes `None` as an empty cell, and `_read_idps_csv` reads an empty (NaN) cell back as `None`. Regression runs already take this path.
- No test asserts the zeros (`grep` over `tests/` for these fields `== 0`).

**History.**
- #82 put DPO's diagnostics in `extra`: "Each DPO step result has `reward_chosen` and `reward_rejected` in `extra` as floats", pinned by `test_dpo_step_emits_reward_metrics_in_extra`, and read by NNx Studio. **This ticket keeps them in `extra`.** BUG-20 step 2 (moving them to `metrics=`) is dropped.
- #257 (diffusion and JEPA objective adapters) required "The routed records contain no dummy classification fields." The objective paths comply (`examples/08_diffusion_2d_mixture.py` L116 and `examples/16_ijepa_image_plumbing.py` L187 assert `accuracy is None`); the step factories were not brought in line. This ticket finishes that.
- #212 and #251 set the "no fabricated classification fields" rule for task records.

**Background for the worker.**
- `NNEvaluationDataPoint` (EDP): the per-batch / per-epoch record of metrics (`src/nnx/nn/params/nn_evaluation_data_point.py`). `f1`, `recall`, `accuracy`, `precision`, `loss` and `error` are `Optional[float]`, default `None`. `extra` holds user or paradigm metrics by name.
- Paradigm train step: a function built by a `*_train_step_factory` that runs one batch, steps the optimizer and returns an EDP. `run.idps[i].train_edp` is the EDP of that epoch's last batch.
- `idps.csv`: the per-epoch record file in each run directory.

**Proposal.**
1. Delete the four lines `f1=0.0,` / `recall=0.0,` / `accuracy=0.0,` / `precision=0.0,` from these `return NNEvaluationDataPoint(...)` calls, leaving the other arguments as they are:
   - `src/nnx/paradigms/dpo.py` L214–L217 (`dpo_train_step_factory`; keep `extra=` unchanged)
   - `src/nnx/paradigms/jepa.py` L489–L492 (`jepa_train_step_factory`)
   - `src/nnx/paradigms/contrastive.py` L148–L151 (`simclr_train_step_factory`)
   - `src/nnx/embeddings/contrastive_trainer.py` L317–L320 (`text_contrastive_train_step_factory`)
   - `src/nnx/diffusion/training.py` L119–L122 (`diffusion_train_step_factory`)
2. In `src/nnx/paradigms/augmentation.py`, delete `f1=0.0,`, `recall=0.0,` and `precision=0.0,` at L177, L178, L180 (`mixup_train_step_factory`) and L269, L270, L272 (`cutmix_train_step_factory`). Keep `accuracy=acc,`.
3. In `src/nnx/diffusion/training.py`, `diffusion_train_step_factory` docstring, replace L69–L70:

   Old:
   ```
       metrics (accuracy/f1/...) are not meaningful for a generative
       paradigm and stay zero.
   ```

   New:
   ```
       metrics (accuracy/f1/...) are not meaningful for a generative

   ```
4. In `docs/jepa.md` §4.4, replace L194:

   Old: `a signal to lock onto. The other classification fields stay zero.`

5. Regenerate `docs/api.md`: `uv run python -m scripts.docs.build_api_reference` (the diffusion docstring appears there).
6. Add to `CHANGELOG.md` under `## [Unreleased]` → `### Changed`:

Saved records (`idps.csv`, checkpoint metadata) hold an empty value where they held `0.0`. `loss`, `error`, DPO's reward diagnostics in `extra` and run ids are unchanged.
