## Summary

FIX-150: #859 added `_artifacts.atomic_torch_save` for the PEFT adapter saves, `FeedFwdNN.to_file`, `TransformerNN.to_file` and the FAISS fallback, and it repeats three bugs that FIX-115 and FIX-116 fix in `nn_run`: a second import-time `os.umask(0)` read, a plain `os.fsync` (which also fails the save where the filesystem cannot flush), and an unconditional chmod that widens a re-saved file. This ticket rewrites `atomic_torch_save` on the partial-file protocol (`_reserve_partial` / `_commit_partial` / `_discard_partial`), which already gets all three right once FIX-114, FIX-115 and FIX-116 have merged, and deletes the second `_created_file_mode`. Merging it with `nn_checkpoint._atomic_torch_save` stays with FEAT-071 to FEAT-073.

## Context

**What happens today.** `src/nnx/_artifacts.py` at `1402b49`, L181–L188:

```python
def _created_file_mode() -> int:
    """The mode ``open(path, "w")`` creates a file with under the current umask."""
    umask = os.umask(0)  # read once at import: os.umask is process-wide
    os.umask(umask)
    return 0o666 & ~umask


_CREATED_FILE_MODE = _created_file_mode()
```

and the body of `atomic_torch_save` (L197–L208):

```python
    target = os.fspath(path)
    fd, tmp = tempfile.mkstemp(prefix=f".{os.path.basename(target)}.", dir=os.path.dirname(os.path.abspath(target)))
    try:
        with os.fdopen(fd, "wb") as handle:
            torch.save(obj, handle)
            handle.flush()
            os.fsync(handle.fileno())
        os.chmod(tmp, _CREATED_FILE_MODE)  # what a plain write gives, not mkstemp's 0600
        os.replace(tmp, target)
    finally:
        if os.path.exists(tmp):
            os.remove(tmp)
```

Its seven callers (all at `1402b49`): `save_lora_weights` (`peft/lora.py` L303), `save_ia3_weights` (`peft/ia3.py` L180), `save_prefix_weights` (`peft/prefix.py` L282), `save_prompt_weights` (`peft/prompt.py` L194), `FeedFwdNN.to_file` (`nn/net/feed_fwd_nn.py` L113), `TransformerNN.to_file` (`nn/net/transformer_nn.py` L227) and the `torch.save` fallback of `export_to_safetensors` (`embeddings/faiss_export.py` L201).

Problems:
1. **Import-time umask (as BUG-12, FIX-116).** `os.umask(0)` and the restore run at `import nnx`, so for a moment the process umask is 0 (a race for any thread creating files then), and every later save uses that frozen mode, whatever umask the application sets afterwards. FIX-116 deletes `nn_run`'s copy of this function and does not touch this one.
2. **Plain `os.fsync` (as BUG-11, FIX-115).** On macOS it reaches only the drive's cache, which a power loss can drop. It also raises on a filesystem that does not support a flush (`EINVAL`, `ENOTSUP`), so such a save fails, where every other NNx writer tolerates that.
3. **Widened mode (as BUG-13, FIX-116).** The chmod runs even when `path` already exists, so re-saving over an adapter file the user restricted to 0600 makes it 0644.
4. **A second atomic `torch.save` (as SMELL-01).** `nn_checkpoint._atomic_torch_save` (L294–L320 at `9ad461e`) does the same job for checkpoints, and also hashes while it writes. That merge is FEAT-071 to FEAT-073; this ticket leaves it.

The partial-file protocol in `nn_run.py` (L290–L322 at `9ad461e`) already does what problems 1–3 need, once FIX-114 and FIX-116 have merged, and `NNModel.export_state_dict` (`nn_model.py` L5017–L5025 at `9ad461e`) writes a state dict through it in six lines.

**Why it matters.** Adapter files and net weights can end up readable by other users after a re-save or under a stricter umask, can be lost on a power loss on macOS after the save returned, and fail to save at all on a filesystem without flush support. Source: #859 (1402b49), merged after the review.

**History.**
- #552 (FIX-084) set the flush rule: a real I/O error fails the write, and "an unsupported flush (`ENOTSUP`, `EINVAL`, ...) stays tolerated everywhere". The bare `os.fsync` breaks the second half for these saves.
- #443 (FIX-030) introduced `F_FULLFSYNC` (through `_full_fsync`) so a write reaches stable storage on macOS.
- #260 (FIX-025) pinned "Cleanup never unlinks a path that the helper does not own." Today's `finally` checks and removes the temporary name even after a successful rename; the partial-file protocol discards the partial only on failure.
- FIX-116 (BUG-12, BUG-13) and FIX-115 (BUG-11) fix the same problems in `nn_run`; this ticket applies their result to #859's writer, so `_reserve_partial` and `_commit_partial` stay the one place that decides a new file's mode and flush.

**Background for the worker.**
- Umask: the process-wide mask the kernel clears from the `mode` a new file is created with. `open(path, "w")` asks for 0666, so under the common umask 022 the file is 0644 ("plain mode"); `tempfile.mkstemp` asks for 0600.
- `_full_fsync(fd)` (`nn/params/nn_checkpoint.py` L213–L232 at `9ad461e`): flushes a descriptor with `fcntl(fd, F_FULLFSYNC)` where the platform has it, else `os.fsync`; an unsupported flush (`_UNSUPPORTED_FLUSH`: `ENOTSUP`, `EOPNOTSUPP`, `EINVAL`, `ENOTTY`, `EBADF`) is tolerated, any other `OSError` raises. FIX-115 routes the standalone text artifacts through it; this ticket gives the binary saves the same flush.
- `F_FULLFSYNC`: the macOS `fcntl` command that makes the drive write its cache to permanent storage. `nn_checkpoint.fcntl` is the `fcntl` module, or `None` on Windows; tests replace it with a fake that has `F_FULLFSYNC`.
- Partial file: a uniquely named, hidden file beside the destination (`.<name>.<16 hex digits>.partial`) that a writer fills and then renames onto the destination, so a failed write leaves the earlier file intact. In `src/nnx/nn/params/nn_run.py`, after FIX-114 and FIX-116:
  - `_reserve_partial(path)` creates it empty with `_create_exclusive(..., 0o666)`, so the kernel applies the umask in force at that moment (FIX-116);
  - `_commit_partial(partial, path)` gives it an existing `path`'s permission bits (`_destination_mode`, FIX-116), flushes it through `_fsync_file` (a writable descriptor, FIX-114, then `_full_fsync`) and renames it onto `path`;
  - `_discard_partial(partial)` removes it after a failure.
- `torch.save(obj, partial)` with a path opens the existing partial with `"wb"`, which keeps the mode it was created with.
- Lazy import: `_artifacts.py` is imported by modules that do not need torch or the run module (its docstring says "standard library only"), so `atomic_torch_save` imports `torch` and `nn_run` inside the function, as `atomic_write` (L65–L68 at `1402b49`) already imports `_atomic_write_text`.

**Proposal.**
1. In `src/nnx/_artifacts.py` (line numbers at `1402b49`; FIX-115 has also edited `atomic_write` by the time you start):
   - delete `import tempfile` (L15); only `atomic_torch_save` uses it;
   - delete `_created_file_mode` and `_CREATED_FILE_MODE` (L181–L188, with the blank lines after them). Do not keep an alias: the value (an import-time umask) is the bug. After FIX-116, `grep -rn "_CREATED_FILE_MODE\|_created_file_mode" src/ tests/` lists only `_artifacts.py` L181, L188 and L204 (the chmod inside `atomic_torch_save`, replaced next);
   - replace `atomic_torch_save` (L191–L208) with:

     ```python
     def atomic_torch_save(obj: Any, path: Union[str, os.PathLike[str]]) -> None:
         """``torch.save(obj, path)`` through a partial file beside ``path``, as
         ``NNModel.export_state_dict`` writes. The partial is created under the
         umask in force now (the mode a plain write gives), flushed to stable
         storage (``F_FULLFSYNC`` on macOS; a filesystem that cannot flush is
         tolerated, a real I/O error raises), given an existing ``path``'s
         permission bits so a re-save never widens them, and renamed onto
         ``path``. A failure removes the partial and leaves ``path`` as it was,
         so a reader never sees a truncated file under the final name."""
         import torch  # lazy: this module is imported by modules that do not need torch

         # lazy: the run module is heavy and imports modules that import this one
         from .nn.params.nn_run import _commit_partial, _discard_partial, _reserve_partial

         target = os.fspath(path)
         partial = _reserve_partial(target)
         try:
             torch.save(obj, partial)
             _commit_partial(partial, target)
         except BaseException:
             _discard_partial(partial)
             raise
     ```

   The seven callers keep calling `atomic_torch_save(...)` unchanged.
2. CHANGELOG: in `## [Unreleased]` → `### Fixed`, add at the end of the list:

   ```
   - **PEFT adapter saves and `to_file` on the feed-forward and transformer nets get the umask in force when they write, keep an existing file's permission bits, and flush like the other exports.** `save_lora_weights`, `save_ia3_weights`, `save_prefix_weights`, `save_prompt_weights` and `to_file` used a mode read once at import (which set the process umask to 0 for a moment) and widened a re-saved file the user had restricted. They now write through the same partial file as `export_state_dict`: flushed with `F_FULLFSYNC` on macOS, and a filesystem that cannot flush no longer fails the save.
   ```

Add at the end of the module:

   ```python
   def _fake_full_fsync(monkeypatch, error=None):
       """F_FULLFSYNC present (as on macOS): record each flushed descriptor, or raise ``error`` for it."""
       flushed: list[int] = []

       def fcntl(fd, command, *args):
           assert command == 51
           flushed.append(fd)
           if error is not None:
               raise OSError(error, os.strerror(error))
           return 0

       monkeypatch.setattr(nn_checkpoint, "fcntl", types.SimpleNamespace(F_FULLFSYNC=51, fcntl=fcntl))
       return flushed


   @pytest.mark.skipif(os.name == "nt", reason="POSIX permission bits")
   def test_a_save_follows_the_umask_in_force_when_it_writes(tmp_path):
       """The mode was read once at import (with os.umask(0) and a restore), so a stricter umask set later was
       ignored. The kernel now applies the umask in force at each save."""
       old = os.umask(0o077)
       try:
           _feed_forward().to_file(str(tmp_path / "net.pt"))
           atomic_torch_save({"w": torch.ones(2)}, tmp_path / "state.pt")
       finally:
           os.umask(old)
       assert stat.S_IMODE((tmp_path / "net.pt").stat().st_mode) == 0o600
       assert stat.S_IMODE((tmp_path / "state.pt").stat().st_mode) == 0o600


   @pytest.mark.skipif(os.name == "nt", reason="POSIX permission bits")
   def test_a_resave_keeps_the_existing_files_mode(tmp_path):
       model = nn.Sequential(nn.Linear(4, 4))
       apply_lora_to(model, "*", r=2, alpha=4.0)
       net = _feed_forward()
       net_path, lora_path = tmp_path / "net.pt", tmp_path / "lora.pt"
       old = os.umask(0o022)  # a fresh save gives 0644, so a kept 0640 is visible
       try:
           net.to_file(str(net_path))
           save_lora_weights(model, lora_path)
           os.chmod(net_path, 0o640)
           os.chmod(lora_path, 0o640)
           net.to_file(str(net_path))
           save_lora_weights(model, lora_path)
       finally:
           os.umask(old)
       assert stat.S_IMODE(net_path.stat().st_mode) == 0o640
       assert stat.S_IMODE(lora_path.stat().st_mode) == 0o640


   def test_a_save_is_flushed_with_full_fsync_where_the_platform_has_it(tmp_path, monkeypatch):
       """On macOS os.fsync reaches only the drive's cache; F_FULLFSYNC reaches stable storage."""
       flushed = _fake_full_fsync(monkeypatch)
       plain: list[int] = []
       monkeypatch.setattr(os, "fsync", plain.append)
       _feed_forward().to_file(str(tmp_path / "net.pt"))
       assert len(flushed) == 1 and plain == []


   def test_a_filesystem_that_cannot_flush_does_not_fail_the_save(tmp_path, monkeypatch):
       """An unsupported flush is tolerated, as for every other NNx file (#552)."""
       _fake_full_fsync(monkeypatch, error=errno.ENOTSUP)

       def unsupported(fd):
           raise OSError(errno.EINVAL, os.strerror(errno.EINVAL))

       monkeypatch.setattr(os, "fsync", unsupported)
       path = tmp_path / "net.pt"
       _feed_forward().to_file(str(path))
       assert path.stat().st_size > 0
       assert sorted(os.listdir(tmp_path)) == ["net.pt"]


   def test_a_real_flush_error_fails_the_save_and_keeps_the_previous_file(tmp_path, monkeypatch):
       path = tmp_path / "net.pt"
       net = _feed_forward()
       net.to_file(str(path))
       previous = path.read_bytes()
       with torch.no_grad():
           net.layers[0].weight.add_(1.0)  # the new save would write other bytes
       _fake_full_fsync(monkeypatch, error=errno.EIO)
       with pytest.raises(OSError) as caught:
           net.to_file(str(path))
       assert caught.value.errno == errno.EIO
       assert path.read_bytes() == previous
       assert sorted(os.listdir(tmp_path)) == ["net.pt"]  # the partial is discarded
   ```

   The three tests #859 added (`test_a_failed_net_save_leaves_the_previous_file_intact`, `test_a_failed_lora_save_leaves_the_previous_file_intact`, `test_a_fresh_net_file_gets_the_mode_a_plain_write_gives`) stay unchanged and must pass: `_truncating_save` handles a path target (the partial) as well as a file object, and a fresh partial gets the plain mode.
