## Summary

FIX-149: `magnitude_prune` and `semi_structured_24` match `layer_pattern` against `named_modules()`, which reports a module shared by two paths under its first name only, so a Linear registered as `a.x` and `b.x` is missed by `layer_pattern="b.*"`. They also take only one pattern, unlike `apply_lora_to(module, *patterns)`, and `magnitude_prune` checks `sparsity` with a bare comparison (a string raises a raw `TypeError`). This ticket (SMELL-57 steps 2–3) matches on every registration path, accepts `*layer_patterns` beside the kept `layer_pattern` keyword, and validates `sparsity` with `require_finite_real`.

## Context

**What happens today.** `magnitude_prune` (`src/nnx/prune/magnitude.py` L99–L110):

```python
    if not (0.0 <= sparsity < 1.0):
        raise ValueError(f"magnitude_prune sparsity must be in [0, 1), got {sparsity}")

    # Two-phase: collect targets first, then mutate. Iterating
    # named_modules() while reassigning child attributes via
    # `prune.l1_unstructured` registers a forward_pre_hook that doesn't
    # alter traversal order today, but collecting up-front keeps the
    # function defensive against any future PyTorch internals change.
    targets: list[tuple[str, nn.Linear]] = []
    for name, mod in net.named_modules():
        if isinstance(mod, nn.Linear) and fnmatch.fnmatchcase(name, layer_pattern):
            targets.append((name, mod))
```

`semi_structured_24` (`src/nnx/prune/semi_structured.py` L86–L109) builds a set of matched *names* the same way and passes torchao a filter that accepts `fqn in targets`.

**Why it matters.** A pattern for a shared layer's second name silently prunes nothing, and the two pruning functions take patterns differently from the PEFT helpers they document as "same fnmatch convention".

**History.** #224 (FIX-014) found the same bug in the PEFT apply helpers ("walk `named_modules()`, which hides repeated module objects") and fixed it by walking every registration path (`peft/_targets._registrations`). #554 (FIX-086) wrote the parametrized-weight refusal, whose message tells users to "exclude the layer with `layer_pattern`", so the `layer_pattern` keyword stays. Sharing `freeze` / `unfreeze`'s loop (SMELL-57 step 1) is FEAT-133.

**Background for the worker.**
- `_registrations(root)` (`src/nnx/peft/_targets.py` L48–L68): yields `(path, parent, attr, child)` for every registration path of every submodule (not the root), including repeats of a shared module.
- `require_finite_real` (`src/nnx/_validation.py` L50–L92): returns `float(value)` for a finite real in the domain; a bool, string or `None` raises `ValueError("<owner> requires <field> to be a finite real number …")`; an out-of-domain value raises `domain_message`.
- Decisions taken here (the open questions on this finding): positional patterns and the keyword are **joined** (union), never an error; the keyword's default becomes `None`, and with no pattern at all the selection is `"*"`, as today. A shared Linear is pruned **once**. The root module is still a candidate under the name `""`, as `named_modules()` reported it.
- `nnx.peft` does not import `nnx.prune`, so a module-level import of `..peft._targets` in `nnx.prune` adds no cycle.

**Proposal.**
1. Create `src/nnx/prune/_select.py`:

   ```python
   """Layer selection shared by the pruning functions."""

   from __future__ import annotations

   import fnmatch
   from typing import Optional

   from torch import nn

   from ..peft._targets import _registrations


   def _patterns(layer_patterns: tuple[str, ...], layer_pattern: Optional[str], helper: str) -> tuple[str, ...]:
       """The fnmatch globs a pruning call selects with: the positional
       ``layer_patterns`` and the ``layer_pattern`` keyword together, or
       ``("*",)`` (every Linear) when neither is given."""
       patterns = (*layer_patterns, *(() if layer_pattern is None else (layer_pattern,)))
       for pattern in patterns:
           if not isinstance(pattern, str):
               raise TypeError(f"{helper}: a layer pattern must be a string, got {pattern!r}")
       return patterns or ("*",)


   def _matched_linears(net: nn.Module, patterns: tuple[str, ...]) -> list[tuple[str, nn.Linear]]:
       """Every ``nn.Linear`` of ``net`` (``net`` itself included, under the
       name ``""``) one of whose registration paths matches one of
       ``patterns``, once each, under its first matching path, in registration
       order. Unlike ``named_modules()``, which reports a module shared by two
       paths under the first only, a pattern for either path selects it."""
       found: dict[int, tuple[str, nn.Linear]] = {}
       paths = [("", net), *((path, child) for path, _, _, child in _registrations(net))]
       for path, module in paths:
           if isinstance(module, nn.Linear) and id(module) not in found:
               if any(fnmatch.fnmatchcase(path, pattern) for pattern in patterns):
                   found[id(module)] = (path, module)
       return list(found.values())
   ```

     ```python
         # Two-phase: select the matched Linears FIRST, on every registration path,
         # so we can return the count and short-circuit when there's nothing to do.
         targets = _matched_linears(net, _patterns(layer_patterns, layer_pattern, "semi_structured_24"))
         if not targets:
             # No-op fast path: avoid invoking torchao at all when the
             # pattern matched nothing. Keeps the CPU-only error path off
             # the call graph for users who want to dry-run their pattern.
             return 0
         pending = {id(module) for _, module in targets}

         def _filter(mod: nn.Module, fqn: str) -> bool:
             # torchao asks per submodule path. Accept each matched Linear once,
             # by identity, so a Linear shared by two paths is swapped once,
             # whichever path torchao reaches it by.
             if isinstance(mod, nn.Linear) and id(mod) in pending:
                 pending.discard(id(mod))
                 return True
             return False

         ao_sparsity.sparsify_(net, ao_sparsity.semi_sparse_weight(), _filter)
         return len(targets)
     ```
