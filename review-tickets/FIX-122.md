## Summary

FIX-122: `nnx.bundles` parses its JSON files with its own `_parse_json` / `_no_duplicates`, which has no `parse_float` hook, so `1e999` in a bundle file reads as `inf` instead of being refused. Every other NNx JSON artifact uses the strict `_artifacts.parse_json`. This ticket makes `bundles._parse_json` a thin wrapper over `parse_json` with `max_depth=_MAX_DEPTH`, keeping the 64-level bound and the UTF-8 error mapping.

## Context

**What happens today.** `bundles._parse_json` (`src/nnx/bundles.py` L421–L437):

```python
def _parse_json(data: bytes, what: str) -> Any:
    def constant(name: str) -> Any:
        raise BundleIntegrityError(f"{what} is strict JSON; {name} is not a JSON number")

    try:
        value = json.loads(data.decode("utf-8"), object_pairs_hook=_no_duplicates, parse_constant=constant)
    except BundleIntegrityError as exc:
        raise BundleIntegrityError(f"{what}: {exc}") from None
    except RecursionError:
        raise BundleIntegrityError(f"{what} is nested too deeply") from None
    except (UnicodeDecodeError, ValueError) as exc:
        raise BundleIntegrityError(f"{what} is not valid UTF-8 JSON: {exc}") from None
```

`NaN` and repeated keys are refused, but `json.loads` turns `1e999` into `float("inf")`. A state file holding it is caught only later, by the tensor-reference walk, with an unrelated message. `_artifacts.parse_json` (L80–L114) refuses NaN, `1e999`, repeated keys, malformed text and over-deep nesting, all through one `error` type.

**Why it matters.** Two strict parsers with different rules drift (SMELL-07 counts four). The bundle copy is the one that misses the overflow.

**History.** #551 bounded JSON nesting across artifacts, journals and provenance and recorded "Bundles, provenance, `_artifacts` and the history readers share one depth walk." Its Scope Out lists "The bundle limit of 64.", so **`_MAX_DEPTH = 64` stays**; whether bundles should refuse deep run configs up front or raise the bound is DEC-019. #218 made the artifact loaders strict JSON.

**Background for the worker.**
- Run bundle: the data-only export of a run (`export_bundle`): `bundle.json` (the manifest) plus a `g-<generation>/` directory with `state.json`, safetensors payloads and `calibrator-<n>.json` records.
- `BundleIntegrityError`: the `ValueError` subclass bundles raise for a malformed or tampered bundle (`bundles.py` L125).
- `_artifacts.parse_json(text, what, error, *, max_depth=None)`: the shared strict JSON parser. Its messages start with `the {what} file …`: `repeats the key 'k'; a JSON object may name a key only once`, `is strict JSON; NaN is not a JSON number`, `holds 1e999, which overflows a float`, `is JSON: <decoder error>` (malformed text, or nesting past the decoder's own limit) and `nests more than {max_depth} levels`.
- `_MAX_DEPTH = 64`: the bundle nesting bound (`bundles.py` L112).

**Proposal.**
1. In `src/nnx/bundles.py`, add `from ._artifacts import parse_json` to the first-party imports (directly above `from ._config import _freeze_config`, L74). `_artifacts` imports only `_config`, `_json_depth` and `_validation`, so there is no cycle.
2. Delete `_no_duplicates` (L412–L418) and replace `_parse_json` (L421–L437) with:

   ```python
   def _parse_json(data: bytes, what: str) -> Any:
       """Strict JSON (:func:`nnx._artifacts.parse_json`): NaN, ``1e999``, a
       repeated key, malformed text and nesting past ``_MAX_DEPTH`` raise
       :class:`BundleIntegrityError`, as does data that is not UTF-8."""
       try:
           text = data.decode("utf-8")
       except UnicodeDecodeError as exc:
           raise BundleIntegrityError(f"{what} is not valid UTF-8 JSON: {exc}") from None
       return parse_json(text, what, BundleIntegrityError, max_depth=_MAX_DEPTH)
   ```

   The four callers (L523, L605, L1030, L1037) do not change.
3. Delete `from ._json_depth import too_deep` (L75): `_parse_json` was its only user in this module (`grep -n too_deep src/nnx/bundles.py` returns only the import afterwards).
4. Update the message fragments that `tests/test_bundle_validation.py` asserts. In the `TAMPERING` table (L439–L466), change these entries' second element:

   | Case (L) | Old match | New match |
   |---|---|---|
   | `"duplicate manifest key"` (L448) | `"duplicate JSON key"` | `"repeats the key 'version'"` |
   | `"duplicate state key"` (L449) | `"duplicate JSON key"` | `"repeats the key 'version'"` |
   | `"truncated manifest"` (L453) | `"not valid UTF-8 JSON"` | `r"the bundle\.json file is JSON: "` |
   | `"deeply nested state"` (L457) | `"nested too deeply"` | `r"the state\.json file (nests more than 64 levels\|is JSON)"` |
   | `"nested state the decoder parses"` (L458) | `"nested too deeply"` | `r"the state\.json file nests more than 64 levels"` |
   | `"duplicate calibrator key"` (L462) | `"duplicate JSON key"` | `"repeats the key 'labels'"` |

   (In the regex for "deeply nested state", write a plain `|`; it is escaped above only for the table.) The 100,000-level case raises `RecursionError` inside the decoder on Python 3.11–3.13 (`is JSON: maximum recursion depth exceeded …`) and parses on 3.14 (`nests more than 64 levels`), hence the alternation, as `tests/test_calibration.py` L1309 does.
5. In the same file, in `test_a_staged_generation_readers_would_reject_is_never_published` (L604; its callback `_Deep` nests 40 tuples; the `pytest.raises` is at L625), change `match="nested too deeply"` to `match=r"the state\.json file nests more than 64 levels"`.
6. Add a tampering case for the overflow. After `_duplicate_state_key` (ends L302), add:

   ```python
   def _overflowing_float_state(path):
       target = os.path.join(_generation_dir(path), "state.json")
       with open(target, encoding="utf-8") as handle:
           text = handle.read()
       with open(target, "w", encoding="utf-8") as handle:
           handle.write(text.replace('"version": 1,', '"version": 1,\n "overflow": 1e999,', 1))
       _rehash(path, "state.json")
   ```

   and add this entry to `TAMPERING`, after `"duplicate state key"`:

   ```python
       "overflowing float in state": (_overflowing_float_state, "holds 1e999, which overflows a float"),
   ```

   `test_validation_rejects_tampering_before_any_tensor_read` runs it through both `validate_bundle` and `reconstruct_bundle`.
7. Add to `CHANGELOG.md` under `## [Unreleased]` → `### Fixed`:

   ```
   - **Run bundles refuse an overflowing JSON number.** Bundle files are parsed by the same strict parser as every other NNx JSON artifact, so `1e999` in `bundle.json`, `state.json` or a calibrator record raises `BundleIntegrityError` instead of reading as infinity. Messages for a repeated key, malformed text and over-deep nesting now read like the other artifacts' (`the state.json file repeats the key …`); the 64-level bound is unchanged.
   ```

**Worker setup.** Branch from `develop`. `uv sync --frozen --all-extras` installs torch and every extra the tests need.
