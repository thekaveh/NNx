## Summary

FIX-115: `_atomic_write_text` flushes every text file with plain `os.fsync`, which on macOS reaches only the drive's cache. For run files that is deliberate and safe: #552 chose it, and a later directory flush with `F_FULLFSYNC` takes them to stable storage before LAST. Standalone artifacts (split manifests, standardizers, calibration, abstention and benchmark artifacts, provenance, `export_history_csv`, the Hub `config.json`, manifest and tokenizer, the Ollama `Modelfile`) have no later flush, so a power loss can drop a file NNx reported as saved. This ticket adds `_atomic_write_text(..., full_flush=True)`, which flushes through `_full_fsync`, passes it at those call sites, and updates concepts §4.2 and §14.3.

## Context

**What happens today.** `_atomic_write_text` (`src/nnx/nn/params/nn_run.py` L210) re-implements the flush inline (L250–L259):

```python
                f.write(content)
                f.flush()
                try:
                    os.fsync(raw.fileno())
                except OSError as error:
                    # fsync isn't supported on every filesystem (e.g., some
                    # network mounts): the atomic rename is still useful
                    # without it. Any other error is a failed write.
                    if error.errno not in _UNSUPPORTED_FLUSH:
                        raise
```

`_full_fsync` (`nn_checkpoint.py` L213–L232, already imported by `nn_run.py` at L37) uses `fcntl(fd, F_FULLFSYNC)` where the platform has it, "on macOS `fsync` only reaches the drive's cache, which a power loss can drop", falls back to `os.fsync`, and tolerates the same `_UNSUPPORTED_FLUSH` errors.

**Why it matters.** On macOS a split manifest, a calibration artifact or a Hub config can be lost after `save()` returned. The run files are not affected (see History). The finding was first raised for every `_atomic_write_text` file; it is narrowed here to the standalone ones and its severity lowered to Low.

**History.**
- #552 (FIX-084) chose plain `os.fsync` for run files and documented it, and this ticket keeps that choice. Its acceptance criteria: "`_atomic_write_text` has an explicit, documented flush-error decision" and "Concepts §14.3, and §4.2 if `_atomic_write_text` changes, state the flush policy for run files, history and bundles." §14.3 (L2256–L2265) records: "`run.yaml`, `metadata.yaml`, `idps.csv` and the history journal's manifest are flushed with `os.fsync` before their rename", and "The run directories are flushed like a resume point's ... All of it happens before LAST". On macOS that directory flush is an `F_FULLFSYNC`, which empties the drive's whole write cache, so the run files already reach stable storage before LAST commits.
- #443 (FIX-030) introduced `F_FULLFSYNC` for resume points; this ticket extends it to the text files no later flush covers.

**Background for the worker.**
- `F_FULLFSYNC`: the macOS `fcntl` command that asks the drive to write its cache to permanent storage; `os.fsync` on macOS stops at the drive.
- Run file: a file inside `runs/<id>/` written as part of an epoch (`run.yaml`, `metadata.yaml`, `idps.csv`, the history marker `.history-committed-by-last`, the history journal's `journal.json`). Standalone artifact: a text file a user saves or exports, with no later directory flush.
- FIX-116 (a dependency) changed the signature to `_atomic_write_text(path, content, *, plain_mode: bool = False)` and the four Hub/Ollama call sites to `plain_mode=True`; this ticket adds a second keyword next to it. FIX-114 (a dependency) made `_fsync_file` writable; it does not touch `_atomic_write_text`.
- `nnx._artifacts.atomic_write(path, text)` (`src/nnx/_artifacts.py` L64–L67) is the shared wrapper for `JsonArtifact.save` (calibration, abstention), the comparison report, the benchmark report and records, offline-distillation records and the export-conformance report.

**Proposal.**
1. In `src/nnx/nn/params/nn_run.py`, change the signature of `_atomic_write_text` to:

   ```python
   def _atomic_write_text(path: str, content: str, *, plain_mode: bool = False, full_flush: bool = False) -> None:
   ```

2. Replace the flush block (L252–L259, from `try:` through `raise`) with:

   ```python
                   if full_flush:
                       # A standalone artifact: no later flush covers it, so F_FULLFSYNC on macOS (_full_fsync
                       # tolerates the same unsupported-flush errors and raises any other).
                       _full_fsync(raw.fileno())
                   else:
                       try:
                           os.fsync(raw.fileno())
                       except OSError as error:
                           # fsync isn't supported on every filesystem (e.g., some
                           # network mounts): the atomic rename is still useful
                           # without it. Any other error is a failed write.
                           if error.errno not in _UNSUPPORTED_FLUSH:
                               raise
   ```

3. Add to the docstring, after the sentence that FIX-116 wrote about ``plain_mode``: "The temporary file is flushed with ``os.fsync``, the policy of run files, which a later directory flush before LAST takes to stable storage (#552). ``full_flush=True`` (a standalone artifact no later flush covers) flushes it with ``F_FULLFSYNC`` on macOS instead (``_full_fsync``)."
4. Pass `full_flush=True` at these nine call sites, and nowhere else:
   - `src/nnx/_artifacts.py` L67, `atomic_write`: `_atomic_write_text(os.fspath(path), text, full_flush=True)`
   - `src/nnx/history.py` L1387, `export_history_csv`: `_atomic_write_text(os.fspath(path), pd.json_normalize(data=records).to_csv(), full_flush=True)`
   - `src/nnx/data_splits.py` L325, `SplitManifest.save`: `_atomic_write_text(os.fspath(path), self.to_json(), full_flush=True)`
   - `src/nnx/preprocessing.py` L471, `Standardizer.save`: `_atomic_write_text(os.fspath(path), self.to_json(), full_flush=True)`
   - `src/nnx/provenance.py` L567, `_write_json`: `_atomic_write_text(path, canonical_bytes(value).decode("utf-8") + "\n", full_flush=True)`
   - `src/nnx/nn/nn_model.py` `_write_hub_manifest` (L1414–L1418) and `_save_pretrained`'s `config.json` write (L4777–L4781): add `full_flush=True,` after the `plain_mode=True,` line FIX-116 wrote.
   - `src/nnx/nn/generative_nn_model.py` L68–L72 (`tokenizer.json`) and `src/nnx/interop/ollama.py` L173–L177 (`Modelfile`): the same.

   The run-file call sites keep the default: `nn_run.py` L540 (`runs/best/POINTER.txt`), L1142 (history marker), L1214, L1229, L1234 (`run.yaml`, `metadata.yaml`, `idps.csv`), and `history.py` L333, L565, L589 (the journal manifest and its rollback).
5. `docs/concepts.md` §4.2: replace L432 and L434.

   Old (L432):
   ```
   The temp is flushed with `fsync` before the rename. A flush the filesystem does not support (`ENOTSUP`, `EINVAL`, ...) is tolerated. A real I/O error (`EIO`, a full disk) fails the write before the rename, so the destination keeps its previous content.
   ```
   New:
   ```
   The temp is flushed before the rename: a run file (`run.yaml`, `metadata.yaml`, `idps.csv`, the history marker and the journal's manifest) with `fsync`, because the directory flush before LAST takes it to stable storage (§14.3), and every other text artifact with `fcntl(F_FULLFSYNC)` on macOS and `fsync` elsewhere, because no later flush covers it. A flush the filesystem does not support (`ENOTSUP`, `EINVAL`, ...) is tolerated. A real I/O error (`EIO`, a full disk) fails the write before the rename, so the destination keeps its previous content.
   ```

   Old (L434):
   ```
   After a successful rename the temp name is never touched. The same writer, and so the same flush policy, also saves these other NNx text artifacts: split manifests, standardizers, calibration and abstention artifacts, provenance records, `export_history_csv` and the `runs/best` pointer.
   ```
   New:
   ```
   After a successful rename the temp name is never touched. The same writer also saves these other NNx text artifacts, flushed with `F_FULLFSYNC` on macOS: split manifests, standardizers, calibration and abstention artifacts, provenance records, `export_history_csv`, benchmark and comparison reports, the Hub `config.json`, manifest and `tokenizer.json`, and the Ollama `Modelfile`. The `runs/best` pointer file (`best/POINTER.txt`, where symlinks are unavailable) is flushed as a run file.
   ```

8. Tests in `tests/test_atomic_write_text.py`. Add `import types` (after `import tempfile`, L15) and `import nnx.nn.params.nn_checkpoint as nn_checkpoint` (before `import nnx.nn.params.nn_run as nn_run`, L21). The module defines `nn_run`, `_atomic_write_text` and `mock`. Add at the end:

   ```python
   def _fake_full_fsync(monkeypatch, command=None):
       """F_FULLFSYNC present: record each fcntl command, or run ``command`` for it."""
       calls: list[int] = []

       def fcntl(fd, cmd, *args):
           calls.append(cmd)
           return command(fd, cmd) if command is not None else 0

       monkeypatch.setattr(nn_checkpoint, "fcntl", types.SimpleNamespace(F_FULLFSYNC=51, fcntl=fcntl))
       return calls


   @pytest.mark.parametrize("full_flush", [True, False], ids=["standalone", "run-file"])
   def test_a_standalone_artifact_gets_full_fsync_and_a_run_file_keeps_fsync(tmp_path, monkeypatch, full_flush):
       full_calls = _fake_full_fsync(monkeypatch)
       fsync_calls: list[int] = []
       real_fsync = os.fsync
       monkeypatch.setattr(nn_run.os, "fsync", lambda fd: fsync_calls.append(fd) or real_fsync(fd))
       _atomic_write_text(str(tmp_path / "artifact.json"), "x", full_flush=full_flush)
       assert (full_calls, len(fsync_calls)) == (([51], 0) if full_flush else ([], 1))


   def test_json_artifacts_are_flushed_with_full_fsync(tmp_path, monkeypatch):
       """JsonArtifact.save, the comparison and benchmark reports all go through nnx._artifacts.atomic_write."""
       from nnx._artifacts import atomic_write

       full_calls = _fake_full_fsync(monkeypatch)
       atomic_write(tmp_path / "report.json", "{}")
       assert full_calls == [51]


   def test_a_real_full_flush_error_fails_a_standalone_write_before_the_rename(tmp_path, monkeypatch):
       def eio(fd, cmd):
           raise OSError(errno.EIO, "Input/output error")

       _fake_full_fsync(monkeypatch, command=eio)
       target = tmp_path / "split.json"
       target.write_text("old", encoding="utf-8")
       with pytest.raises(OSError) as caught:
           _atomic_write_text(str(target), "new", full_flush=True)
       assert caught.value.errno == errno.EIO
       assert sorted(p.name for p in tmp_path.iterdir()) == ["split.json"]
       assert target.read_text(encoding="utf-8") == "old"
   ```

   The existing tests that patch `nn_run.os.fsync` (`test_atomic_text_success_utf8` L128, `test_a_real_flush_io_error_fails_the_write_before_the_rename` L139, `test_the_temp_is_flushed_before_it_is_renamed` L158) call `_atomic_write_text` without `full_flush`, so they keep testing the run-file path on every platform and stay unchanged.
