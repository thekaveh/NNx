## Summary

FIX-139: The guides name `nnx.decisions.jev.SDK_RANGE` (`docs/decisions.md` L276) and `nnx.interop.gguf.SUPPORTED_QUANTIZATIONS` (`docs/gguf.md` L35), both in their modules' `__all__`, but `docs/api.md` lists neither. This ticket adds both to `scripts/docs/api_reference_catalog.txt` and regenerates `docs/api.md`.

## Context

**What happens today.** The catalog renders `nnx.decisions.jev` with no members (`scripts/docs/api_reference_catalog.txt` L205):

```
@api nnx.decisions.jev members=
```

and §16.1 (L1059–L1067) catalogs `write_gguf`, `map_tensors` and `export_ollama_modelfile` but not the `nnx.interop.gguf` package or its constant. `grep -c SDK_RANGE docs/api.md` and `grep -c SUPPORTED_QUANTIZATIONS docs/api.md` both print 0.

**Why it matters.** A reader who follows a guide's name to the API reference finds nothing.

**History.** #220 (the Jev adapter) introduced `SDK_RANGE` as the tested SDK range; the `nnx.decisions.jev` module docstring already states the range in prose, so only the constant's entry is missing. #235 required that "New symbols are exported and listed in `scripts/docs/api_reference_catalog.txt`"; constants are listed with `members=`, as `@api nnx members=__version__,…` does at L9.

**Background for the worker.**
- `scripts/docs/api_reference_catalog.txt`: the list of `@api <dotted.path> [members=a,b]` entries that `scripts/docs/build_api_reference.py` renders into `docs/api.md`. `members=` with names renders those attributes under the entry; a constant renders its value and "Exported value."
- `docs/api.md` is generated: never edit it by hand.

**Proposal.**
1. In `scripts/docs/api_reference_catalog.txt`, replace L205:

   Old: `@api nnx.decisions.jev members=`

   New: `@api nnx.decisions.jev members=SDK_RANGE`
2. In the same file, §16.1, insert before L1063 (`@api nnx.interop.gguf.writer.write_gguf`):

   ```
   @api nnx.interop.gguf members=SUPPORTED_QUANTIZATIONS

   ```

   (the entry, then one blank line).
3. Regenerate: `uv run python -m scripts.docs.build_api_reference`.

**Worker setup.** No torch needed (docs/config only). `uv sync --frozen --all-extras` is still needed so the builder can import `nnx`.

## Acceptance criteria

- [ ] Both constants are in the reference. Check: `grep -c "nnx.decisions.jev.SDK_RANGE\|nnx.interop.gguf.SUPPORTED_QUANTIZATIONS" docs/api.md` returns at least 2
- [ ] The reference is in sync. Check: `uv run python -m scripts.docs.build_api_reference --check`
- [ ] The docs build passes. Check: `uv run python -m scripts.docs.build_docs --check`
- [ ] The projection tests pass. Check: `uv run pytest tests/test_docs_projection.py`
