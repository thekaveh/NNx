## Summary

FIX-134: Since 3ed0133 (#853), `StreamingMetrics.update` checks the scored rows of categorical probabilities and raises `ValueError` for a row that is not finite, not in [0, 1] or does not sum to 1. Its docstring and `docs/concepts.md` §21 do not say so, and the CHANGELOG names only "NaN, infinite and out-of-range" rows. This ticket documents the full rule in all three places.

## Context

**What happens today.** `StreamingMetrics.update` (`src/nnx/streaming.py` L545–L547):

```python
                # The scored rows, checked as categorical probabilities in their input's own
                # dtype (a bfloat16 tensor's rounding), before anything is accumulated.
                categorical_probabilities(_scored_rows(probabilities, mask), error=ValueError, allow_empty=True)
```

`categorical_probabilities` (`src/nnx/_probability.py` L170–L178) requires each row to be "finite, in ``[0, 1]``, each row summing to 1 within the input's own rounding". The check runs only for categorical semantics. The CHANGELOG `[Unreleased]` → `### Fixed` bullet (L32 at `9ad461e`) reads "Streaming metrics refuse NaN, infinite and out-of-range probability rows."

**Why it matters.** A caller streaming softmax outputs that were renormalized or truncated gets a refusal the docs do not mention, and the CHANGELOG omits the most likely cause (a row that does not sum to 1).

**History.** #518 established the documentation precedent for `StreamingMetrics.update`: its docstring and concepts §21 describe exactly what a scored row reads. This ticket adds the refusal there.

**Background for the worker.**
- `StreamingMetrics`: the mergeable metric accumulator in `nnx.streaming`; `update(target, probabilities=..., ...)` adds one batch.
- Scored rows: the rows whose target is not masked (`valid=False`, a NaN target, or `ignore_index`); masked rows are not checked.
- `docs/api.md` is generated from docstrings: regenerate it, never edit it by hand.

**Proposal.**
1. In `src/nnx/streaming.py`, `StreamingMetrics.update` docstring, insert after L510 (`        excluded too. Arrays and tensors are accepted.`) one blank line and:

   ```
           Categorical probabilities of the scored rows must be finite, in
           [0, 1] and sum to 1 within the input dtype's rounding bound; any
           other row raises ``ValueError`` before anything is accumulated.
   ```
2. In `docs/concepts.md` §21 (**Mergeable metrics**), replace L2964:

   Old: ``      from raw outputs as `evaluate()` does.``

   New:
   ```
         from raw outputs as `evaluate()` does. Categorical probabilities of the
         scored rows must be finite, in [0, 1] and sum to 1 within the input
         dtype's rounding bound; any other row raises `ValueError` before
         anything is accumulated.
   ```
3. In `CHANGELOG.md` `[Unreleased]` → `### Fixed`, replace the bullet below. Find it by its text: it was L32 at `9ad461e`, and #859 added a bullet above it.

   Old: `- Streaming metrics refuse NaN, infinite and out-of-range probability rows.`

   New: `- Streaming metrics refuse NaN, infinite, out-of-range and unnormalized categorical probability rows.`
4. Regenerate the API reference: `uv run python -m scripts.docs.build_api_reference` (`StreamingMetrics` is catalogued at `scripts/docs/api_reference_catalog.txt` L525).

**Worker setup.** No torch needed (docs/config only).
