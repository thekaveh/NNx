## Summary

FIX-116: 582c08a (#849) computes the permission bits of exported files once, at import, with `os.umask(0)` followed by a restore. That briefly sets the process umask to 0 (a race for any thread creating files at that moment) and freezes the mode for the process, so a later, stricter umask is ignored. The atomic writers also chmod every committed file to that mode, so re-exporting over a file the user restricted to 0600 widens it to 0644. This ticket lets the kernel apply the umask in force when each file is created, and keeps an existing destination's mode. It does not change which call sites use the plain mode; that policy is DEC-021. The copy of the import-time mode that #859 added to `_artifacts.py` is FIX-150's.

## Context

**What happens today.** `src/nnx/nn/params/nn_run.py` L279–L287:

```python
def _created_file_mode() -> int:
    """The mode ``open(path, "w")`` creates a file with under the current umask."""
    umask = os.umask(0)
    os.umask(umask)
    return 0o666 & ~umask


# Read once at import: os.umask is process-wide, so it is not re-read per write.
_CREATED_FILE_MODE = _created_file_mode()
```

It is applied in two places:
- `_commit_partial` (L309–L316) always runs `os.chmod(partial, _CREATED_FILE_MODE)` before the rename. Callers: `to_onnx`, `export_state_dict`, `write_gguf`.
- `_atomic_write_text(..., mode=...)` (L210–L276) chmods its `mkstemp` temporary before the rename (L268–L269). Four call sites pass `mode=_CREATED_FILE_MODE`: the Hub manifest (`nn_model._write_hub_manifest`, L1414–L1418), the Hub `config.json` (`NNModel._save_pretrained`, L4777–L4781), the Hub `tokenizer.json` (`GenerativeNNModel._hub_reconstruction_config`, `generative_nn_model.py` L68–L72) and the Ollama `Modelfile` (`interop/ollama.py` L173–L177).

#859 (1402b49, after the review) added a second copy: `_artifacts._created_file_mode` / `_CREATED_FILE_MODE` (`src/nnx/_artifacts.py` L181–L188 at `1402b49`) and an unconditional `os.chmod(tmp, _CREATED_FILE_MODE)` in `_artifacts.atomic_torch_save` (L204), which the PEFT adapter savers, `FeedFwdNN.to_file`, `TransformerNN.to_file` and the FAISS fallback call. FIX-150, which builds on this ticket, moves `atomic_torch_save` onto `_reserve_partial` / `_commit_partial` and deletes that copy, so this ticket does not touch `_artifacts.py`.

Problems:
1. **Thread safety (BUG-12).** Between `os.umask(0)` and the restore, a file or directory another thread creates gets mode 0666/0777. `import nnx` is often done lazily on a worker thread.
2. **Stale umask (BUG-12).** A daemon that tightens its umask to `0o077` after importing NNx still gets 0644 for every export.
3. **Widened mode (BUG-13).** Before #853/#849 these exports wrote the existing file in place (`"wb"`/`"w"`), which keeps its mode. Now a user's 0600 `model.onnx` or `config.json` becomes 0644 on re-export. The Hub save is staged in `.nnx-hub-*` and moved in by `save_pretrained` (L4630–L4633), so an existing Hub file's mode is lost there too.

**Why it matters.** Exported weights and configs can end up readable by other users after a re-export, or under a umask the application set to prevent that. Source: 582c08a (#849), 3ed0133 (#853).

**History.** #260 (FIX-025) pinned the guarantees of `_atomic_write_text` that the new creation path must keep: the temporary file is created beside the destination; any failure before the rename releases the descriptor and unlinks the temp; cleanup never masks the first exception; "Cleanup never unlinks a path that the helper does not own." `tests/test_atomic_write_text.py` enforces them and must pass unchanged.

**Background for the worker.**
- Umask: the process-wide mask the kernel clears from the `mode` passed to `open(O_CREAT)`. `os.open(name, flags, 0o666)` therefore gives exactly what a plain `open(path, "w")` gives, under the umask in force at that call, without reading the umask.
- Plain mode: the permission bits a plain `open(path, "w")` gives (0644 under the common 022 umask). `mkstemp` gives 0600.
- Partial file: `_reserve_partial(path)` creates an empty, uniquely named `.<name>.<random>.partial` beside `path`; `_commit_partial(partial, path)` flushes it (`_fsync_file`, writable since FIX-114) and renames it onto `path`; `_discard_partial` unlinks it.
- `O_EXCL` makes `open` fail with `FileExistsError` if the name exists; `O_NOFOLLOW` (POSIX) refuses a symlink at the name. Together they make the name the caller's own.
- Plan conflict 2: this ticket defines `_create_exclusive(directory, prefix, suffix, mode)` and `_atomic_write_text(..., plain_mode: bool = False)`; it replaces the chmod in `_commit_partial` with "keep the existing destination's mode if `path` exists, else rely on the umask applied at create time"; the set of plain-mode call sites stays the same four.
- FIX-110 (a dependency) rewrote the lines before and after `save_pretrained`'s move loop; this ticket changes only the loop body.

**Proposal.**
1. In `src/nnx/nn/params/nn_run.py`, add `import secrets` and `import stat` to the standard-library imports (alphabetically, between `import os` and `import shutil`, L9–L10).
2. Delete `_created_file_mode` and `_CREATED_FILE_MODE` (L279–L287). Do not keep an alias: the constant's value (an import-time umask) is the bug, and no test references it (`grep -rn "_CREATED_FILE_MODE\|_created_file_mode" tests/` prints nothing).
3. Add, in their place:

   ```python
   def _create_exclusive(directory: str, prefix: str, suffix: str, mode: int) -> tuple[int, str]:
       """Create a new file ``<directory>/<prefix><16 hex digits><suffix>`` and
       return its descriptor (open for writing) and path. The kernel masks
       ``mode`` with the umask in force now, as a plain ``open(path, "w")``
       does, so nothing reads or changes the process umask. ``O_EXCL`` (and
       ``O_NOFOLLOW`` where the platform has it) makes the name this call's
       own: an existing file or symlink of that name is never opened. Raises
       ``FileExistsError`` when 100 names in a row are taken."""
       flags = os.O_WRONLY | os.O_CREAT | os.O_EXCL | getattr(os, "O_BINARY", 0) | getattr(os, "O_NOFOLLOW", 0)
       for _ in range(100):
           name = os.path.join(directory, f"{prefix}{secrets.token_hex(8)}{suffix}")
           try:
               return os.open(name, flags, mode), name
           except FileExistsError:
               continue
       raise FileExistsError(errno.EEXIST, "no unused temporary name", os.path.join(directory, f"{prefix}*{suffix}"))


   def _destination_mode(path: str) -> Optional[int]:
       """The permission bits of the regular file at ``path`` (followed through a
       symlink), or ``None`` when there is none: a writer replacing it gives its
       new file these bits, so a re-export never widens what the user set."""
       try:
           status = os.stat(path)
       except (FileNotFoundError, NotADirectoryError):
           return None
       return stat.S_IMODE(status.st_mode) if stat.S_ISREG(status.st_mode) else None
   ```

     ```python
       directory = os.path.dirname(os.path.abspath(path))
     ```


6. Replace `_commit_partial` (L309–L316) with:

   ```python
   def _commit_partial(partial: str, path: str) -> None:
       """Flush the finished ``partial`` to stable storage and rename it onto
       ``path``. It keeps the mode it was created with (:func:`_reserve_partial`:
       the umask in force at creation), unless ``path`` is an existing file: then
       it takes that file's permission bits, so a re-export never widens them. A
       failure before the rename leaves ``path`` untouched; the caller discards
       ``partial`` (:func:`_discard_partial`)."""
       existing = _destination_mode(path)
       if existing is not None:
           os.chmod(partial, existing)
       _fsync_file(partial)
       os.replace(partial, path)
   ```

   The chmod comes before the flush, so the mode is flushed with the data. FIX-108's `_commit_export_dir` commits every staged ONNX file through `_commit_partial`, so it follows the same rule whichever of the two lands first.
