## Summary

DEC-016: #857 made `BooleanResult` keep a provider's own false probability (`given_p_false`), but the benchmark records only `p_true` and replays `1 - p_true`, and `given_p_false` is left out of equality. The docs are out of date either way. The owner must decide whether benchmark records keep the given value (A) or #857 is reverted and every doc says `p_false = 1 - p_true` (B).

## Context

**What happens today.** `BooleanResult` (`src/nnx/decisions/schema.py` L355–L357) keeps the given value but excludes it from `==` and `hash`:

```python
    # The provider's own p_false when it gave one: kept as given, and checked against p_true within
    # PROBABILITY_TOLERANCE. Left None, p_false is 1 - p_true.
    given_p_false: Optional[float] = field(default=None, compare=False)
```

The benchmark collector stores only `p_true` (`src/nnx/decisions/benchmark.py` `_answer`, L646–L648):

```python
    if isinstance(sample.question, Boolean):
        checked: Any = validate_response(sample.question, getattr(result, "p_true", None), provider=provider_id)
        return {"p_true": float(checked.p_true)}
```

and replay rebuilds the false probability (`_row`, L1081–L1084):

```python
    if isinstance(sample.question, Boolean):
        if record.p_true is None:
            raise BenchmarkError("the record answers a Boolean without p_true")
        return _Row(sample, labels, (record.p_true, 1.0 - record.p_true))
```

The docs disagree with the code and with each other:
- DOC-08: `docs/decisions.md` L84–L85 and the `validate_response` docstring (`schema.py` L445–L446) still give the Boolean form as `{"true": p, "false": 1 - p}`; since #857 any `q` with `|p + q - 1| <= PROBABILITY_TOLERANCE` is accepted and kept.
- DOC-09 (items 1–3): the `BooleanResult` docstring (L348–L349) says only "one ``p_true`` in ``[0, 1]``"; the `p_false` property (L370–L372) has no docstring, so `docs/api.md` L3207 reads "No public description is currently available."
- DOC-10: the CHANGELOG `[Unreleased]` entry (L11, "is stored as given") and `docs/decisions.md` L69–L70 over-claim: benchmark records drop the given value.

**Why it matters.** A feature that stops at the benchmark boundary is half a contract. The numeric effect is bounded by `PROBABILITY_TOLERANCE` (1e-6), so this is a consistency decision, not a correctness emergency.

**History.**
- #219 (FEAT-009) set the Boolean contract: "Boolean holds one `p_true` in `[0,1]`." Option B restores it.
- #243 (FEAT-021) defined the record format `nnx.decision-record/1`: "Records keep the provider/model revision, prompt identity and execution metadata across a JSON Lines (JSONL) round trip." `Record.from_state` refuses unknown keys, in 0.5.0 too (`benchmark.py` L530–L534 at `v0.5.0`). So option A writes `p_false` only when it is set: a record without one reads in 0.5.0; a record with one does not.
- #857 (ed6c9dd) is unreleased (it is not an ancestor of `v0.5.0`), so option B's revert needs no CHANGELOG entry of its own.

**Background for the worker.**
- `Boolean`: a yes/no decision question. `BooleanResult`: its validated answer (`question_digest`, `p_true`, `provider`, `raw`, `given_p_false`).
- `validate_response(question, response)`: the one validator every provider uses; for a Boolean, `response` is a number (`p_true`) or a mapping `{"true": p, "false": q}`.
- `PROBABILITY_TOLERANCE = 1e-6` (`schema.py` L33): how far a distribution's sum may be from 1; never renormalized.
- `Record`: one provider output for one sample in the benchmark (`benchmark.py` L430–L547); `state()` / `Record.from_state` are its JSON form; `write_records` / `read_records` write and read JSONL.
- `_answer`: turns a provider result into the answer fields of a `Record`; `collect` passes them as keyword arguments to `Record(...)` (`_records`, L657–L676).
- `_row`: turns a `Record` into the probability row that `evaluate` scores.
- `docs/api.md` is generated from docstrings: regenerate with `uv run python -m scripts.docs.build_api_reference`, never edit it by hand.

## Options

| Option | What changes | Trade-off |
|---|---|---|
| A (recommended) | `Record` gains `p_false` (written only when set); `collect` stores the given value and `evaluate` replays it; `given_p_false` joins equality; the docs describe both values. | Keeps #857's promise end to end. A record holding `p_false` cannot be read by NNx 0.5.0, which refuses unknown keys; records without one are unchanged. |
| B | Revert #857 (`git revert ed6c9dd`); every doc says `p_false` is `1 - p_true`. | Restores #219's one-`p_true` contract and leaves the record format untouched. A provider's own `q` is checked, then dropped. |

A is recommended because #857 is a deliberate, documented owner change, and the only boundary that drops the value is the benchmark; the 0.5.0 incompatibility is limited to records that actually carry a given `q`.
