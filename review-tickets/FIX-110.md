## Summary

FIX-110: When a `save_pretrained` produces no `tokenizer.json` but the previous save did, NNx deletes the old one before any staged file moves in. A failure on the first move then leaves an artifact whose manifest lists a tokenizer that is gone, which `from_pretrained` refuses. The deletion also checks only that the old manifest lists the file, not that the file is still the one NNx wrote, so a tokenizer the user replaced after an NNx save is deleted too. This ticket removes the stale tokenizer after the new manifest is in place, and only when the file still has the digest the previous manifest lists.

## Context

**What happens today.** `NNModel.save_pretrained` (`src/nnx/nn/nn_model.py` L4592–L4636) deletes first and moves after (L4624–L4633):

```python
            previous = _previous_hub_files(target)
            if previous is not None and _HUB_TOKENIZER_FILENAME in previous and _HUB_TOKENIZER_FILENAME not in produced:
                with contextlib.suppress(FileNotFoundError):
                    os.remove(target / _HUB_TOKENIZER_FILENAME)
            # config.json, then the manifest, move last: an interrupted move leaves the previous manifest beside files
            # it no longer matches, which a load refuses rather than reading a mix of two saves.
            for name in sorted(produced, key=lambda produced_name: _HUB_MOVE_ORDER.get(produced_name, 0)):
                if name == "README.md" and (target / name).exists():
                    continue  # huggingface_hub does not overwrite an existing model card
                os.replace(os.path.join(staging, name), target / name)
```

1. **Too early.** A failure or interrupt between the `os.remove` and the first `os.replace`, or on the first `os.replace`, leaves a directory that is the previous save in every file except that `tokenizer.json` is gone. Its manifest still lists the tokenizer, so `from_pretrained` raises "tokenizer.json is listed in nnx_hub_manifest.json but is missing; refusing to load it" (`_verify_hub_manifest`, L1440–L1445). A plausible trigger: on Windows, `os.replace` raises `PermissionError` while `model.safetensors` is still memory-mapped by an earlier load.
2. **Wrong file.** The test is "the previous manifest lists `tokenizer.json`", not "the file still has the listed digest". A user who overwrote `tokenizer.json` after an NNx save loses it on the next save without a tokenizer.

**Why it matters.** Both contradict the unreleased CHANGELOG: L12 ("A refused or failed `save_pretrained` leaves the previous artifact intact") and L26 ("a user-written one is left alone"). Source: ed93d51 (#855).

**History.** #260 (FIX-025) set the principle for NNx's writers: "Cleanup never unlinks a path that the helper does not own." A tokenizer whose content no longer matches the manifest is not NNx's.

**Background for the worker.**
- Hub artifact: the directory `save_pretrained` writes: `model.safetensors`, `config.json`, `nnx_hub_manifest.json`, `README.md`, and `tokenizer.json` for a `GenerativeNNModel`.
- Hub manifest (`nnx_hub_manifest.json`): lists each NNx-written file with its SHA-256 and byte size; `from_pretrained` verifies every listed file before building anything.
- `_previous_hub_files(target)` (L1394–L1401): `{name: (sha256, size)}` from the target's current manifest, or `None` when there is no readable manifest.
- `_file_digest(path)` (L1359–L1367): `(sha256_hex, size)` of a file, the same tuple the manifest entries hold.
- Staging: the save is written into `.nnx-hub-*` beside the target and moved in file by file; `config.json` and then the manifest move last (`_HUB_MOVE_ORDER`, L193).

**Proposal.**
1. In `src/nnx/nn/nn_model.py`, add after `_previous_hub_files` (after L1401):

   ```python
   def _remove_if_unchanged(path: Path, listed: tuple[str, int]) -> None:
       """Remove the file at ``path`` if it is still the one a previous NNx save
       wrote: a regular file, not a symlink, with the SHA-256 and size ``listed``
       (the previous manifest's entry). A file the user wrote or changed after
       that save stays. Best effort: the new save no longer lists the file, so it
       is complete without the removal."""
       with contextlib.suppress(OSError):
           if path.is_file() and not path.is_symlink() and _file_digest(str(path)) == listed:
               os.remove(path)
   ```

2. In `save_pretrained`, replace L4622–L4627:

   Old:
   ```python
               # A tokenizer.json an earlier NNx save wrote (the manifest there lists it) goes when this save writes none.
               # One the manifest does not list is the user's, and stays.
               previous = _previous_hub_files(target)
               if previous is not None and _HUB_TOKENIZER_FILENAME in previous and _HUB_TOKENIZER_FILENAME not in produced:
                   with contextlib.suppress(FileNotFoundError):
                       os.remove(target / _HUB_TOKENIZER_FILENAME)
   ```
   New:
   ```python
               # A tokenizer.json an earlier NNx save wrote goes when this save writes none, but only once the new manifest
               # is in place (removed earlier, a failed move would leave the previous artifact without a file its manifest
               # lists), and only if it still has the digest that manifest lists: otherwise it is the user's, and stays.
               previous = _previous_hub_files(target)
               stale_tokenizer = (
                   previous.get(_HUB_TOKENIZER_FILENAME)
                   if previous is not None and _HUB_TOKENIZER_FILENAME not in produced
                   else None
               )
   ```

3. After the move loop (after L4633) and before `return result` (L4634), add:

   ```python
               if stale_tokenizer is not None:
                   _remove_if_unchanged(target / _HUB_TOKENIZER_FILENAME, stale_tokenizer)
   ```

4. No message changes. `docs/hub.md` §2.2 (L161) is rewritten by FIX-111, which describes this ordering; do not edit it here.
5. CHANGELOG: in `## [Unreleased]` → `### Fixed`, replace L26:

   Old:
   ```
   - A stale `tokenizer.json` written by an earlier NNx save is removed when a save produces none; a user-written one is left alone.
   ```
   New:
   ```
   - **A stale `tokenizer.json` is removed only after the new Hub save is in place, and only if NNx wrote it.** A `save_pretrained` that produces no tokenizer removes the previous one once the new manifest has moved in, and only when the file still has the digest the previous manifest lists: a save that fails while moving files keeps it, and a tokenizer the user wrote or overwrote after that save stays.
   ```

6. Tests in `tests/test_hub_manifest.py`. It imports `os`, `pytest`, `torch`, `NNModel`, `_tiny_model` and `_resign` (L5–L13) and defines `_lm_with_tokenizer(tmp_path)` (L18–L45, a `GenerativeNNModel` with a trained BPE tokenizer; it skips without `tokenizers`) and `_listed(directory)` (L48–L49). Add after `test_resaving_without_a_tokenizer_leaves_a_user_written_tokenizer_alone` (L142–L147):

   ```python
   def test_a_failed_move_keeps_the_previous_tokenizer(tmp_path, monkeypatch):
       """The stale tokenizer was removed before any staged file moved, so a failed move left an artifact whose
       manifest lists a tokenizer that is gone: from_pretrained refused it."""
       from nnx import GenerativeNNModel

       out = tmp_path / "hub"
       _lm_with_tokenizer(tmp_path).save_pretrained(str(out))
       real_replace = os.replace

       def busy_move(src, dst, *args, **kwargs):
           if ".nnx-hub-" in os.fspath(src) and ".nnx-hub-" not in os.fspath(dst):  # a staged file moving in
               raise OSError("busy")
           return real_replace(src, dst, *args, **kwargs)

       with monkeypatch.context() as patch:
           patch.setattr(os, "replace", busy_move)
           with pytest.raises(OSError, match="busy"):
               _tiny_model().save_pretrained(str(out))
       assert (out / "tokenizer.json").exists()
       assert isinstance(GenerativeNNModel.from_pretrained(str(out)), GenerativeNNModel)


   def test_a_user_overwritten_tokenizer_is_kept(tmp_path):
       """The previous manifest lists the tokenizer NNx wrote; a file with another digest is the user's."""
       out = tmp_path / "hub"
       _lm_with_tokenizer(tmp_path).save_pretrained(str(out))
       (out / "tokenizer.json").write_text('{"user": true}', encoding="utf-8")
       _tiny_model().save_pretrained(str(out))
       assert (out / "tokenizer.json").read_text(encoding="utf-8") == '{"user": true}'
       assert set(_listed(out)) == {"model.safetensors", "config.json"}
   ```

   The staged writes inside `.nnx-hub-*` (the weights partial, `_atomic_write_text`'s temporaries) rename within the staging directory, so `busy_move` lets them through and fails only the moves into `out`. `test_resaving_without_a_tokenizer_removes_the_tokenizer_nnx_wrote` (L133–L139), `test_resaving_without_a_tokenizer_leaves_a_user_written_tokenizer_alone` (L142–L147) and `test_a_directory_without_a_manifest_keeps_its_tokenizer` (L150–L156) stay unchanged and must pass.

## Scope

**In:** `_remove_if_unchanged`, the order and condition of the stale-tokenizer removal in `save_pretrained`, the CHANGELOG bullet, two tests.

**Out:**
- Documenting what a save interrupted mid-move leaves, in the CHANGELOG, the docstring and `docs/hub.md` (FIX-111).
- Making the move reversible with backups (BUG-09 option b; not the project's stance, see FIX-111).
- Naming the tokenizer file once (FEAT-102), computing the state dict once per save (FEAT-101), moving the Hub helpers (FEAT-076).
