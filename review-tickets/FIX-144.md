## Summary

FIX-144: `examples/run_bundle.py` calls `fit_temperature` without `test_split_id`, so it emits NNx's new `DeprecationWarning` today and will fail once the argument is required. The example smoke tests never turn that warning into an error, which is how it slipped through. This ticket passes the split ids in the example and makes both smoke tests fail on that deprecation.

## Context

**What happens today.** `built_in_classifier` (`examples/run_bundle.py` L130–L136):

```python
    fit = fit_temperature(
        first.predict(X_CAL).logits,
        Y_CAL.numpy(),
        labels=LABELS,
        model_id=model_fingerprint(first),
        split_id="calibration",
    )
```

It is the only call in `examples/`, `src/` and the docs that omits `test_split_id`; `examples/calibration_offline.py` L59–L67 passes `train_split_id="train", test_split_id="test"`. `warn_omitted_test_split` (`src/nnx/_validation.py` L253–L262) warns with `stacklevel=3`, so the warning is attributed to the example's own module: `__main__` in the subprocess of `test_representative_examples_run_end_to_end` (L144), `__nnx_example_smoke__` under `runpy` in `test_bounded_example_helpers_execute` (L238). Neither test makes it an error, and `pyproject.toml`'s `filterwarnings` has no such entry.

**Why it matters.** The example is the documented way to bundle a calibrated classifier; it will break in the next minor release, and nothing would have told us.

**History.** #571 fixed tests that "pass or skip, and the suite exits 0, when the behavior they guard breaks"; this is the same class. #217 introduced the calibration artifacts and their split separation.

**Background for the worker.**
- `test_split_id`: the id of the held-out test split; omitting it is deprecated and becomes required in the next minor release (CHANGELOG `[Unreleased]` L18).
- `PYTHONWARNINGS`: an environment variable of warning filters, `action:message:category:module`, comma-separated. In it, `message` is a literal prefix of the warning text (case-insensitive) and `module` is an exact module name.
- `pytest.mark.filterwarnings("action:message:category:module")`: the same filter for one test; here `message` and `module` are regular expressions matched at the start.
- Filters are narrowed to this deprecation's message so an unrelated third-party `DeprecationWarning` raised from example code does not fail the run.

**Proposal.**
1. `examples/run_bundle.py`, after L135 (`        split_id="calibration",`), add:

   ```python
           train_split_id="train",
           test_split_id="test",
   ```
2. `tests/test_examples_smoke.py`, `test_representative_examples_run_end_to_end`, after L146 (`    env["NNX_TQDM_DISABLE"] = "1"`), add:

   ```python
       # An example must not call a deprecated NNx API: the deprecation is attributed to the example (__main__).
       env["PYTHONWARNINGS"] = (
           "error:fit_temperature() without test_split_id:DeprecationWarning:__main__,"
           "error:select_threshold() without test_split_id:DeprecationWarning:__main__"
       )
   ```
3. Same file, decorate `test_bounded_example_helpers_execute` (L237–L238) so the marks read, in this order:

   ```python
   @pytest.mark.parametrize(("name", "helper"), BOUNDED_EXAMPLE_HELPERS, ids=lambda value: value)
   @pytest.mark.filterwarnings("error:.*without test_split_id is deprecated:DeprecationWarning:__nnx_example_smoke__")
   def test_bounded_example_helpers_execute(name, helper, tmp_path, monkeypatch):
   ```
4. No CHANGELOG entry: the example and tests are not part of the package.

**Worker setup.** Branch from `develop`. `uv sync --frozen --all-extras` installs torch and every extra the tests need.
