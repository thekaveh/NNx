## Summary

FIX-131: Since 3ed0133 (#853), every DPO step refuses a batch holding a chosen or rejected response with no valid token (empty, or every position `pad_token_id`), and, with `prompt_packing=True`, a prompt with no valid token. Training then fails mid-epoch with a `ValueError`. The CHANGELOG, `docs/dpo.md` and the `dpo_train_step_factory` docstring say nothing about it, and `docs/dpo.md` even says the default "keeps results unchanged". This ticket documents the refusal in all three places.

## Context

**What happens today.** The step calls the refusals before any forward (`src/nnx/paradigms/dpo.py` L151–L154):

```python
        _require_response_tokens(chosen_ids, pad_token_id, "chosen")
        _require_response_tokens(rejected_ids, pad_token_id, "rejected")
        if prompt_packing:
            _require_prompt_tokens(prompt_ids, pad_token_id)
```

`_require_response_tokens` (L252–L268) raises `ValueError("DPO {name} response of batch row {row} has no valid tokens ({reason}): its log-prob would be 0 with no gradient yet still count as a preference pair. Drop that row from the dataset.")`. `NNPreferenceDataset` still right-pads an empty response to all-pad without refusing it (`_pad_or_truncate`, `nn_preference_dataset.py` L76–L81), so the dataset accepts rows that training rejects at the step whose batch holds them. `grep -n "no valid token" CHANGELOG.md docs/dpo.md` finds nothing.

**Why it matters.** It is a breaking runtime refusal that can stop a long run mid-epoch, and the only user-facing text about this path claims nothing changed.

**History.** No board issue covers it; the refusal came with 3ed0133 (#853) after 0.5.0. `tests/test_paradigms_dpo.py` L689–L720 pins the behaviour.

**Background for the worker.**
- DPO (direct preference optimization): a training paradigm that scores a chosen and a rejected response per prompt; `dpo_train_step_factory` builds its train step.
- Valid token: a response position whose id is not `pad_token_id`. A response's log-prob is the sum over its valid tokens, so a response with none scores exactly 0 with no gradient.
- `prompt_packing=True`: an opt-in mode that places each response directly after its prompt's valid tokens.
- `docs/api.md` is generated from docstrings: regenerate it, never edit it by hand.

**Proposal.**
1. Add to `CHANGELOG.md` under `## [Unreleased]` → `### Changed` (after the `test_split_id` / calibration bullets, L18–L19):

   ```
   - **DPO refuses a response with no valid tokens.** `dpo_train_step_factory` raises `ValueError` at the step whose batch holds a chosen or rejected response that is empty or every position `pad_token_id` (its log-prob would be 0 with no gradient yet still count as a pair). Drop such rows before building `NNPreferenceDataset`. With `prompt_packing=True` a prompt with no valid token is refused the same way.
   ```
2. In `docs/dpo.md` §1, insert after L31 (`freeze the policy.`) one blank line and this paragraph:

   ```
   A chosen or rejected response with no valid token (empty, or every
   position `pad_token_id`) is refused: the step raises `ValueError` at
   the first batch that holds one, before any forward, because its
   log-prob would be 0 with no gradient yet still count as a preference
   pair. `NNPreferenceDataset` pads an empty response to all-pad without
   refusing it, so drop such rows before building the dataset. With
   `prompt_packing=True`, a prompt with no valid token is refused the
   same way.
   ```
3. In `docs/dpo.md` §3, replace L123:

   Old: `# prompt_packing=True (opt-in; the default keeps results unchanged) also`

   New: `# prompt_packing=True (opt-in; the default keeps the padded-prompt scoring) also`
4. In `src/nnx/paradigms/dpo.py`, `dpo_train_step_factory` docstring, insert after L116 (`            (freezing it would freeze the policy).`), inside the `ValueError` item:

   ```
               At every step, before any forward: a chosen or rejected
               response with no valid token (empty, or all ``pad_token_id``)
               and, with ``prompt_packing=True``, a prompt with no valid
               token. Drop such rows from the dataset.
   ```
5. Regenerate the API reference: `uv run python -m scripts.docs.build_api_reference` (catalogued at `scripts/docs/api_reference_catalog.txt` L1035).

**Worker setup.** No torch needed (docs/config only).
