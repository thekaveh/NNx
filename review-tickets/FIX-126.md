## Summary

FIX-126: `export_conformance._weights_digest` calls `tensor.numpy()` on every state tensor, which raises `TypeError` for `torch.bfloat16` because NumPy has no bfloat16. Today's profiles are FP32 only, so this is latent. This ticket hashes a bfloat16 tensor's bytes through an `int16` view under the name `bfloat16`, and leaves the digest of every other dtype byte-identical, so recorded FP32 evidence still replays.

## Context

**What happens today.** `_weights_digest` (`src/nnx/export_conformance.py` L438–L444):

```python
def _weights_digest(module: torch.nn.Module) -> str:
    digest = hashlib.sha256()
    for name, tensor in module.state_dict().items():
        array = tensor.detach().cpu().contiguous().numpy()
        digest.update(f"{name}|{array.dtype}|{list(array.shape)}|".encode())
        digest.update(array.tobytes())
    return digest.hexdigest()
```

`run_profile` writes it into each record as `config.weights_sha256` (L925), and `execute` (which replays a stored record) refuses a record whose rebuilt weights hash differently (L1007).

**Why it matters.** A bfloat16 profile, or a caller digesting a bf16 net, crashes with a bare `TypeError: Got unsupported ScalarType BFloat16`. `benchmarking._feed_digest` already handles bfloat16 with a byte view, but its digest format differs (dtype and shape `repr`, no `name|` separators), so routing through it would change every FP32 digest and break replay of the records CI has already uploaded.

**History.** #255 (target-runtime export conformance profiles) scoped the profiles to "the FP32 (32-bit floating point) feed-forward model under both exporters" and listed "Claims beyond the FP32 feed-forward profiles" as Out. This ticket does not add a bf16 profile; it only removes the crash in the digest helper and keeps the FP32 format.

**Background for the worker.**
- Export-conformance record: the JSON evidence `run_profile` writes; `config.weights_sha256` pins the exact weights the profile built.
- Replay: `execute(record, directory)` rebuilds the model from a stored record and compares `_weights_digest` with `weights_sha256`; any change to the FP32 digest bytes would make every stored record fail replay.
- bfloat16 has the same element size as int16, so `tensor.view(torch.int16)` reinterprets the same bytes without copying or rounding.

**Proposal.**
1. In `src/nnx/export_conformance.py`, replace `_weights_digest` (L438–L444) with:

   ```python
   def _weights_digest(module: torch.nn.Module) -> str:
       """SHA-256 of ``module``'s state: per tensor ``name|dtype|shape|`` then its
       bytes. The FP32 form is what recorded evidence pins, so it never changes;
       NumPy has no bfloat16, so a bfloat16 tensor's bytes are read through an
       int16 view and hashed under the name ``bfloat16``."""
       digest = hashlib.sha256()
       for name, tensor in module.state_dict().items():
           flat = tensor.detach().cpu().contiguous()
           if flat.dtype == torch.bfloat16:
               array, dtype_name = flat.view(torch.int16).numpy(), "bfloat16"
           else:
               array = flat.numpy()
               dtype_name = str(array.dtype)
           digest.update(f"{name}|{dtype_name}|{list(array.shape)}|".encode())
           digest.update(array.tobytes())
       return digest.hexdigest()
   ```

   For every non-bf16 tensor, `str(array.dtype)` is exactly what `f"{array.dtype}"` produced, so the bytes fed to SHA-256 are unchanged.
2. Add to `CHANGELOG.md` under `## [Unreleased]` → `### Fixed`:

   ```
   - **Export-conformance weight digests accept bfloat16 weights.** `_weights_digest` raised NumPy's `TypeError` on a bfloat16 tensor; it now hashes such a tensor's bytes under the dtype name `bfloat16`. Digests of every other dtype are byte-identical, so recorded FP32 evidence still replays.
   ```
3. In `tests/test_export_conformance.py`, add `import hashlib` after `from __future__ import annotations` (with the other standard-library imports), and add these tests after `test_both_exporters_match_native_logits_in_onnx_runtime`:

   ```python
   def test_the_weights_digest_of_fp32_weights_keeps_its_format():
       torch.manual_seed(0)
       net = torch.nn.Linear(3, 2)
       expected = hashlib.sha256()
       for name, tensor in net.state_dict().items():
           array = tensor.detach().numpy()
           expected.update(f"{name}|{array.dtype}|{list(array.shape)}|".encode())
           expected.update(array.tobytes())
       assert conformance._weights_digest(net) == expected.hexdigest()


   def test_the_weights_digest_hashes_bfloat16_weights():
       torch.manual_seed(0)
       net = torch.nn.Linear(3, 2).to(torch.bfloat16)
       expected = hashlib.sha256()
       for name, tensor in net.state_dict().items():
           expected.update(f"{name}|bfloat16|{list(tensor.shape)}|".encode())
           expected.update(tensor.detach().contiguous().view(torch.int16).numpy().tobytes())
       assert conformance._weights_digest(net) == expected.hexdigest()
       assert conformance._weights_digest(torch.nn.Linear(3, 2).to(torch.bfloat16)) != expected.hexdigest()
   ```

   Neither test needs ONNX Runtime.

**Worker setup.** Branch from `develop`. `uv sync --frozen --all-extras` installs torch and every extra the tests need.
