## Summary

FIX-108: `to_onnx` exports into a hidden partial file (`.model.onnx.<random>.partial`) and renames only that file onto `path`. The dynamo exporter names its external data after the file it is given, so the committed `model.onnx` references `.model.onnx.<random>.partial.data`, a hidden, random name that every re-export leaks and a failed export leaves behind. This ticket stages the export in a hidden directory under the final file name, moves the data files in first and the `.onnx` last, and documents the atomic write, the warning and the two refusals in the `to_onnx` docstring.

## Context

**What happens today.** `to_onnx` (`src/nnx/nn/nn_model.py` L4221) reserves a sibling file and passes it to all three `torch.onnx.export` calls (L4344, L4361–L4370):

```python
        partial = _reserve_partial(path)
        training_modes = _capture_training_modes(self.net)
        self.net.eval()
```

```python
                    torch.onnx.export(
                        self.net,
                        example_input,
                        partial,
                        input_names=in_names,
                        output_names=out_names,
                        dynamic_shapes=dynamic_shapes,
                        opset_version=opset_version,
                        dynamo=True,
                    )
```

On success `_commit_partial(partial, path)` renames that one file; on failure `_discard_partial(partial)` unlinks that one file (`src/nnx/nn/params/nn_run.py` L309–L322). With `dynamo=True`, torch saves external data as `f"{given_file_name}.data"`; onnxscript's `save_model_with_external_data` and onnx_ir externalise every tensor of 256 bytes or more, and torch 2.6 and later default to `external_data=True` (read from torch source, not run here). So almost every real dynamo export writes `.model.onnx.<random>.partial.data`, which:
- the committed `model.onnx` references, so copying `model.onnx` with a conventional `model.onnx.data` does not load;
- every re-export leaks again (possibly several GB each);
- a failed export leaves behind, because `_discard_partial` removes only the `.onnx` partial.

The legacy exporter on a model over 2 GB writes one external file per tensor into the target's directory, and a failure leaves those too. The existing tests miss it: `tests/test_onnx_dynamo.py` (L38–L52) uses a 4→8→2 net whose tensors are all under 256 bytes.

**Why it matters.** The artifact references a file name nobody expects, and disks fill with orphaned weights. It also breaks retained CI evidence: the `export-conformance` job uploads `conformance/` with `actions/upload-artifact` (`.github/workflows/ci.yml` L238–L247), which skips hidden files unless `include-hidden-files: true` is set, so the hidden `.partial.data` that `export_conformance._manifest` hashes for the dynamo profile is left out of the upload. Source: 3ed0133 (#853, "ONNX export is atomic").

**History.**
- #255 (FEAT-038) requires: "CI retains `conformance.json` with its ONNX and external-data files." The hidden name breaks that silently; a visible `model.onnx.data` restores it with no workflow change.
- #570 made `to_onnx(dynamo=False)` raise an `ImportError` naming the extra; its Raises entry stays and is joined by the two refusals below.

**Background for the worker.**
- External data: ONNX tensors stored in a separate file beside the `.onnx`, referenced by a relative `location` in each tensor's `external_data` entries.
- Partial file: a hidden, uniquely named file beside the target that a writer fills and then renames onto the target (`_reserve_partial` / `_commit_partial` / `_discard_partial`, `nn_run.py` L290–L322). `_commit_partial` flushes the file (`_fsync_file`), sets its mode and renames it; this ticket reuses it for every staged file, so later changes to `_commit_partial` (FIX-114's flush, FIX-116's mode rule) apply to the ONNX files too.
- Staging directory: a new hidden directory beside the target, created by `tempfile.mkdtemp` on the same filesystem, so each later `os.replace` is an atomic rename.
- FIX-107 (this ticket's dependency) replaced the dropped-state check with `_unread_state_keys(net, example_input)`, which takes no file path, and moved the warning after the commit. This ticket leaves that call and the warning exactly as FIX-107 wrote them; it changes only where torch writes.

**Proposal.**
1. In `src/nnx/nn/params/nn_run.py`, add three helpers after `_discard_partial` (L319–L322). `errno`, `os`, `shutil` and `tempfile` are already imported.

   ```python
   def _reserve_export_dir(path: str) -> tuple[str, str]:
       """A new, empty hidden directory beside ``path`` (``.<name>.<random>.partial``,
       on the same filesystem, so each later rename is atomic) and the path a
       writer fills inside it, ``<staging>/<name>``: a writer that names side
       files after its target (an ONNX exporter's ``<name>.data``) then names
       them after the final file. :func:`_commit_export_dir` moves the result
       into place; :func:`_discard_export_dir` removes it."""
       directory = os.path.dirname(os.path.abspath(path))
       name = os.path.basename(path)
       staging = tempfile.mkdtemp(prefix=f".{name}.", suffix=".partial", dir=directory)
       return staging, os.path.join(staging, name)


   def _commit_export_dir(staging: str, path: str) -> None:
       """Move what a writer left in ``staging`` beside ``path``: every side file
       first, under the name the writer gave it, then the file at ``path``
       itself, last, each flushed and renamed by :func:`_commit_partial`, so a
       reader never finds the new file before the data it references. The moves
       are not one atomic step: a failure between two renames leaves the side
       files that already moved. Removes the emptied ``staging``."""
       name = os.path.basename(path)
       directory = os.path.dirname(os.path.abspath(path))
       entries = sorted(os.listdir(staging))
       if name not in entries:
           raise FileNotFoundError(errno.ENOENT, "the writer left no file to commit", os.path.join(staging, name))
       for entry in entries:
           if entry != name:
               _commit_partial(os.path.join(staging, entry), os.path.join(directory, entry))
       _commit_partial(os.path.join(staging, name), path)
       os.rmdir(staging)


   def _discard_export_dir(staging: str) -> None:
       """Remove a staging directory a failed write left behind, with whatever it holds."""
       shutil.rmtree(staging, ignore_errors=True)
   ```

     ```python
     def test_dynamo_external_data_is_named_after_the_target(tmp_path, skip_on_dynamo_dispatch_error):
         """torch names external data after the file it writes. The export used to write into a hidden partial
         file, so model.onnx referenced `.model.onnx.<random>.partial.data` and every export leaked one."""
         onnx = pytest.importorskip("onnx")
         pytest.importorskip("onnxscript")
         model = NNModel(
             net_params=NNParams(input_dim=4, output_dim=2, hidden_dims=[64], dropout_prob=0.0, activation=Activations.RELU),
             params=NNModelParams(net=Nets.FEED_FWD, device=Devices.CPU, loss=Losses.CROSS_ENTROPY),
         )
         path = tmp_path / "model.onnx"
         try:
             for _ in range(2):  # a re-export leaks nothing either
                 model.to_onnx(str(path), example_input=torch.randn(2, 4), dynamo=True)
         except Exception as error:
             skip_on_dynamo_dispatch_error(error)
             raise
         assert sorted(os.listdir(tmp_path)) == ["model.onnx", "model.onnx.data"]
         graph = onnx.load(str(path), load_external_data=False).graph
         locations = {
             entry.value
             for init in graph.initializer
             if init.data_location == onnx.TensorProto.EXTERNAL
             for entry in init.external_data
             if entry.key == "location"
         }
         assert locations == {"model.onnx.data"}
         onnx.checker.check_model(str(path))
     ```

     `hidden_dims=[64]` makes `layers.0.weight` 64×4 float32 = 1024 bytes, over the 256-byte external-data threshold.
   - `tests/test_to_onnx_inputs.py`: add `import types` to the imports (after `import sys`, L19) and these two tests after `test_a_failed_export_leaves_the_previous_onnx_file_intact` (L207–L225). Both use the module's `_model()` (L35–L49) and need neither `onnx` nor `onnxscript`: the fake exporter takes `dynamo` as a parameter, so `to_onnx` takes its `dynamo=True` branch, and a stub `onnxscript` module passes its import guard.

     ```python
     def _fake_dynamo_export(fail: bool):
         def export(net, args, f, *, dynamo=False, **kwargs):
             with open(f, "wb") as handle:
                 handle.write(b"graph")
             with open(f"{f}.data", "wb") as handle:  # torch names external data after the file it writes
                 handle.write(b"weights")
             if fail:
                 raise RuntimeError("export failed")

         return export


     def test_external_data_moves_beside_the_target_under_the_exporters_name(tmp_path, monkeypatch):
         monkeypatch.setitem(sys.modules, "onnxscript", types.ModuleType("onnxscript"))
         monkeypatch.setattr(torch.onnx, "export", _fake_dynamo_export(fail=False))
         path = tmp_path / "model.onnx"
         out = _model().to_onnx(str(path), example_input=torch.randn(2, 4), dynamic_batch=False, dynamo=True)
         assert out == str(path)
         assert sorted(os.listdir(tmp_path)) == ["model.onnx", "model.onnx.data"]
         assert (tmp_path / "model.onnx.data").read_bytes() == b"weights"


     def test_a_failed_export_leaves_no_external_data_behind(tmp_path, monkeypatch):
         path = tmp_path / "model.onnx"
         path.write_bytes(b"previous export")
         monkeypatch.setitem(sys.modules, "onnxscript", types.ModuleType("onnxscript"))
         monkeypatch.setattr(torch.onnx, "export", _fake_dynamo_export(fail=True))
         with pytest.raises(RuntimeError, match="export failed"):
             _model().to_onnx(str(path), example_input=torch.randn(2, 4), dynamic_batch=False, dynamo=True)
         assert path.read_bytes() == b"previous export"
         assert sorted(os.listdir(tmp_path)) == ["model.onnx"]
     ```
