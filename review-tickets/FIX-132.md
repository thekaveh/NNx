## Summary

FIX-132: Since 3ed0133 (#853), `write_gguf` and `export_ollama_modelfile` refuse a network whose `state_dict` holds an entry that no GGUF tensor carries (an auxiliary head, a `logit_scale`, a bias). The `write_gguf` docstring and the CHANGELOG say so; `docs/gguf.md` §3 lists the other refusals but not this one. This ticket adds it to that sentence.

## Context

**What happens today.** `docs/gguf.md` L90–L94:

```
`write_gguf` and `export_ollama_modelfile` refuse such a hook on any module,
and a tied head that no longer reads the embedding's weight, with a
`TypeError` that names the affected tensors and the fix.
They also refuse PEFT adapters and factorized projections. A refused export
writes no `.gguf`, `model.gguf` or Modelfile.
```

The tensor map refuses unread state (`src/nnx/interop/gguf/tensor_name_map.py` L290–L298):

```python
    unread = _unread_state_keys(net, read)
    if unread:
        raise TypeError(
            f"GGUF export has no tensor slot for {', '.join(unread)}, so the file would silently drop "
```

**Why it matters.** The refusal bites a model with an attached `logit_scale`, which `docs/hub.md` (L192) describes, and the guide a user reads before exporting does not mention it.

**History.** #525 (FIX-058) wrote the paragraph above for the prune-mask and legacy-norm refusals; this ticket extends the same paragraph. CHANGELOG `[Unreleased]` L14 already reads "**GGUF export refuses state it would drop.**".

**Background for the worker.**
- GGUF: the llama.cpp model file format; `nnx.interop.gguf.write_gguf` writes it and `export_ollama_modelfile` wraps it in an Ollama bundle.
- Unread state: a `state_dict` entry that the GGUF tensor map does not copy into any GGUF tensor; exporting it would drop it silently, so NNx refuses.

**Proposal.**
1. In `docs/gguf.md` §3, replace L93:

   Old: ``They also refuse PEFT adapters and factorized projections. A refused export``

   New (three lines, replacing that one line; L94 `writes no …` stays):
   ```
   They also refuse PEFT adapters, factorized projections and any `state_dict`
   entry no GGUF tensor carries (an auxiliary head, a `logit_scale`, a bias); the
   `TypeError` names every such key. Remove it from the network, or export a copy
   that holds only the `TransformerNN`'s own weights. A refused export
   ```

**Worker setup.** No torch needed (docs/config only).
