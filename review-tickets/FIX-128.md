## Summary

FIX-128: Six optional-import guards (`quantize_int8`, the QAT quantizer, `semi_structured_24`, the GGUF writer, the Jev adapter and `nnx.search`) catch every `ImportError` and say "install the extra", even when the package is installed and one of its own imports failed. This ticket (part 2 of 3) replaces each with `nnx._optional.require`, which FIX-127 taught about these packages. Every hint fragment a test asserts is kept; three tests change only how they simulate a missing package.

## Context

**What happens today.** For example `quantize_int8` (`src/nnx/quantize/ptq.py` L90–L96):

```python
    try:
        from torchao.quantization import Int8WeightOnlyConfig, quantize_
    except ImportError as e:  # pragma: no cover — opt-in extra
        raise ImportError(
            "quantize_int8 requires torchao. Install with `pip install thekaveh-nnx[quantize]` "
            "(or `pip install 'torchao>=0.17'` directly)."
        ) from e
```

The same shape is in `qat._build_quantizer` (L93–L99), `semi_structured_24` (L78–L84), `gguf.writer._require_gguf` (L83–L91), `jev._sdk` (L107–L111, with its own `_INSTALL_HINT` at L102) and `search._optuna` (L104–L111). Each hint is worded differently.

**Why it matters.** A user with a broken torchao (or gguf, optuna, SDK) install is told to install what they already have, and the real cause is hidden behind the hint.

**History.** #249 introduced `require` with the rule "An `ImportError` raised inside an installed dependency keeps its original cause"; these six guards predate or bypassed it. The hint wording is pinned by #234 ("leads with `pip install "thekaveh-nnx[embeddings]"` — wording a new optional backend must match") and #220 ("the adapter raises `ImportError` naming `thekaveh-nnx[jev]`"). `require`'s message, `<feature> needs <package>: pip install "thekaveh-nnx[<extra>]" (or pip install <requirement>)`, satisfies both.

**Background for the worker.**
- `require(module, feature) -> ModuleType` (`src/nnx/_optional.py`): imports `module` with `importlib.import_module`. If the top-level package of `module` is registered in `DOMAIN_EXTRAS`, the `ModuleNotFoundError` names that package, and the package is not installed (`importlib.util.find_spec` finds nothing), it raises `ImportError` naming the extra. Any other failure propagates unchanged.
- How tests simulate a missing package: `monkeypatch.setitem(sys.modules, "pkg", None)`. Then `import pkg` raises `ModuleNotFoundError(name="pkg")` and `find_spec("pkg")` returns `None`. Setting only a submodule (`"pkg.sub"`) to `None` while `pkg` is installed now means "broken install", so `require` re-raises it. A `builtins.__import__` patch does not affect `importlib.import_module`, so it cannot simulate a missing package any more.
- `ModuleNotFoundError` raised by hand without `name=` has `name=None`; `require` treats it as a broken install. A real missing module always carries `name`.

   ```python

       Int8WeightOnlyConfig, quantize_ = quantization.Int8WeightOnlyConfig, quantization.quantize_
   ```

   In the docstring, replace L87–L88 (`        ImportError: if ``torchao`` is not installed. Install with` / `            ``pip install thekaveh-nnx[quantize]``.`) with:

   ```
           ImportError: if ``torchao`` is not installed; the message names
               ``thekaveh-nnx[quantize]``. An installed torchao that fails
               to import raises its own error.
   ```


   and replace L76–L84 with:

   ```python

   ```
4. `src/nnx/interop/gguf/writer.py`: add `from ..._optional import require` as a first-party import after `from typing import TYPE_CHECKING, Any, Optional` (L30), separated by one blank line. Replace `_require_gguf` (L76–L91) with:

   ```python

       """The ``gguf`` package, imported on use (:func:`nnx._optional.require`):
       a missing one raises an ``ImportError`` naming the ``gguf-write`` extra,

       Returns the imported module so the caller can grab
       ``gguf.GGUFWriter`` and ``gguf.GGMLQuantizationType`` from it.
   ```
