## Summary

DEC-027: `nnx.embeddings.train_contrastive` is a second hand-written training loop (its own optimizer, gradient clipping, non-finite check and `print` output) beside `NNModel.train` driven by `text_contrastive_train_step_factory`, which the same module already ships. The owner must decide whether it stays a standalone loop (A) or is rewritten as a thin wrapper over `NNModel.train` with the same public signature (B), which writes a run directory and may change the loss trajectory.

## Context

**What happens today.** After its argument checks (which FIX-124 completes), `train_contrastive` runs its own loop (`src/nnx/embeddings/contrastive_trainer.py` L464–L484):

```python
    optimizer = optimizer_cls(trainable, lr=lr, weight_decay=weight_decay)

    backbone.train()
    for epoch in range(n_epochs):
        epoch_losses: list[float] = []
        for anchors, positives in loader:
            optimizer.zero_grad()
            z1 = _encode(backbone, anchors, device)
            z2 = _encode(backbone, positives, device)
            loss = nt_xent_loss(z1, z2, temperature=temperature)
            loss_val = float(loss.detach())
            if not torch.isfinite(loss).item():
                raise FloatingPointError(
                    f"non-finite contrastive loss ({loss_val!r}) at epoch "
                    f"{epoch}. Check lr / temperature / input normalization."
                )
            loss.backward()
            if grad_clip_norm is not None:
                torch.nn.utils.clip_grad_norm_(trainable, grad_clip_norm)
            optimizer.step()
            epoch_losses.append(loss_val)
```

The step factory in the same file does the same per batch through NNx's shared tail (L310–L314):

```python
        z1 = _encode(m.net, anchors, m.device)
        z2 = _encode(m.net, positives, m.device)

        loss = nt_xent_loss(z1, z2, temperature=temperature)
        loss_val = finalize_step(loss, ctx, paradigm="embeddings.contrastive")
```

The docstring already points elaborate setups there: "For more elaborate setups — callbacks, custom schedulers, multi-optimizer training, run.id persistence under ``runs/<id>/`` — use :func:`text_contrastive_train_step_factory` with the standard :meth:`NNModel.train` driver instead." (L352–L355).

**Why it matters.** Two loops drift: fixes to clipping, non-finite handling, precision or seeding in `NNModel.train` do not reach this one.

**History.**
- #542 (FIX-074) refused bool hyperparameters in paradigm steps and #544 (FIX-076) moved hand-written validators onto shared helpers; FIX-124 finishes that for `n_epochs` and `batch_size` here. No board issue decided that `train_contrastive` must stay a separate loop, and none that it must not.

**Background for the worker.**
- `NNModel(module=backbone, params=NNModelParams(...))`: wraps an existing module without copying it (`model.net is backbone`).
- `NNModel.train(params, train_step_fn=...)`: the standard driver. It always reserves and writes a run under `./runs/<id>/` (run.yaml, history, checkpoints), shows a tqdm bar unless `NNX_TQDM_DISABLE=1`, and builds its optimizer and scheduler from `NNTrainParams`.
- `text_contrastive_train_step_factory(temperature=...)` (L257): the per-batch step for `(anchors, positives)` batches; `finalize_step` raises `FloatingPointError` on a non-finite loss and applies `grad_clip_norm`.
- Registered optimizer factory (`nnx.optimizers`): `register_optimizer_factory(id, version, factory, replace=...)` registers a callable `factory(param_groups, config) -> torch.optim.Optimizer`; `NNOptimFactoryParams(factory=OptimizerFactorySpec(id=..., version=..., config=...), max_lr=..., weight_decay=..., grad_clip_norm=...)` selects it. This is how B keeps `optimizer_cls` working for any class.
- `NNSchedulerParams(kind=Schedulers.STEP, step_size=1, factor=1.0, …)`: a step scheduler that multiplies the learning rate by 1.0, i.e. a constant learning rate (a plateau scheduler refuses `factor >= 1`).
- `Devices`: NNx's device enum, `CPU`, `MPS`, `CUDA` (the default CUDA device).
- `NNRun.idps`: one `NNIterationDataPoint` per batch, with `epoch_idx` and `train_edp.loss`.

## Options

| Option | What changes | Trade-off |
|---|---|---|
| A (recommended) | Keep the standalone loop (with FIX-124's validation). | No behaviour change: no run directory, the exact current loss trajectory, any `optimizer_cls`. Two loops to keep in step. |
| B | Rewrite the body after validation as `NNModel(module=backbone, ...).train(params, train_step_fn=text_contrastive_train_step_factory(...))`, keeping the signature: `optimizer_cls` through a registered optimizer factory, a constant learning rate, `verbose` printed from the run's history. | One loop. Every call now writes `./runs/<id>/` and shows a progress bar; a backbone on a non-default CUDA device is refused; the loss trajectory may differ from today's for the same seed, which the pinned test below detects. |

A is recommended because `train_contrastive` is the documented quick path ("High-level wrapper"), its side-effect-free behaviour is part of what users get, and the standard driver is already one call away through the step factory.

2. In `src/nnx/embeddings/contrastive_trainer.py`, `train_contrastive`, keep everything up to and including the `trainable` check (through L463, as FIX-124 left it), and replace L464–L489 with:

   ```python
       from ..nn.enum.devices import Devices
       from ..nn.enum.losses import Losses
       from ..nn.enum.schedulers import Schedulers
       from ..nn.nn_model import NNModel
       from ..nn.params.nn_model_params import NNModelParams
       from ..nn.params.nn_scheduler_params import NNSchedulerParams
       from ..nn.params.nn_train_params import NNTrainParams
       from ..optimizers import (
           NNOptimFactoryParams,
           OptimizerFactorySpec,
           register_optimizer_factory,
           unregister_optimizer_factory,
       )

       if device.index not in (None, 0):  # NNx's Devices.CUDA is the default device
           raise ValueError(f"train_contrastive runs on NNModel.train, which uses the default device; got {device}")

       def build(param_groups: Any, config: Any) -> torch.optim.Optimizer:
           return optimizer_cls(param_groups[0]["params"], lr=lr, weight_decay=weight_decay)

       register_optimizer_factory(_OPTIMIZER_FACTORY, 1, build, replace=True)
       try:
           optimizer_name = f"{optimizer_cls.__module__}.{optimizer_cls.__qualname__}"
           params = NNTrainParams(
               n_epochs=n_epochs,
               data_id="nnx.embeddings.train_contrastive",
               train_loader=loader,
               optim=NNOptimFactoryParams(
                   factory=OptimizerFactorySpec(id=_OPTIMIZER_FACTORY, version=1, config={"optimizer": optimizer_name}),
                   max_lr=lr,
                   weight_decay=weight_decay,
                   grad_clip_norm=grad_clip_norm,
               ),
               # A constant learning rate, as the standalone loop had: STEP with factor 1.0 never changes it.
               scheduler=NNSchedulerParams(
                   min_lr=0.0, factor=1.0, patience=0, cooldown=0, threshold=0.0, kind=Schedulers.STEP, step_size=1
               ),
           )
           model = NNModel(module=backbone, params=NNModelParams(loss=Losses.CROSS_ENTROPY, device=Devices(device.type)))
           run = model.train(params=params, train_step_fn=text_contrastive_train_step_factory(temperature=temperature))
       finally:
           unregister_optimizer_factory(_OPTIMIZER_FACTORY, 1)
       if verbose:
           for epoch in range(n_epochs):
               losses = [idp.train_edp.loss for idp in run.idps or [] if idp.epoch_idx == epoch]
               mean = sum(losses) / max(1, len(losses))
               print(f"[epoch {epoch + 1}/{n_epochs}] mean NT-Xent loss = {mean:.4f}")
       return backbone
   ```

   and add at module level, after the imports: `_OPTIMIZER_FACTORY = "nnx.embeddings.train_contrastive"  # registered for the duration of one call`. The loss argument is required by `NNModelParams` and unused by the contrastive step.
