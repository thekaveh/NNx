## Summary

FIX-140: Five comments and doc lines about tooling are wrong: `.gitignore` says `mkdocs.yml` excludes two folders (it is generated and excludes nothing); the external-contracts ledger names ipython `9.18.1` (the lock has `9.19.1`); CONTRIBUTING says CairoSVG is pinned only in the `docs-publish` group; `.pre-commit-config.yaml` says the ruff rev tracks a pyproject pin (it must match `uv.lock`); and `pyproject.toml` calls pyright's floor a pin. This ticket corrects each with exact text.

## Context

**What happens today.**
- `.gitignore` L62–L63: ``# accidental `git add -A`. Belt-and-braces; mkdocs.yml already excludes`` / `# both from the published site.` But `mkdocs.yml` is generated by `scripts/docs/build_docs.py` (`render_mkdocs`), git-ignored (`.gitignore` L56) and has no `exclude_docs`; `docs/specs/` and `docs/superpowers/` stay unpublished because `docs_dir: generated/site` holds only the pages `docs/manifest.yaml` lists.
- `docs/external-contracts.md` L23 (Explainability row): `` `ipython>=8.0` / `9.18.1` (extra `notebook`) ``; `uv.lock` L1486–L1487 locks `version = "9.19.1"` (a Dependabot bump). `tests/test_docs_projection.py::test_external_contract_tool_versions_match_automation_sources` checks only the tool rows, so nothing caught it.
- `CONTRIBUTING.md` L17: ``Debian/Ubuntu. CairoSVG itself is pinned in the `docs-publish` dependency group.`` CairoSVG is also pinned in the `docs` extra (`pyproject.toml` `docs = ["cairosvg==2.9.1", …]`), which is what `uv sync --all-extras` installs; `docs-publish` (L12–L16) pins it too.
- `.pre-commit-config.yaml` L6–L8: `# ruff rev should track the pin in pyproject.toml's [dev] extras —` … But `[dev]` has a range (`"ruff>=0.6,<0.18"`); the enforced rule is `tests/test_pypi_publication.py::test_pre_commit_ruff_version_matches_frozen_ci_version` (L136), which compares the rev with the ruff version in `uv.lock`.
- `pyproject.toml` L129: ``"pyright>=1.1.380",    # CI runs `pyright --warnings`; pin here so locals match`` — a floor, not a pin.

**Why it matters.** Each one sends a contributor to the wrong file when a version or the published site changes.

**History.** #567 (FIX-099) grouped pinned-tool bumps and pins the ledger's tool rows against `requirements-tools.txt` and `uv.lock`; #757 (DEC-003) landed the Dependabot backlog that moved ipython. The maintenance ledger's copy of the `mkdocs.yml` claim (`.maintenance/overnight-2026-07-01.md` L36) belongs to DEC-022.

**Background for the worker.**
- `uv.lock`: the lock file; the source of truth for versions CI runs.
- External-contracts ledger: `docs/external-contracts.md` §2, one row per external dependency with "`range` / `frozen version`" pairs.

**Proposal.**
1. `.gitignore`, replace L62–L63:

   Old:
   ```
   # accidental `git add -A`. Belt-and-braces; mkdocs.yml already excludes
   # both from the published site.
   ```
   New:
   ```
   # accidental `git add -A`. Belt-and-braces: the generated site holds only
   # the pages docs/manifest.yaml lists, so neither is published.
   ```
2. `docs/external-contracts.md` L23: replace `` `ipython>=8.0` / `9.18.1` `` with `` `ipython>=8.0` / `9.19.1` `` (the rest of the row stays).
3. `CONTRIBUTING.md` L17:

   Old: ``Debian/Ubuntu. CairoSVG itself is pinned in the `docs-publish` dependency group.``

   New: ``Debian/Ubuntu. CairoSVG itself is pinned (`cairosvg==2.9.1`) in the `docs` extra and the `docs-publish` dependency group.``
4. `.pre-commit-config.yaml`, replace L6–L8:

   Old:
   ```
     # ruff rev should track the pin in pyproject.toml's [dev] extras —
     # otherwise pre-commit lints under a different rule set than CI / local
     # `ruff` and 96-file format drift accumulates silently.
   ```
   New:
   ```
     # ruff rev must equal the ruff version locked in uv.lock (enforced by
     # tests/test_pypi_publication.py::test_pre_commit_ruff_version_matches_frozen_ci_version);
     # otherwise pre-commit lints under a different rule set than CI.
   ```
5. `pyproject.toml` L129:

   Old: ``    "pyright>=1.1.380",    # CI runs `pyright --warnings`; pin here so locals match``

   New: ``    "pyright>=1.1.380",    # CI runs `pyright --warnings`; floor only; uv.lock pins the version CI runs``

**Worker setup.** No torch needed (docs/config only).
