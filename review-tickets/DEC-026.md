## Summary

DEC-026: NNx floors probabilities at three different values before taking a logarithm: `1e-300` in `link_metrics`, `1e-12` (`NLL_EPSILON`) in the named `nll` metric, and none in the decision benchmark, whose NLL is exact by design (#243). The `link_metrics` floor is undocumented. The owner must decide whether `link_metrics` keeps `1e-300` and documents it (A) or switches to `NLL_EPSILON` (B), which changes reported values.

## Context

**What happens today.** `link_metrics` (`src/nnx/link_tasks.py`) clips bare probabilities at `1e-300` for the categorical NLL (L662–L663):

```python
        else:
            nll = -np.log(np.clip(p[rows], 1e-300, 1.0))
```

and at `[1e-300, 1 - 1e-16]` for the binary cross-entropy (L678–L680):

```python
    else:
        clipped = np.clip(p, 1e-300, 1.0 - 1e-16)
        bce = float(-(y * np.log(clipped) + (1 - y) * np.log1p(-clipped)).mean())
```

The shared NLL floors at `NLL_EPSILON = 1e-12` (`src/nnx/_probability.py` L43, used by `nll_terms`, L127–L146). The floor applies only when `link_metrics` gets probabilities (`from_logits=False`); `LinkTask`'s own evaluation scores logits, exactly, with no floor (docstring, L609–L616).

So a true class given probability 0 costs `-log(1e-300)` ≈ 690.8 in `link_metrics`, but `-log(1e-12)` ≈ 27.6 in the named `nll` metric.

**Why it matters.** Two NNx metrics named NLL give different numbers for the same saturated probabilities, and neither the docstring nor the guide says so.

**History.**
- #243 (FEAT-021) made the decision benchmark's NLL exact on purpose: "Exact NLL is `+inf` when the true class has zero probability and `epsilon=None`." That floor is not in question here.
- #518 (FIX-051) computed the Bernoulli `nll` metric without float32 sigmoid saturation; the named metric's `1e-12` floor is its contract.
- FEAT-113 (SMELL-37 steps 1–2) moves the benchmark onto the shared `nll_terms` with the benchmark's own `epsilon` (exact by default). This ticket is step 3, the link-task floor, which the cross-check kept as a decision.

**Background for the worker.**
- `link_metrics(probabilities, targets, *, from_logits=False)` (`link_tasks.py` L603): binary `(K,)` scores give `bce`, `auroc`, `ap`, `accuracy`; categorical `(K, C)` give `nll`, `accuracy`.
- Floor: the smallest probability the logarithm sees; it caps one row's loss at `-log(floor)` instead of `inf`.
- `NLL_EPSILON` (`_probability.py` L43): the floor of the named `nll` metric (`nnx.monitors`).
- Values: `-log(1e-300)` = 690.7755278982137; `-log1p(-(1 - 1e-16))` = 36.7368005696771; `-log(1e-12)` = 27.631021115928547.

## Options

| Option | What changes | Trade-off |
|---|---|---|
| A (recommended) | Keep `1e-300` (and the BCE's `1 - 1e-16` ceiling) as named constants, and document them in the `link_metrics` docstring and the guide. | No reported value changes. Two floors remain, now stated. |
| B | Floor at `NLL_EPSILON` (`1e-12`), as the named `nll` metric does; the BCE ceiling becomes `1 - NLL_EPSILON`. | One floor for both named NLLs. Saturated probabilities score far lower (a zero true-class probability: 27.6 instead of 690.8), so saved and published `link_metrics` numbers change; one existing test is rewritten. |

A is recommended because `link_metrics` on probabilities is the secondary path (the task scores logits, exactly), a floor of `1e-300` stays closest to the exact value, and changing it would silently move numbers users have recorded.

**If option A, the worker does:**

1. In `src/nnx/link_tasks.py`, add after `__all__`:

   ```python
   # link_metrics' floor and BCE ceiling for bare probabilities (from_logits=False): as close to the exact value
   # as float64 allows. Not the named nll metric's NLL_EPSILON (1e-12); logits need no floor.
   _PROBABILITY_FLOOR = 1e-300
   _PROBABILITY_CEILING = 1.0 - 1e-16
   ```

   and use them at L663 (`np.clip(p[rows], _PROBABILITY_FLOOR, 1.0)`) and L679 (`np.clip(p, _PROBABILITY_FLOOR, _PROBABILITY_CEILING)`). Values are unchanged.
2. In the `link_metrics` docstring, add after `The task's evaluation scores the logits.` (L616):

   ```
   Bare probabilities are clipped before the logarithm: to ``[1e-300, 1]``
   for the NLL and to ``[1e-300, 1 - 1e-16]`` for the BCE. A true class or
   positive given probability 0 costs ``-log(1e-300)`` ≈ 690.8, and a
   negative given probability 1 about 36.7. This is not the named ``nll``
   metric's floor of ``1e-12``; logits need none.
   ```

3. In `docs/concepts.md` L3581–L3582, append to the bullet `**Scoring outside the evaluator.**` the sentence: `` Bare probabilities are floored at `1e-300` before the logarithm (a zero true-class probability costs about 690.8), not at the named `nll` metric's `1e-12`; logits need no floor. ``
4. Add to `tests/test_link_tasks.py`:

   ```python
   def test_bare_probabilities_are_floored_at_1e_300():
       categorical = link_metrics([[0.0, 1.0], [1.0, 0.0]], [0, 0])
       assert categorical["nll"].value == pytest.approx(-math.log(1e-300) / 2, rel=1e-12)
       binary = link_metrics([0.0, 1.0], [1, 0])
       assert binary["bce"].value == pytest.approx((-math.log(1e-300) - math.log1p(-(1.0 - 1e-16))) / 2, rel=1e-12)
   ```

5. `uv run python -m scripts.docs.build_api_reference`. No CHANGELOG entry (no value changes).

**If option B, the worker does:**

1. In `src/nnx/link_tasks.py`, add `from ._probability import NLL_EPSILON` to the first-party imports (after `from ._optional import require`). Change L663 to `nll = -np.log(np.clip(p[rows], NLL_EPSILON, 1.0))` and L679 to `clipped = np.clip(p, NLL_EPSILON, 1.0 - NLL_EPSILON)`.
2. In the `link_metrics` docstring, add after `The task's evaluation scores the logits.` (L616):

   ```
   Bare probabilities are clipped to ``[NLL_EPSILON, 1]`` for the NLL and
   to ``[NLL_EPSILON, 1 - NLL_EPSILON]`` for the BCE, with
   ``NLL_EPSILON = 1e-12`` as for the named ``nll`` metric: a true class
   given probability 0 costs ``-log(1e-12)`` ≈ 27.6. Logits need no floor.
   ```

3. In `docs/concepts.md`, append to the `**Scoring outside the evaluator.**` bullet (L3581–L3582): `` Bare probabilities are floored at `1e-12`, as for the named `nll` metric; logits need no floor. ``
4. Tests in `tests/test_link_tasks.py`:
   - Rewrite the assertion `assert saturated is not None and saturated > 2 * exact` in `test_saturated_logits_keep_an_exact_categorical_nll` (L799). Two of its three float32 softmax rows give the true class a probability below `1e-12` (one exactly 0, one about `3.8e-44`) and the third gives 1, so the new assertion is `assert saturated == pytest.approx(-2 * math.log(1e-12) / 3, rel=1e-12) and saturated < exact / 2`. Keep the comment `# exp(-120) underflows`.
   - Add:

     ```python
     def test_bare_probabilities_are_floored_at_the_nll_epsilon():
         categorical = link_metrics([[0.0, 1.0], [1.0, 0.0]], [0, 0])
         assert categorical["nll"].value == pytest.approx(-math.log(1e-12) / 2, rel=1e-12)
         binary = link_metrics([0.0, 1.0], [1, 0])
         assert binary["bce"].value == pytest.approx((-math.log(1e-12) - math.log1p(-(1.0 - 1e-12))) / 2, rel=1e-12)
     ```

   - `test_saturated_logits_keep_exact_binary_metrics` (L729) and `test_moderate_logits_score_as_their_probabilities` (L768) pass unedited: the first only asserts that saturated values differ from the exact ones, and the second never reaches either floor.
5. `uv run python -m scripts.docs.build_api_reference`.
6. `CHANGELOG.md`, `[Unreleased]` → `### Changed`:

   ```
   - **`link_metrics` floors bare probabilities at `1e-12`, as the named `nll` metric does.** A true class or label given probability 0 now costs `-log 1e-12` ≈ 27.6 in the NLL and BCE, instead of `-log 1e-300` ≈ 690.8, so saturated probabilities score lower than before. Scores from logits (`from_logits=True`, what the task's own evaluation uses) are unchanged.
   ```
