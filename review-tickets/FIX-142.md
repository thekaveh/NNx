## Summary

FIX-142: The `embeddings` extra installs `faiss-cpu` and `sentence-transformers`, and the docs say each `ImportError` "is deferred to the call site that actually needs each one". No NNx code imports `sentence-transformers`; only `export_to_faiss` needs an optional package. This ticket rewrites the two passages to say what each package is for. Dropping the dependency is out of scope.

## Context

**What happens today.**
- `docs/embeddings.md` L23 (§2): ``Pulls in `faiss-cpu` and `sentence-transformers`. Both are optional at import time: `import nnx.embeddings` works even without them — the `ImportError` is deferred to the call site that actually needs each one.``
- `src/nnx/embeddings/__init__.py` L42–L46: ``The extra pulls ``faiss-cpu`` (for the FAISS index export) and ``sentence-transformers`` (the canonical backbone source). Both are optional at import time; this module imports cleanly without them and raises a clear :class:`ImportError` only at the call site that actually needs them.``
- No file in `src/`, `examples/` or `scripts/` imports `sentence_transformers` at module level; it appears only in docstrings (e.g. `examples/13_train_domain_embedder.py` L12, inside the module docstring). `train_contrastive` accepts any `nn.Module` whose `forward(list[str])` returns a tensor, and duck-types a SentenceTransformer. Only `export_to_faiss` raises an `ImportError` (`faiss_export._import_faiss`, L32–L50).

**Why it matters.** "Each one" implies a call that needs sentence-transformers; there is none, and the package pulls in `transformers`, so users should know it is a convenience, not a requirement.

**History.** No board issue covers it.

**Background for the worker.**
- Extra: `pip install "thekaveh-nnx[embeddings]"` installs the packages listed under `embeddings` in `pyproject.toml` `[project.optional-dependencies]`.
- Backbone: the text encoder `train_contrastive` and `export_to_faiss` take; a `SentenceTransformer` is one option.

**Proposal.**
1. `docs/embeddings.md` L23:

   Old: ``Pulls in `faiss-cpu` and `sentence-transformers`. Both are optional at import time: `import nnx.embeddings` works even without them — the `ImportError` is deferred to the call site that actually needs each one.``

   New: ``Pulls in `faiss-cpu` (used by `export_to_faiss`) and `sentence-transformers` (a convenience backbone source: NNx never imports it, and any `nn.Module` that maps `list[str]` to a tensor works). `import nnx.embeddings` works without either; `export_to_faiss` raises an `ImportError` naming the extra when `faiss` is missing.``
2. `src/nnx/embeddings/__init__.py`, replace L42–L46:

   Old:
   ```
   The extra pulls ``faiss-cpu`` (for the FAISS index export) and
   ``sentence-transformers`` (the canonical backbone source). Both are
   optional at import time; this module imports cleanly without them and
   raises a clear :class:`ImportError` only at the call site that actually
   needs them.
   ```
   New:
   ```
   The extra pulls ``faiss-cpu`` (used by :func:`export_to_faiss`) and
   ``sentence-transformers`` (a convenience backbone source: NNx never
   imports it, and any ``nn.Module`` that maps ``list[str]`` to a tensor
   works). This module imports cleanly without either; only
   :func:`export_to_faiss` raises an :class:`ImportError` naming the extra,
   when ``faiss`` is missing.
   ```

**Worker setup.** No torch needed (docs/config only).
