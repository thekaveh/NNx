## Summary

DEC-018: `nnx.export_conformance` is a 1,362-line CI harness (ONNX export parity profiles for one 4-8-2 feed-forward model) shipped in the runtime package. FEAT-059 stops `import nnx` from loading it. The owner must decide whether it then stays a public, lazily loaded module (A) or leaves the wheel for the repository's `scripts/` directory in a breaking release (B).

## Context

**What happens today.** `src/nnx/__init__.py` imports it eagerly (L34–L46):

```python
from . import (
    abstention,
    benchmarking,
    bundles,
    calibration,
    comparison,
    compilation,
    components,
    data_splits,
    decisions,
    distributed,
    embeddings,
    export_conformance,
```

and lists it in `__all__` (L354). Its docstring scopes it to one model ("the only targets NNx claims executed parity for: FeedFwdNN 4-8-2"). Its consumers are `scripts/check_export_conformance.py` (L48), the `export-conformance` CI job (`.github/workflows/ci.yml` L186–L225), `tests/test_export_conformance.py`, `tests/test_examples_smoke.py` L647, `docs/export-conformance.md` and two example comments.

**Why it matters.** A CI harness in the runtime wheel is public API NNx must keep stable, for a profile set that covers one model. FEAT-059 removes the import cost; the placement remains.

**History.**
- #255 (FEAT-038) created it as a module of the package and required "`python -c "import nnx"` succeeds in an environment without the new extra" (the `onnx-runtime` extra). Its Scope In: "Executable CPU conformance profiles for the FP32 feed-forward model under both exporters". The placement is deliberate, so moving it is this decision.
- #566 (FIX-098) and #573 (FEAT-051, the `nnx.export_conformance` keyword comment in `pyproject.toml` L63) treated it as a public subsystem.
- #756 (DEC-002) records how a non-default version is released: "`feat` commits a patch bump before 1.0. Another version needs a `Release-As:` footer." Option B is a breaking change and needs that.

**Background for the worker.**
- Lazy load (FEAT-059): `nnx.export_conformance` imports on first attribute access through `nnx.__getattr__`, not on `import nnx`.
- `scripts/`: the repository's tool directory. It is a package (`scripts/__init__.py`), is linted (`ruff check … scripts/`), and its modules are listed in `pyrightconfig.json`. It is not in the wheel or the sdist; a test that imports from it first calls `repo_file("scripts", …)` (`tests/_repo_files.py`), which skips in an extracted sdist.
- Running `python scripts/check_export_conformance.py` puts `scripts/`, not the repository root, on `sys.path`, so the script must add the root itself before `from scripts.export_conformance import …`.
- Shim: a module left at the old import path that raises `ImportError` naming the new place.

## Options

| Option | What changes | Trade-off |
|---|---|---|
| A (recommended) | Nothing beyond FEAT-059: `nnx.export_conformance` stays public and lazily loaded. | No break; the documented `from nnx.export_conformance import run_profile` keeps working. The runtime package keeps a CI harness for one model. |
| B | In a release the owner marks breaking, move the module to `scripts/export_conformance.py`, leave a shim at `nnx.export_conformance` that raises `ImportError`, and point every consumer at the new place. | The wheel loses a test harness and its public surface shrinks. Anyone importing `nnx.export_conformance` breaks; profiles run only from a source checkout. |

A is recommended because #255 made the module public on purpose, FEAT-059 already removes its only runtime cost, and B breaks a documented import for no user-visible gain.

The review proposed `tools/`. Option B uses `scripts/` instead: `tools/` does not exist, and `scripts/` is already linted, type-checked and importable by the tests.
