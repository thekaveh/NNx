## Summary

DEC-025: `DecisionJob` (`jobs._modality`) and the benchmark collector (`benchmark._modality`) each decide whether an input is "text", "tensor" or unknown before checking a provider's declared capabilities, and after #557 they still disagree in three cases. The owner must decide which rule becomes the one shared helper: the jobs rule (A) or the benchmark rule, which #557 named as the reference (B). Both keep "unknown → the provider judges" and DEC-009's empty-batch outcome.

## Context

**What happens today.** The jobs rule (`src/nnx/decisions/jobs.py` L575–L599):

```python
def _first(state: Any) -> Any:
    """The part of ``state`` holding its rows: the first part of a tuple of
    several inputs (a tuple of texts is one batch of texts), else the state."""
    return state[0] if isinstance(state, tuple) and state and not isinstance(state[0], str) else state
```

```python
    first = _first(state)
    if isinstance(first, (torch.Tensor, np.ndarray)) and getattr(first, "ndim", 0) >= 1:
        return "tensor", len(first)
    if (
        isinstance(first, Sequence)
        and not isinstance(first, str)
        and len(first) > 0
        and all(isinstance(x, str) for x in first)
    ):
        return "text", len(first)
    return None
```

The benchmark rule (`src/nnx/decisions/benchmark.py` L781–L791):

```python
def _modality(inputs: Any) -> Optional[str]:
    """``"text"`` for a list of strings, ``"tensor"`` for a tensor or an
    array (the first part of several inputs), else ``None``: unknown."""
    import numpy as np

    first = inputs[0] if isinstance(inputs, tuple) and inputs else inputs
    if isinstance(first, list) and first and all(isinstance(item, str) for item in first):
        return "text"
    if isinstance(first, np.ndarray) or (hasattr(first, "detach") and hasattr(first, "dtype")):
        return "tensor"
    return None
```

The three differences:

| Input | jobs today | benchmark today |
|---|---|---|
| a tuple of texts, `("a", "b")` | text, 2 rows | unknown (its first part is a `str`) |
| a non-list sequence of texts (a `collections.UserList`, a tuple subclass) | text | unknown (only `list`) |
| a tensor-like object with `detach` and `dtype` that is not a `torch.Tensor` / `np.ndarray` | unknown | tensor |
| a 0-d tensor or array | unknown (and `_one_value` refuses it first) | tensor |

The jobs rule also feeds `_rows` (L602–L611), the row count NNx checks a provider's answers against in `DecisionJob` (L931) and `nnx.result.decide_result` (`result.py` L298).

**Why it matters.** Two rules for one question drift; the same state can be refused by a job and served by the benchmark. In practice `collect` never sees the differing shapes: `_batch_input` (`benchmark.py` L606–L625) turns sample inputs into a `list` of texts, a stacked tensor or array (never 0-d), a `list` of other values, or a tuple of such parts. So option A changes no observable `collect` behaviour, and option B changes only `DecisionJob` and `decide_result`.

**History.**
- #557 (FIX-089) aligned the two and named the benchmark the reference: "Proposal: make `jobs._modality` match `benchmark._modality` and skip `capabilities().check(...)` when the modality is unknown." Its evidence row for jobs: "tests a tuple itself for text"; that rule and the tensor check were not aligned.
- #763 (DEC-009) kept an empty batch as the provider's to judge: "Option A is current: it extends the #557 rule that a modality NNx cannot tell is the provider's to judge." `tests/test_decision_jobs.py::test_an_empty_batch_is_the_providers_to_judge_and_answered_with_no_results` (L1160) pins it; both options keep it unedited.
- `docs/decisions.md` L414–L427 documents the benchmark rule for jobs: "A list of texts is text, and so is a tuple of several inputs whose first part is one; a tensor or array is a tensor."

**Background for the worker.**
- Modality: the kind of input a provider declares it reads (`Capabilities.modalities`, e.g. `{"text"}`, `{"tensor"}`, `{"image"}`).
- Without a provider `check()`, `DecisionJob._Runner._check` (L745–L761) refuses a state whose modality NNx can tell and the provider does not declare (`InvalidJob`), and leaves an unknown one to the provider. `benchmark._refusal` (L807–L826) does the same for `collect`, recording `"unsupported"`.
- `_one_value` (L614–L630): refuses one `str` or a 0-d tensor / array as a state before any modality check; neither option changes it.
- `_rows`: the input row count an answer must match, or `None` when NNx cannot tell (then the count is unchecked).
- `decisions/providers.py` is imported by both `jobs.py` and `benchmark.py` (`from .providers import _synchronous`), so the shared helper lives there.

## Options

| Option | What changes | Trade-off |
|---|---|---|
| A | The jobs rule becomes `providers._input_modality(state) -> Optional[tuple[str, int]]`; `benchmark._refusal` calls it. | No observable change for `DecisionJob`, `decide_result` or `collect` (whose inputs never take the differing shapes). The docs gain the tuple-of-texts case. |
| B (recommended) | The benchmark rule becomes `providers._input_modality(inputs) -> Optional[str]`; `jobs._first` reads a tuple's first part always, and `jobs._modality` adds the row count. | Code matches #557's reference and the current docs. A job whose state is a tuple (or other non-list sequence) of texts becomes the provider's to judge, so its capabilities and result count are no longer checked by NNx; a duck-typed tensor is checked as a tensor. |

B is recommended because #557 named the benchmark rule as the reference and `docs/decisions.md` already documents it; B makes `DecisionJob` do what its guide says, and a tuple of texts is better written as a list.

**If option A, the worker does:**

1. In `src/nnx/decisions/providers.py`, add after `_batch` (L178–L187):

   ```python
   def _first_part(state: Any) -> Any:
       """The part of ``state`` holding its rows: the first part of a tuple of
       several inputs (a tuple of texts is one batch of texts), else the state."""
       return state[0] if isinstance(state, tuple) and state and not isinstance(state[0], str) else state


   def _input_modality(state: Any) -> Optional[tuple[str, int]]:
       """The modality and batch size a provider's capabilities are checked
       against, read from the state's :func:`_first_part`, or ``None`` when NNx
       cannot tell: a provider-specific input or an empty batch, the provider's
       to judge."""
       import torch

       first = _first_part(state)
       if isinstance(first, (torch.Tensor, np.ndarray)) and getattr(first, "ndim", 0) >= 1:
           return "tensor", len(first)
       if isinstance(first, Sequence) and not isinstance(first, str) and len(first) > 0 and all(
           isinstance(x, str) for x in first
       ):
           return "text", len(first)
       return None
   ```

- Hoisting the function-local `numpy` / `torch` imports of these helpers (FEAT-136), and splitting `benchmark.py` (FEAT-121).
