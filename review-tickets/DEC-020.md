## Summary

DEC-020: NNx has adapter-only save/load helpers for LoRA, IA3, prefix and prompt tuning, but not for DoRA: a DoRA adapter's learned `magnitude` persists only through the full `state_dict()`. FIX-119 makes `save_lora_weights` warn when it skips a magnitude. The owner must decide whether that full-state round trip stays the DoRA path (A) or NNx adds `save_dora_weights` / `load_dora_weights` (B).

## Context

**What happens today.** The LoRA helpers own only the two LoRA matrices (`src/nnx/peft/lora.py` L264):

```python
_LORA_OWNED = ("lora_A", "lora_B")
```

and `dora.py`'s module docstring (L25–L31) sends DoRA users to the full state:

```python
Because ``DoRALinear`` is a subclass of ``LoRALinear``, the existing
:func:`nnx.peft.save_lora_weights` and :func:`nnx.peft.load_lora_weights`
helpers still pick up the ``lora_A`` / ``lora_B`` matrices unchanged.
The ``magnitude`` parameter is not LoRA-shaped; callers wanting to
persist a full DoRA adapter should use the standard
``module.state_dict()`` round-trip (the magnitude key is small —
single vector of length ``out_features`` per wrapped layer).
```

So does `docs/concepts.md` L1677 ("Persist a DoRA adapter with the complete `state_dict()`, since the LoRA-only helpers omit `magnitude`") and the API catalog's §9 intro.

**Why it matters.** A full `state_dict()` also carries every frozen base weight, so a DoRA adapter file is as large as the model. An adapter-only file for DoRA is what users of the other families get.

**History.**
- #201 (FIX-002) scoped this out on purpose: "**Out:** A separate DoRA-magnitude artifact API; the learned DoRA magnitude still needs a full-state round trip." It also required that "the existing DoRA LoRA-only round-trip test passes unchanged" (`tests/test_peft_dora.py` L194). Option B reverses the first; both options keep the second.
- #225 (FIX-015) recorded that `docs/concepts.md` "states that `magnitude` needs full module state persistence".
- FIX-119 (BUG-19 step 2) adds a `UserWarning` to `save_lora_weights` for DoRA layers, ending "Persist a DoRA adapter with the full module state_dict().", a docstring paragraph ending "Persist a DoRA adapter with the full ``state_dict()``." and a CHANGELOG `### Changed` bullet ending "Persist a DoRA adapter with the full `state_dict()`." Option B points those three at the new helper.

**Background for the worker.**
- `LoRALinear` wraps an `nn.Linear` with a frozen `base` and trainable `lora_A` / `lora_B`; `DoRALinear` (`dora.py` L156) subclasses it and adds a trainable per-output-row `magnitude`.
- `owned_adapter_keys(module, wrapper_types, owned)` (`peft/_ownership.py` L32): the `state_dict` keys that the given wrapper types register under the given attribute names, from the module tree, never from key substrings (#201). `select_owned(state_dict, allowed)` (L45) keeps only those keys.
- `_resolve_source_to_state_dict(source, fn_name)` (`peft/_source.py` L29): a path or a dict to a state dict. `_refuse_shape_mismatch(module, sd, fn_name)` (L64): raises a size-mismatch `RuntimeError` before anything is copied.
- `docs/api.md` is generated: `uv run python -m scripts.docs.build_api_reference` after a docstring or catalog change.

## Options

| Option | What changes | Trade-off |
|---|---|---|
| A (recommended) | Nothing beyond FIX-119's warning: a DoRA adapter persists with the full `state_dict()`, as #201 decided. | No new API. A DoRA adapter file carries the frozen base weights too. |
| B | Add `save_dora_weights` / `load_dora_weights` in `nnx.peft.dora`, owning `lora_A`, `lora_B` and `magnitude`, exported from `nnx.peft` and `nnx`; point the docs and FIX-119's warning at them. | DoRA gets an adapter-only file like the other families. Reverses #201's Scope Out and adds two public functions to keep in step with FEAT-125's shared save/load bodies. |

A is recommended because #201 excluded a DoRA artifact API deliberately, the magnitude is one small vector per layer, and FIX-119 now tells users at the call which path to take.

   - Append at the end of the file:

     ```python
     _DORA_OWNED = ("magnitude",)


     def _dora_keys_only(module: nn.Module, state_dict: Mapping[str, Any]) -> dict:
         """``state_dict`` restricted to the adapter state DoRA wrappers own: ``lora_A`` / ``lora_B`` (as
         for LoRA) and ``magnitude``. Ownership comes from the module tree, never from a key substring (#201)."""
         allowed = owned_adapter_keys(module, LoRALinear, _LORA_OWNED) | owned_adapter_keys(
             module, DoRALinear, _DORA_OWNED
         )
         return select_owned(state_dict, allowed)


     def save_dora_weights(module: nn.Module, path: Union[str, Path]) -> str:
         """Save ONLY the DoRA adapter state of ``module`` to ``path``.

         An atomic ``torch.save`` (written beside ``path``, then renamed onto
         it, as the other adapter savers write) of the ``lora_A`` / ``lora_B``
         tensors owned by the :class:`LoRALinear` wrappers in ``module`` (DoRA wrappers
         included) plus the ``magnitude`` of each :class:`DoRALinear` —
         selected by registered ownership, so no frozen base tensor is written.
         Loadable via :func:`load_dora_weights`. Like the other adapter files,
         it records no transformation recipe: apply the same adapters first.

         Returns:
             The path written (so calls can be chained).
         """
         atomic_torch_save(_dora_keys_only(module, module.state_dict()), str(path))
         return str(path)


     def load_dora_weights(module: nn.Module, source: Union[str, Path, dict]) -> int:
         """Load DoRA adapter state into ``module`` from ``source`` (a file from
         :func:`save_dora_weights`, or a state dict).

         ``module`` must already carry the same DoRA wrappers (``apply_dora_to``
         first). The source is restricted to the keys ``module``'s own wrappers
         own, so a full checkpoint can never overwrite a frozen base tensor; a
         wrong-shaped owned key raises a size-mismatch ``RuntimeError`` before
         anything is copied.

         Returns:
             The number of tensors loaded.
         """
         sd = _dora_keys_only(module, _resolve_source_to_state_dict(source, "load_dora_weights"))
         _refuse_shape_mismatch(module, sd, "load_dora_weights")
         result = module.load_state_dict(sd, strict=False)
         return len(sd) - len(result.unexpected_keys)
     ```

   ```python
   def test_dora_weights_round_trip(tmp_path):
       torch.manual_seed(0)
       net = _TinyNet()
       apply_dora_to(net, "layers.*", r=2, alpha=4.0)
       with torch.no_grad():  # a trained adapter: non-default LoRA matrices and magnitudes
           for name, p in net.named_parameters():
               if p.requires_grad:
                   p.add_(0.1 * torch.randn_like(p))
       x = torch.randn(5, 8)
       net.eval()
       expected = net(x)
       path = save_dora_weights(net, tmp_path / "dora.pt")
       saved = torch.load(path, weights_only=True)
       assert sorted({key.rsplit(".", 1)[1] for key in saved}) == ["lora_A", "lora_B", "magnitude"]
       torch.manual_seed(0)
       fresh = _TinyNet()
       apply_dora_to(fresh, "layers.*", r=2, alpha=4.0)
       assert load_dora_weights(fresh, path) == len(saved)
       fresh.eval()
       torch.testing.assert_close(fresh(x), expected)


   def test_load_dora_weights_never_writes_a_base_tensor(tmp_path):
       torch.manual_seed(0)
       net = _TinyNet()
       apply_dora_to(net, "layers.*", r=2, alpha=4.0)
       base = {name: p.detach().clone() for name, p in net.named_parameters() if ".base." in name}
       full = {name: torch.full_like(t, 7.0) for name, t in net.state_dict().items()}
       load_dora_weights(net, full)
       for name, value in base.items():
           assert torch.equal(dict(net.named_parameters())[name], value), name
   ```
